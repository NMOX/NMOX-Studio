Ваші руки вже знають, де що лежить. Ця сторінка — мапа від цих звичок до NMOX Studio: спершу сполучення клавіш, потім де живе кожна ідея VS Code, а наостанок — що тут чесно інакше.

Перші чотири сполучення, які натискає користувач VS Code, роблять те, чого він чекає: **⇧⌘P** відкриває палітру команд, **⇧⌘E** — дерево файлів, **⇧⌘X** — плагіни, а **⌃\`** — термінал. Їх записано в усіх п’ятьох профілях розкладки, які постачає платформа, а затвор збирання перевіряє кожне з них у зібраній розкладці на macOS, Windows і Linux, щоб замість нього не спрацювало щось інше.

<a id="the-chords"></a>
## Сполучення клавіш

Стовпці macOS використовують значки з рядка меню (⌃ Control, ⌥ Option, ⇧ Shift, ⌘ Command); стовпці Windows і Linux — це те саме сполучення на клавіатурі ПК.

| Що потрібно | VS Code, macOS | NMOX, macOS | VS Code, Win/Linux | NMOX, Win/Linux |
|---|---|---|---|---|
| Палітра команд | ⇧⌘P | **⇧⌘P** (або ⌘I) — Швидкий пошук | Ctrl+Shift+P | **Ctrl+Shift+P** (або Ctrl+I) |
| Відкрити файл за назвою | ⌘P | **⌘P** — Перейти до файлу | Ctrl+P | **Ctrl+P** |
| Дерево файлів | ⇧⌘E | **⇧⌘E** — Студія проєкту | Ctrl+Shift+E | **Ctrl+Shift+E** |
| Розширення | ⇧⌘X | **⇧⌘X** — Інструменти ▸ Плагіни | Ctrl+Shift+X | **Ctrl+Shift+X** |
| Термінал у теці проєкту | ⌃\` | **⌃\`** | Ctrl+\` | **Ctrl+\`** |
| Відкрити недавній проєкт | ⌃R | **⌥⌘P** — Змінити проєкт… | Ctrl+R | **Ctrl+Alt+P** |
| Перейти до символу в проєкті | ⌘T | **⌥⇧⌘O** | Ctrl+T | **Ctrl+Alt+Shift+O** |
| Перейти до визначення | F12 | **⌘B** | F12 | **Ctrl+B** |
| Перейменувати символ | F2 | **⌃R** | F2 | **Ctrl+R** |
| Перейти до рядка | ⌃G | **⌃G** | Ctrl+G | **Ctrl+G** |
| Закоментувати рядок | ⌘/ | **⌘/** | Ctrl+/ | **Ctrl+/** |
| Показати підказки | ⌃Space | **⌃Space** | Ctrl+Space | **Ctrl+Space** |
| Додати до виділення наступне входження | ⌘D | **⌘D** або ⌘J | Ctrl+D | **Ctrl+D** або Ctrl+J |
| Виділити всі входження | ⇧⌘L | **⌃⇧⌘J** | Ctrl+Shift+L | **Ctrl+Alt+Shift+J** |
| Додати курсор вище / нижче | ⌥⌘↑ / ⌥⌘↓ | **⌥⌘↑ / ⌥⌘↓** | Ctrl+Alt+↑ / ↓ | **Alt+Shift+[ / ]** |
| Перемістити рядок угору / вниз | ⌥↑ / ⌥↓ | **⌃⇧↑ / ⌃⇧↓** | Alt+↑ / ↓ | **Alt+Shift+↑ / ↓** |
| Скопіювати рядок нижче | ⇧⌥↓ | **⌥⇧↓** | Shift+Alt+↓ | **Ctrl+Shift+↓** |
| Видалити рядок | ⇧⌘K | **⌘E** | Ctrl+Shift+K | **Ctrl+E** |
| Відформатувати документ | ⇧⌥F | **⌃⇧F** | Shift+Alt+F | **Alt+Shift+F** |
| Закрити вкладку редактора | ⌘W | **⌘W** | Ctrl+W | **Ctrl+W** |
| Панель проблем | ⇧⌘M | **⌘6** — Завдання (⇧⌘M тут ставить або знімає закладку) | Ctrl+Shift+M | **Ctrl+6** |
| Поставити чи зняти точку зупину | F9 | **⌘F8** | F9 | **Ctrl+F8** |

| Запустити без зневадження | ⌃F5 | **F6** — Запустити проєкт | Ctrl+F5 | **F6** |
| Налаштування | ⌘, | **⌘,** — NMOX Studio ▸ Settings… | Ctrl+, | Інструменти ▸ Налаштування (без сполучення) |

На macOS ⌘, належить самому меню застосунку; кожне інше сполучення NMOX у таблиці прочитано з поставленої розкладки, а не згадано з пам’яті. Кілька речей, які не вмістити в клітинку:

- **F5 зайнята під час зневадження.** Тут вона означає *Продовжити*, як у кожній IDE родини NetBeans, тож запуск зі зневадженням починається з **⇧⌘F5** (Ctrl+Shift+F5), а продовжується з F5.
- **⌃R тут — перейменування**, тому *Змінити проєкт* живе на ⌥⌘P, а не на сполученні Open Recent із VS Code. Перейменування працює там, де його підтримує мова, що стоїть за файлом.
- **Ctrl+, у Windows і Linux** веде назад історією ваших правок, як це завжди було в NetBeans; налаштування — у меню Інструменти ▸ Налаштування (на macOS — **Settings…** у меню застосунку, ⌘,).

**Довідка ▸ Клавіатурні скорочення…** перелічує кожне сполучення NMOX у вашій чинній розкладці, разом із чотирма сполученнями VS Code, прочитане з розкладки, що працює, тож воно не може розійтися з тим, що роблять клавіші.

<a id="from-the-terminal"></a>
## З термінала

`code .` — це `nmox .`:

```bash
cd ~/code/my-app
nmox .          # open this folder (manifest or not) and aim the IDE at it
nmox src/app.ts # open one file
nmox src/app.ts:42  # open it at line 42 (code -g's form; -g itself is accepted)
nmox            # just start the IDE
```

Команда повертається одразу, а другий `nmox` передає свою теку IDE, що вже працює. Стовпець (`src/app.ts:42:7`) теж приймається, і редактор відкривається на початку рядка; ім’я, якого немає, відхиляється просто в терміналі, і нічого не запускається. Homebrew, інсталятор Windows (*Add "nmox" to PATH*, «Додати nmox до PATH») і пакети Linux кладуть її у PATH; для встановлення з DMG [посібник користувача](user-guide.uk.md#2-first-launch) показує посилання в один рядок.

<a id="where-each-vs-code-idea-lives"></a>
## Де живе кожна ідея VS Code

| У VS Code | У NMOX Studio |
|---|---|
| **Explorer** | **Студія проєкту** (⇧⌘E) — дерево файлів, шаблони й редактор `package.json` проєкту. **Робоче місце** (⌥⌘0) — домашня база: відкриті файли, недавні файли, недавні проєкти й усе, що працює. |
| **Command Palette** | **Швидкий пошук** (⇧⌘P або ⌘I) — дії, файли, недавні проєкти, прилади стійки, працюючі сервери, запити Студії API, символи. Працюють і назви команд самого VS Code: *Format Document*, *Toggle Terminal*, *Git: Commit* чи *Open Settings* показує дію, яка робить тут те саме, у розділі **Команди VS Code** — з її тутешньою назвою та сполученням клавіш. |
| **Extensions** | **Інструменти ▸ Плагіни** встановлює й оновлює модулі, включно з власними оновленнями NMOX. Багато з того, що у VS Code додає розширення, тут — **прилад стійки**, і його можна написати як файл JSON у `~/.nmox/devices.d` ([файли приладів](device-files.md)). |
| **`tasks.json`** | `.vscode/tasks.json` вашого репозиторію читається: наберіть назву завдання у Швидкому пошуку (⇧⌘P або ⌘I), і Ввід на *Запустити завдання: build — make all* запускає його; на проєкті, якому ви ще не довіряєте, спершу спитає довіра до робочої області, вивід іде у вікно **Output**, а зупиняє його ■ на панелі інструментів. Поруч власні скрипти проєкту запускаються так, як їх написано: Запуск / Збирання / Тест на панелі інструментів (F6, F11, ⌃F6), **Запустити скрипт** на рядку scripts у `package.json`, **Оглядач NPM** і **Стійка задач** (⌘9), де задачі — прилади, які ви з’єднуєте між собою. |
| **`launch.json`** | `.vscode/launch.json` вашого репозиторію читається: наберіть назву конфігурації у Швидкому пошуку (⇧⌘P або ⌘I), і Ввід на *Налагодити: Launch Program — ${workspaceFolder}/server.js* запускає зневаджувач із точками зупину на цій програмі, а на недовіреному проєкті спершу спитає довіра до робочої області. Конфігурації Node (`node`, `pwa-node`) і Python (`python`, `debugpy`) зневаджують свій `program` у своєму `cwd`, зі своїми `args` і `env`; конфігурації Chrome (`chrome`, `pwa-chrome`) відкривають свій `url` (або `file`) зі своїм `webRoot`. Без `launch.json` **Налагодити файл** (⇧⌘F5) і кнопка зневадження на панелі самі визначають, що запускати, із самого проєкту — точка входу скрипта `start`, `main`, `index.js`, — а прилад стійки **INSPECTOR** запускає зневаджувач як крок конвеєра. |
| **Integrated terminal** | Вікно **Термінал** (⌃\`): перше натискання запускає оболонку в теці проєкту, наступні повертають її. |
| **`settings.json`** | Інструменти ▸ Налаштування (на macOS — NMOX Studio ▸ Settings…). `.vscode/settings.json` репозиторію задає відступи його файлів (`editor.tabSize`, `editor.insertSpaces`) і чинні під час збереження `files.trimTrailingWhitespace` та `files.insertFinalNewline`; його `.editorconfig` перемагає всюди, де висловлюються обидва, — і під час набирання, і під час збереження. |
| **Problems panel** | **Завдання** (⌘6) або клацання по лічильнику **✕ ⚠** у рядку стану: помилки й попередження мовних серверів, а також знахідки лінтингу й перевірки типів від приладів стійки PURITY і TYPEGUARD. Як і у VS Code, деякі сервери повідомляють лише про відкриті файли; gopls повідомляє про весь пакет. |
| **Outline** | **Навігатор** (⌘7). |
| **Source Control** | Значок git у рядку стану (гілка й зміни, одне клацання до історії) і меню **Команда**. |
| **Workspace Trust** | Та сама ідея, що виконується, перш ніж запуститься будь-що, обране репозиторієм: відкритий склонований проєкт не виконує нічого, доки ви йому не довіритеся. |
| **Keyboard Shortcuts editor** | Інструменти ▸ Налаштування ▸ Комбінації клавіш (на macOS — Settings… ▸ Комбінації клавіш): змініть будь-яке сполучення або перемкніть увесь профіль на Eclipse, Emacs чи IntelliJ. |

Коли ви вперше відкриваєте репозиторій, у якому є `.vscode/tasks.json`, `launch.json` чи `settings.json`, сповіщення каже, що знайдено й де це лежить; клацання по ньому відкриває Швидкий пошук. Для кожного проєкту воно з’являється лише раз.

<a id="what-is-honestly-different"></a>
## Що тут чесно інакше

- **У типовому профілі ⌘D додає наступне входження, але не в кожному профілі.** Профіль Eclipse залишає ⌘D за *Delete Line* середовища Eclipse, а профіль NetBeans 5.5 — за *Shift Line Left*; там той самий жест — ⌘J (Ctrl+J).
- **⌃\` відкриває Термінал і переводить на нього фокус, але не ховає його.** А поки фокус у Терміналі, клавіші належать вашій оболонці, тож друге натискання дістається оболонці, а не повертає вас у редактор.
- **`launch.json` читається, а те, чого зневаджувач не може виконати, відхиляється.** Зневаджувач тут передає програму, її робочу теку, її `args` (список рядків) та її `env` (рядки, додані до успадкованого оточення), тож конфігурація, що задає `envFile`, `runtimeExecutable`, `runtimeArgs`, `preLaunchTask` чи будь-яке інше поле, якого його не навчили, є в списку, але не запускається: Ввід називає ці поля в рядку стану. Запустити програму без них означало б зневаджувати не те, що написано у файлі. Так само вийшло б з `args`, записаними одним рядком (такий рядок VS Code віддає оболонці), і зі значенням `null` в `env` (воно видаляє змінну). Те саме стосується `"request": "attach"`, запису `compounds`, типу, для якого тут немає адаптера (`go`, `msedge`, `cppdbg` та інші), значення, яке може підставити лише VS Code (`${file}`, `${input:…}`), і шляху за межами проєкту. Поля, що лише змінюють те, що показує зневаджувач, — `skipFiles`, `outFiles`, `sourceMaps`, `console`, `justMyCode`, `presentation`, — приймаються, але не застосовуються; вивід програми йде у вікно Output.
- **`tasks.json` читається, а те, що не можна виконати так, як написано, відхиляється.** Завдання, яке використовує значення, доступне лише VS Code (`${input:…}`, `${file}`, `${config:…}`, `${command:…}`), або через `dependsOn` залежить від іншого завдання, є в списку, але не запускається: Ввід називає в рядку стану, яка змінна чи яке завдання заважає. Запуск із порожнім значенням або без завдання, від якого воно залежить, виконав би не те, що написано у файлі. Так само з типом завдання, який дає розширення (`gulp`, `typescript`), і з робочою текою за межами проєкту.
- **Завдання `"type": "shell"` виконується в тій оболонці, яку взяв би VS Code.** На macOS і Linux це ваш `$SHELL` із `-c` (zsh, bash чи fish на macOS стартують як оболонка входу, `-l`, як у типових профілях VS Code); у Windows — PowerShell, `pwsh`, якщо його встановлено. `options.shell` шанується так, як це робить VS Code: укажіть `executable`, і оболонка запуститься рівно з тими `args`, що ви дали, тож bash потрібен `"args": ["-c"]`. У Windows запускаються лише PowerShell (аргументи закінчуються на `-Command`) і `cmd.exe` (аргументи закінчуються на `/c`); будь-яку іншу оболонку там відхилено за назвою, а не передано їй командний рядок, узятий у лапки навмання.
- **Профілю розкладки «VS Code» немає.** Сполучення вище живуть у типовому профілі та в інших чотирьох. Один навмисний виняток: у профілі **Eclipse** ⇧⌘E лишається власним *Switch to Editor* середовища Eclipse, а всередині редактора ⇧⌘P і ⇧⌘X зберігають значення Eclipse (парна дужка, верхній регістр) — хто обрав Eclipse, чекає Eclipse.
- **У Linux Ctrl+\` відкриває Термінал, а не перемикач вікон.** Перемикач — на Ctrl+Tab. На стільниці, що забирає Ctrl+Tab собі (KDE, наприклад), відкриті файли перелічує **Вікно ▸ Документи…**.
- **Сполучення Ctrl+Alt можуть зіткнутися з AltGr.** У Windows розкладки, які набирають символи через AltGr (польська, наприклад), надсилають для нього Ctrl+Alt. Якщо Ctrl+Alt+P чи Ctrl+Alt+K друкує вам символ, перенесіть *Змінити проєкт* або сполучення експериментів у Комбінаціях клавіш.
- **Розширення VS Code тут не встановлюються.** Інтелект мов дають мовні сервери, які знає NMOX (Діагностика середовища перелічує, чого бракує і як це встановити), власні граматики редактора та плагіни, зроблені для платформи NetBeans.
