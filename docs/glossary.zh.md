NMOX Studio 用而别的 IDE 不用的词，以及从 NetBeans 平台透出来的那些术语。每一条都说明这个词在这里是什么意思，以及去哪里读更多。

<a id="the-rack"></a>
## 机架

**任务机架**（Task Rack，⌘9）— 你的工具在其中运行的窗口。每个任务（安装、构建、测试、服务、检查、部署）都是装在机架上的一台*设备*，就像录音棚里的硬件。[用户指南第 4 章](user-guide.zh.md#4-the-task-rack)。

**设备**（device）— 机架上的一个工具，例如 VELOCITY（Vite）、VERITAS（测试）或 PURITY（代码检查）。设备有一块前面板（*面板*），上面有旋钮、按钮、指示灯和一块小显示屏，还有一块带*插孔*的后面板。内置设备共有 53 台，列在[设备参考](devices.md)里。你也可以在 `~/.nmox/devices.d/` 里用一个 JSON 文件添加你自己的设备（[设备文件](device-files.md)）。

**面板**（faceplate）— 设备的前面板。在机架里按 **Tab** 把它翻过来，就能看到后面板。

**插孔**（jack）— 设备后面板上的一个接口。输出插孔发出信号，输入插孔接收信号。信号有三种：
- **触发**（trigger）是一个脉冲：“构建完成”“OK”“FAIL”。
- **闸门**（gate）保持开或关：“服务器已启动”。
- **数据**（data）携带文本，例如一个 URL 或一行输出。

**跳线**（cable）— 从一个输出插孔到一个输入插孔的连接。把构建的 OK 插孔接到测试运行器的 RUN 插孔，每当构建通过，测试就会运行。要连接两个插孔，从一个拖到另一个，或者先点一个再点另一个。

**配线**（patch）— 一整个机架：它的设备、设备的设置以及跳线。以 `.nmoxrack.json` 保存在项目旁边，所以值得提交进版本库。

**预设**（preset）— 可以从机架的**预设**菜单加载的现成配线，例如*发布闸门*或 *E2E 循环*。把任何配线保存进 `~/.nmox/presets.d/`，它也会出现在菜单里。

**起步机架**（starter rack）— 项目第一次打开时得到的配线，按项目的类型选择：Vite 应用得到一个 Vite 控制台，Cargo crate 得到运行、调试和测试通道，以此类推。

**通道**（lane）— 两种意思，都和运行东西有关：
- 一条**流水线**：由跳线连起来的一串设备，例如 安装 → 构建 → 测试。几条通道可以并排运行，QUORUM 会等它们全部结束。
- 设备的 **AUTO 通道**：它为这个项目选的命令。在 AUTO 位置上，测试设备在 Node 项目里运行 `npm test`，在 Rust 项目里运行 `cargo test`。

**分享… / 导入…**（Share… / Import…）— 把一个机架存成文件给别人，或者加载别人给你的机架。导入在挂载任何东西之前，会先把文件里的全部内容给你看，而且每台设备到达时都处于关闭状态。

**机架库**（Rack Gallery）— **工具 ▸ 机架库…** 列出社区机架、预设、起步机架和你自己保存的机架。每一项都说明它是做什么的、需要哪些工具。[社区机架](racks.md)。

<a id="projects-and-running"></a>
## 项目与运行

**指向** / **指向的项目**（aim / aimed project）— IDE 当前正在处理的那个项目。打开一个项目就是指向它：机架、各工作室、状态栏和运行都跟着指向的项目走。指向另一个项目会把它们全部切换过去，而仍在运行的东西会在询问之后先被停掉。

**工作区信任**（Workspace Trust）— NMOX Studio 第一次运行一个项目自己的代码（脚本、构建、测试）之前提出的问题。如果你回答**保持安全**，这个项目里的任何东西都不会运行。你的回答按文件夹记住。

**▶ 和 ■** — 工具栏上的运行和停止。▶（F6）运行指向的项目。■（⌥⌘.）停止 NMOX Studio 替你启动的每一条命令。

**⇄ 标记** / **正在服务**（⇄ chip / serving）— 当你运行的东西打印出一个本地地址，例如 `http://localhost:5173/`，这个地址会出现在状态栏上的 ⇄ 符号之后。那个正在运行的服务器就是一次*服务*。点击地址会在浏览器里打开它。快速搜索把服务列在*活动服务器*下。

**实验**（experiment）— 在 `~/.nmox/experiments` 里用模板做出来的一次性项目。它的依赖已经装好，也已经受信任。想留下它就**提升**，否则就**丢弃**。**文件 ▸ 新建实验…**。

**学习空间**（learning space）— 一门语言或一个框架的带引导的教程。它会创建一个真正的项目、一份导览，以及一个接好活的 REPL 的机架，而**文件 ▸ 检查我的作业**会检查你的练习。一共有 93 个。**文件 ▸ 新建学习空间…**。

**PREFLIGHT** — 发布前检查的设备。它把你项目定义的检查（代码检查、类型、测试、构建）作为一次通过或失败来运行。

**第一步**（First Steps）— 欢迎标签页上的清单。你做完一步，它就自己打上勾，而且永远不会撤销。

<a id="the-windows"></a>
## 窗口

**工作室**（studio）— 为某一类工作配有自己工具的窗口。一共有五个：**API 工作室**（⌥⌘8）、**数据库工作室**（⌥⌘7）、**合约工作室**（⌥⌘6，智能合约）、**块工作室**（⌥⌘5，用积木搭出的 Web 组件）以及**基础设施设计器**（⌥⌘9，云基础设施）。每一个都把工作以 `.nmox*.json` 文件保存在项目旁边。**项目工作室**名字里也有“工作室”，但它是文件树和项目模板。

**工作台**（Workbench，⌥⌘0）— 母港：正在运行什么、打开了什么，以及你最近的项目和文件。

**任务看板**（Task Board，⌥⌘1）— 每个项目一块看板，带冲刺和计时器，保存为 `.nmoxtasks.json`。

**欢迎**（Welcome）— 起始标签页：开始用的操作、最近的项目、列出每个窗口的**工具**一栏，以及第一步。

<a id="ai"></a>
## AI

**KVASIR** — NMOX Studio 的 AI 功能的名字：询问、编辑、补全、解释、起草提交信息。它配合 Claude、ChatGPT 或 Gemini 工作，用的是你自己的 API 密钥，密钥存在操作系统的钥匙串里。每个功能都会先征求一次你的同意，并准确说出会发送什么。在你使用某个功能之前，什么都不会发送。早期版本叫它 ORACLE。

**Agent Port** — **工具 ▸ Agent Port (MCP)…** 让运行在你机器上的 AI 代理（例如编程助手）通过 MCP 只读地访问 IDE 的状态：打开的文件、诊断、运行、符号。它在设计上就是只读的，而且只在你自己的机器上监听。[教程](tutorials/agent-port.md)。

<a id="netbeans-terms-you-may-see"></a>
## 你可能会看到的 NetBeans 术语

NMOX Studio 建立在 NetBeans 平台之上，它的一些词会透出来。

**模块** / **NBM**（module）— 应用的一个组成部分。*NBM* 是交付模块所用的文件。**工具 ▸ 插件**按模块逐个安装更新。

**更新中心**（update center）— **工具 ▸ 插件 ▸ 更新**获取 NMOX Studio 模块新版本的地方。它读取随每个 GitHub 版本发布的目录。

**userdir** — NMOX Studio 存放设置、窗口布局、日志和已安装更新的文件夹。“关于”对话框会显示它在哪里（Windows 和 Linux 上在**帮助**菜单里，macOS 上在 **NMOX Studio** 应用菜单里）。它的日志在 `var/log/messages.log`。想用全新的设置启动，就用 `--userdir <an empty folder>`（尖括号里换成一个空文件夹） 启动。

**选项** / **Settings…**（Options / Settings…）— 偏好设置对话框。在 Windows 和 Linux 上是**工具 ▸ 选项**，在 macOS 上是 **NMOX Studio ▸ Settings…**。

**操作项**（Action Items）— 列出项目中发现的问题的窗口：语言服务器报告的错误和警告，以及机架的代码检查和类型检查结果。点击一个问题就会跳到那一行。
