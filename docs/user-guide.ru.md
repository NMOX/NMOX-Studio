<a id="1-install"></a>
## 1. Установка

**macOS (рекомендуется):**
```bash
brew trust --cask nmox/nmox-studio/nmox-studio
brew install nmox/nmox-studio/nmox-studio
```

Строка `brew trust` — это разовое подтверждение Homebrew для любого стороннего tap: при обновлениях его больше не спросят. Приложение подписано ad-hoc, но не нотаризовано, поэтому копию в карантине Gatekeeper отклонил бы при первом запуске: cask сам снимает атрибут карантина шагом `postflight` и пишет об этом в вывод установки. Ничего молча.

**Всё остальное:** скачайте файл из [последнего выпуска](https://github.com/NMOX/NMOX-Studio/releases/latest) — `.dmg` для macOS, `-setup.exe` для Windows, `.deb` для Debian/Ubuntu, обычный `.tar.gz` для Linux. Все четыре несут собственную среду выполнения Java; заранее ставить ничего не нужно. `-portable.zip` — единственный артефакт, использующий вашу Java (нужна Java 21+ в PATH либо запуск с `--jdkhome <путь-к-jdk>`).

> **macOS, первый запуск:** приложение подписано ad-hoc, но не нотаризовано, поэтому Gatekeeper спрашивает перед запуском. В первый раз **щёлкните по приложению правой кнопкой → Открыть** и подтвердите, либо выполните
> `xattr -d com.apple.quarantine "/Applications/NMOX Studio.app"`. Любой способ решает это навсегда.

### Обновление

IDE обновляет себя сама: **Сервис ▸ Плагины ▸ Обновления** предлагает модули любого более нового выпуска. Установите, перезапустите по запросу — готово, без повторной загрузки всего приложения. Честная оговорка: встроенная среда Java и загрузчик меняются только с полным установщиком, поэтому для крупных переходов платформы правильно поставить заново из файла выпуска.

<a id="2-first-launch"></a>
## 2. Первый запуск

Из терминала `nmoxstudio --open <папка>` запускает приложение с этой папкой, открытой как проект, и наведённой на неё стойкой — та же дверь, что открывает «Открыть папку…» на странице приветствия.

IDE открывается со всеми вкладками набора рядом с областью редактора: **Добро пожаловать → Стойка задач → Студия баз данных → Студия контрактов → Конструктор инфраструктуры → Студия API → Панель Docker** — каждая основная поверхность в одном щелчке с первой минуты. В левой панели: **Студия проекта** (дерево файлов и шаблоны), база **Рабочее место** и **Обозреватель NPM**. Создаётся папка `~/NMOX` как рабочее пространство по умолчанию; стойка указывает туда, пока вы не откроете проект.

![Первый запуск — страница приветствия со всеми открытыми вкладками](images/welcome.png)

<a id="3-projects"></a>
## 3. Проекты

**Открытие:** любая папка с одним из 60 распознаваемых манифестов открывается как настоящий проект — `package.json`, `Cargo.toml`, `go.mod`, `pom.xml`, `composer.json`, `foundry.toml`, `bower.json`, `Gruntfile.js` и подобные — включая манифесты контрактных сетей: репозиторий Aiken (`aiken.toml`) или Clarinet (`Clarinet.toml`) открывается с уже подключёнными настоящими дорожками. Простая папка с HTML и тегами `<script>` **без** манифеста тоже открывается — как проект STATIC: классический веб здесь полноправен, а не ошибка.

**Создание:** *Новый проект…* предлагает настоящие заготовки — Angular, Vue, Svelte, чистый JavaScript, Elixir/Phoenix, PHP Web (LEMP) и Классический веб (jQuery). Каждая приходит с подключёнными настройками линтера, форматирования и тестов и с инициализированным репозиторием git: один коммит-заготовка, который — если мастер выполнил установку за вас — содержит и файл блокировки, так что ваш первый `git status` чист.

**Переключение безопасно:** если устройства работают (сервер разработки, наблюдатель), IDE спрашивает перед переключением и аккуратно их останавливает. Ничто не продолжает работать у вас за спиной — никогда. Даже принудительное завершение IDE не оставит осиротевший процесс.

**Эксперименты** — самый быстрый способ попробовать стек. **Файл ▸ Новый эксперимент…** (⇧⌘E) выбирает шаблон и создаёт одноразовый проект в `~/.nmox/experiments`: без git, без списка недавних, уже доверенный, с установленными зависимостями — чтобы **первый запуск просто сработал**. Он открывается на собственном обходе `EXPERIMENT.md`, который говорит, что нажать, какой файл изменить и где живёт интеллект IDE для этого стека. Оставьте то, из чего что-то выросло: **Файл ▸ Эксперименты…** ▸ **Повысить** выносит его наружу и инициализирует git, **Дублировать** создаёт копию рядом для второго подхода, **Отбросить** убирает остальное. Полка показывает возраст каждого и его измеренную цену на диске. Хотите путь с проводником? Диалог выводит вперёд 93 учебных пространства.

![Полка учебных пространств — количество, цена на диске, возраст и весь жизненный цикл](images/spaces-shelf.png)

![Свежий эксперимент Express: обход открыт, зависимости установлены, API уже отвечает](images/experiment-walkthrough.png)

**Запуск, сборка, тесты — и остановка:** кнопка ▶ на панели (F6) запускает проект так, как его запускает его инструментарий: скрипт `start`, если он есть в package.json, `cargo run`, `go run`, `dotnet run`, а для папки с HTML — небольшой статический сервер на первом свободном порту начиная с 8080. Сборка, Тесты и Очистка рядом и в меню «Запуск». Сервер разработки, объявивший свой адрес, зажигает значок ⇄ в строке состояния и открывает страницу во встроенном браузере. Всё в первый раз проходит через запрос доверия рабочему пространству. Запуск, который не смог начаться, честно говорит об этом и предлагает открыть Доктор окружения. Чтобы остановить: ■ справа от «Отладка» (⌥⌘.) останавливает сразу все выполняемые команды и сообщает, что именно остановил; **Запуск ▸ Остановить** останавливает одну и затем предлагает **Повторить**. ■ видит всё, что продукт запускает для вас, включая установки; при наведении подсказка называет ровно то, что остановит нажатие, и с какого времени работает каждое.

**`.env` повсюду:** если в проекте есть `.env`, устройства, запущенные из стойки, получают эти переменные. Отредактируйте его — и строка состояния отметит, что перезапуски его подхватят; работающие процессы честно сохраняют прежнее окружение.

<a id="4-the-task-rack"></a>
## 4. Стойка задач

![Стойка задач](images/tabs/the-task-rack.png)

Стойка — сердце продукта. Каждый инструмент вашего рабочего процесса — npm, сборщик, запускатель тестов, сервер разработки, линтер, git, развёртывание — это прибор в стойке: ручки выбирают задачу, GO её выполняет, светодиоды показывают состояние, а ЖК-экран словами рассказывает, что произошло.

![Стойка, наведённая на классический сайт на jQuery — пресет Classic Web Bench: MAESTRO, CRATE, DYNAMO (его ручка TASK разобрала настоящий Gruntfile), IGNITION раздаёт статику, VITALS следит за качеством](images/task-rack.png)

**Основы:**

- **Добавляйте приборы**, перетаскивая их с палитры (в ней есть категории и поиск). У каждого прибора есть карточка *Как пользоваться*.
- **Запускайте**, нажимая кнопку GO прибора. Сначала наведите на неё курсор: подсказка покажет точную командную строку, которая будет выполнена. Никакой магии.
- **Соберите конвейер:** нажмите **Tab**, чтобы развернуть стойку задней стороной. Протяните патч-кабель от гнезда **OK** одного прибора к гнезду **GO** следующего. Теперь `установка → сборка → тесты` — одно нажатие: цепочка идёт сама и останавливается на первом сбое. Вывод бежит по люминофорному экрану прибора MONITOR.
- **Отменяйте любые структурные изменения** через **⌘Z** — добавление, удаление, перекоммутацию. Удаление работающего прибора сначала останавливает его процесс.
- **Пресеты** дают целую собранную стойку одним щелчком — Ship Gate, Dev Intelligence, Monorepo Lanes, E2E Loop, LAMP Bench, Web3 Bench, Uptime Watch. Схемы сохраняются по проекту автоматически.

![Tab разворачивает стойку — патч-кабели ведут MAESTRO через CRATE, DYNAMO и IGNITION к VITALS](images/rack-rear.png)

**Координация, когда конвейер разрастается:**

- **QUORUM** сводит дорожки: он срабатывает, только когда *все* его подключённые входы завершились успешно — классическое «дождись линтера И тестов И проверки типов».
- **Затворы ENABLE** на долгих процессах: вход ENABLE сервера разработки означает «не запускайся, пока это не сработает».
- **REFLEX** следит за файлами и разводит их по шаблону — `src/**/*.css` в одну цепочку, `**/*.ts` в другую, по дорожке в монорепозитории.
- **ROSETTA** выбирает дорожку инструментов в смешанных репозиториях (стойка определяет Node/Rust/Go/PHP/… по каталогу и наводит каждый прибор соответственно).

**Дорожки говорят на языке вашего инструментария.** В положении AUTO приборы линтинга и форматирования (PURITY, GLOSS) говорят на инструментарии самого проекта, а не тянутся всюду к средствам Node: рабочее пространство Deno использует `deno lint` и `deno fmt`, проект Cargo — `cargo clippy` и `cargo fmt`, модуль Go — `go vet` (или `golangci-lint`, если проект несёт свою конфигурацию) и `gofmt`. Файл `biome.json` переводит дорожки Node на Biome, а явные положения ручки всегда важнее AUTO.

**Ваши собственные приборы.** Полка расширяется текстовым редактором: любой `*.json` в `~/.nmox/devices.d/` становится настоящим прибором — ручки, кнопки, светодиоды, порты и кабели, сохраняется в схеме и доступен из ⌘I. Опишите команду массивом аргументов, назовите ручку — и `{{ручка}}` подставится при нажатии кнопки. Законы остаются за хозяином, а не за вашим файлом: **доверие рабочему пространству охраняет первый запуск ровно так же, как у встроенного прибора**.

**Затворы качества** превращают «вроде готово» в «готово»:

- **VITALS** прогоняет Lighthouse по вашему живому серверу и требует минимума производительности, доступности, добрых практик или поисковой пригодности.
- **VERITAS** держит минимум покрытия и повторяет ровно те тесты, что упали, по именам.
- **GAUNTLET** нагружает конечную точку и требует минимальной пропускной способности. **PRISM** следит за размером сборки, **BEACON** — за сертификатом и доступностью URL, а **PREFLIGHT** — это список проверок перед отправкой: подключите его OK к прибору развёртывания, и развёртывание физически не сможет пойти, пока всё не станет зелёным.
- **GOVERNOR** следит за регрессиями газа в работе с Solidity (`.gas-snapshot`).

**Всё остальное:** **SOLDER** оборачивает любую команду оболочки в полноценный прибор — а вся стойка **экспортируется в GitHub Actions** (ваш локальный конвейер и ваша интеграция — одна и та же схема). **HELM** выполняет команды на удалённом сервере по ssh, **TAIL** следит за любым журналом, а **PHOSPHOR** — это терминал внутри стойки. Если команда печатает локальный адрес, значок ⇄ загорается, как у любого раздающего прибора, и гаснет, когда запуск завершается.

**Стойка держит себя в согласии сама.** Отредактируйте `package.json` — и ручка скриптов NPM-9000 обновится на месте. Отредактируйте `Gruntfile` — и DYNAMO перечитает свои задачи. Добавьте зависимость — и дисплей CRATE обновится. Не нужно ни перенаводить, ни жать кнопки обновления.

### KVASIR — объясняет последний сбой

![KVASIR объясняет реальный упавший запуск: разрешённый диагноз на лицевой панели и полные шаги исправления в окне просмотра](images/kvasir-explain.png)

**KVASIR** — это помощь ИИ по-стоечному: прибор, который объясняет ошибку, лежащую сейчас на шине MONITOR, а не боковая панель чата. Когда запуск падает, нажмите **EXPLAIN** — и KVASIR спросит вашу ИИ, что пошло не так и каков конкретный следующий шаг. Краткий вердикт появляется на дисплее; **VIEW** открывает полный ответ. **MODEL** выбирает между **FAST** (быстро и дёшево, по умолчанию) и **DEEP** (сильнее). EXPLAIN синий: он читает и спрашивает, но никогда не трогает ваш проект.

**Выберите свою ИИ, положите свой ключ.** KVASIR работает с **Claude (Anthropic)**, **ChatGPT (OpenAI)** или **Gemini (Google)** — ваш ключ, ваш выбор. Нажмите **KEY…**, чтобы выбрать поставщика и вставить его ключ; выбор запоминается, а ключ живёт только в связке ключей операционной системы. Обычные переменные окружения каждого поставщика тоже читаются, и сохранённый ключ важнее ключа из окружения.

**Что KVASIR отправляет — и это всё, что он отправляет.** При первом нажатии EXPLAIN диалог перечисляет ровно то, что покинет вашу машину, и то, что не покинет; без этого согласия не отправляется ничего, и согласие даётся отдельно каждому поставщику. После удачного EXPLAIN кнопка **VIEW** открывает ответ как беседу — можно продолжать спрашивать про тот же сбой.

**Спросите KVASIR о своём коде.** Тот же помощник дотягивается до редактора: выделите код и выберите **Спросить KVASIR о выделенном…** или **Изменить с KVASIR…**, чтобы сказать, что поменять, и увидеть «до» и «после» прежде, чем что-то применится. **⌥⌘G** дополняет у курсора призрачным текстом, который вставится только по Tab, а значок ветки git может составить сообщение коммита.

**Наведите агента на свою IDE.** Сервис ▸ Agent Port (MCP)… открывает конечную точку MCP, которую может опрашивать внешний помощник: она **только для чтения по построению**, выключена, пока вы её не включите, слушает лишь локальный интерфейс и требует токен, созданный при запуске.

Стойка расширяема: сторонние модули могут добавлять приборы (установите их NBM через Сервис ▸ Плагины). Чтобы написать свой, см. [device-spi.md](device-spi.md).

<a id="5-the-editor"></a>
## 5. Редактор

![Код jQuery в палитре NMOX Phosphor, структура в Навигаторе](images/editor.png)

Более 70 языков подсвечиваются как надо — современный набор, классический (включая CoffeeScript) и весь слой настроек, вплоть до `.env`, `.editorconfig`, конфигураций nginx и Apache, файлов Dockerfile и файлов блокировок.

- **Дополнение** знает контекст, а также *классические библиотеки*: если проект несёт jQuery, MooTools, Prototype, Backbone/Underscore или Knockout (через зависимости npm *или* обычные теги `<script>`), их API появляются при дополнении. Проекты на jQuery 1.x и 2.x получают честную отметку об окончании поддержки, а не назойливое напоминание.
- **Структура в Навигаторе (⌘7)** показывает устройство файла для 58 типов; щелчок переносит к месту.
- **Миникарта** — силуэт всего файла рядом с полосой прокрутки каждого редактора; щёлкните или потяните, чтобы прокрутить. Документ всегда умещается в полосу целиком: строки сжимаются по мере роста файла. Вид ▸ Миникарта включает и выключает её сразу во всех открытых редакторах.
- **Липкая прокрутка** — объявления, охватывающие верх видимой области (класс, а затем метод, в который вы опустились), остаются закреплёнными над текстом, до трёх строк самого исходника; щелчок переносит к строке. Полоса исчезает, когда верхнюю видимую строку ничто не охватывает.
- **Перейти к символу (⌥⇧⌘O)** переносит к любой функции, классу, правилу или заголовку во всём проекте по набранному имени — с совпадением по префиксу, по заглавным буквам внутри слова или по шаблону. Указатель ограничен и честен: `node_modules` пропускается, а на очень большом проекте диалог говорит, что проиндексировал первые 2000 файлов, вместо того чтобы делать вид, будто прочитал всё.
- **Окно тестов (⌥⌘2)** показывает все тесты проекта *до того, как что-либо запущено*, и запускает один тест, файл или всё сразу.

### Развернуть сокращение (⌥⌘E)

Наберите сокращение Emmet и нажмите **⌥⌘E**: `ul>li*3` превращается в готовый список. Это работает в HTML, в шаблонах Angular и — в форме CSS — внутри блоков `<style>` и атрибутов `style`, где вырезка ограничена областью, так что она никогда не проглотит окружающую разметку. Сокращение, которого продукт не знает, отклоняется и оставляет ваш текст нетронутым.

### Токены оформления (пользовательские свойства)

Набор `var(` предлагает токены, объявленные в настоящих таблицах стилей вашего проекта, каждый со своим образцом цвета и указанием места объявления. **⌘-щелчок** по использованию `var(--токен)` переносит к его объявлению. Цвета рисуются тем цветом, которым они являются — hex, `rgb()`, `hsl()`, имена, а также `oklch()`, `lab()` и `color-mix()` — а **⌘-щелчок** по цветовому литералу открывает палитру, которая заменит его ровно в той записи, в какой вы его написали.

### Атрибут class знает ваши таблицы стилей

Набор внутри `class="…"` предлагает классы, которые ваш проект действительно объявляет, с указанием таблицы, откуда они; **⌘-щелчок** по классу переносит к его правилу, а **⌘-щелчок** по селектору `.класс` — к его первому применению в разметке. **Переименовать класс…** переименовывает во всём проекте — только целые токены, с числом по каждому файлу — и вслух отказывается, если новое имя уже занято или остались несохранённые изменения.

### Запустить скрипт прямо от курсора

В разделе `scripts` файла `package.json` команда **Запустить скрипт** выполняет строку, на которой стоит курсор — через тот же запрос доверия рабочему пространству и тот же ■, что и любой другой запуск.

### Ключи окружения — полноправные

Набор `process.env.` или `import.meta.env.` предлагает ключи, которые действительно объявлены в вашем семействе файлов `.env`, а **⌘-щелчок** переносит к строке с объявлением. Значения показываются урезанными: напоминание есть, секрета нет.

### Шаблоны Angular — полноправные

Файлы `.component.html` открываются с собственной подсветкой шаблона, с блоками `@if`/`@for` и структурными директивами в дополнении. Установите Angular Language Service — и проверка типов шаблона действительно доходит: ошибитесь в имени свойства, и собственный компилятор Angular предложит верное. **⌘B** в шаблоне переносит к объявлению, а контекстное меню переключает между компонентом, его шаблоном, стилями и тестом.

### Компоненты Vue и Svelte — полноправные

Файлы `.vue` и `.svelte` открываются со своей подсветкой, своим дополнением (включая точечные руны Svelte 5) и Emmet внутри блоков шаблона. Диагностика Vue действительно доходит до редактора — через собственный языковой сервер Vue.

### Отладка с настоящими точками останова

Щёлкните по левому полю, выберите **Отладить файл (точки останова)** — и программа остановится там, со стеком, переменными и вычислением выражений. JavaScript и TypeScript работают сразу благодаря встроенному адаптеру; Python использует debugpy, а Go — delve, которые вы ставите сами. **Отладить в Chrome** делает то же для страницы: точки останова в вашем исходнике срабатывают внутри IDE, пока браузер работает на одноразовом профиле. Всё сначала проходит через запрос доверия рабочему пространству.

### Показывать и делиться

**Вид ▸ Режим презентации** разом увеличивает каждый открытый редактор, страницу во встроенном браузере, окно вывода и терминал — и возвращает всё ровно как было при выходе. **Вид ▸ Показывать нажатия** крупно показывает только что нажатое сочетание, но никогда — то, что вы набираете. **Правка ▸ Копировать как Markdown** копирует выделенное огороженным блоком с верной пометкой языка, а вариант **со ссылкой** добавляет ссылку GitHub на те же строки. **Сервис ▸ Сохранить снимок…** рисует всё окно в двойном размере; есть варианты для одной вкладки редактора, для буфера обмена и для копирования дерева проекта в Markdown.

<a id="6-the-studios"></a>
## 6. Студии

### Доступ с клавиатуры и через экранный диктор

У каждого органа управления в стойке есть доступное имя, и это проверяется при каждой сборке. Ручки — это ползунки, отвечающие на стрелки, Home и End; кнопки отвечают на пробел и Enter, включая приглушённые, которые говорят, почему отказывают; светодиоды и экраны сообщают своё состояние. Tab разворачивает стойку — кроме случая, когда фокус на органе управления: тогда он уступает обычному обходу.

### Git в строке состояния

Значок **⎇ ветка** показывает, на какой вы ветке и сколько файлов изменено; он читается с диска, поэтому не стоит ни одного процесса. Щелчок открывает полную историю, а меню несёт **Различия проекта**, **Аннотировать**, запросы на слияние через ваш собственный `gh` и **Составить сообщение коммита с KVASIR**.

### Доска задач (⌥⌘1)

Канбан для каждого проекта, сохраняемый в `.nmoxtasks.json` — рядом с вашим кодом и под тем же контролем версий. Перетаскивайте карточки или двигайте их с клавиатуры: **⌘↑/⌘↓** меняет порядок, и перемещённая карточка сохраняет фокус. Ограничения на незавершённую работу — это совет, а не преграда: заголовок краснеет, но никто вас не останавливает. Кнопка **Обзор** меняет колонки на сводку — что в работе, сделано сегодня и за неделю, поток по дням, стареющие карточки — а часы (**Отметиться**) считают настоящее время по карточке, причём на всей доске идут только одни часы. **Планёрка** превращает всё это в готовый к вставке отчёт.

### Студия блоков (⌥⌘5)

Собирайте настоящие веб-компоненты из типизированных сцепляющихся деталей, как в Scratch: недопустимые вложения отвергаются, код рождается самодостаточным пользовательским элементом, а щелчок по детали подсвечивает её строки. Сервер предпросмотра в памяти показывает компонент по-настоящему, вместе с остальными исправными компонентами вашей библиотеки. Круг замкнут точно: заново породить только что прочитанное даёт байт в байт тот же файл.

### Студия API (⌥⌘8)

Коллекции, запросы, окружения с `{{переменными}}` и тесты, сохраняемые в `.nmoxapi.json` — секреты только в связке ключей, никогда в этом файле. Каждый ответ получает оценку безопасности по своим заголовкам. Импорт из curl, `.http`, OpenAPI, Postman, Insomnia и HAR; экспорт в `.http` и копирование как curl или как `fetch`, с уже подставленными переменными.

### Студия баз данных (⌥⌘7)

SQLite, PostgreSQL, MySQL, MariaDB, MongoDB и CouchDB, со встроенными драйверами и паролями только в связке ключей. Консоль знает движок, у каждого оператора своя таблица результатов, а строки правятся прямо в таблице, если есть первичный ключ — с предпросмотром точных UPDATE перед применением и честной причиной, когда что-то доступно только для чтения. Экспорт в CSV или JSON, с обезвреженными формулами.

### Студия контрактов (⌥⌘6)

Дерево артефактов Foundry и Hardhat, **Взаимодействие** по ABI с расшифрованными возвратами и откатами, панель **Наблюдение** за блоками и событиями, и **Надзор** с таблицей газа, вердиктами по размеру EIP-170 и адресной книгой. **Никаких приватных ключей**: отправка идёт через разблокированные счета локальной сети, а секретные URL живут в связке ключей.

### Конструктор инфраструктуры (⌥⌘9)

Полотно для DigitalOcean, Hetzner и Cloudflare: сверьтесь с тем, что существует на самом деле, обновите, чтобы увидеть расхождения, и уничтожьте стек, видя перед собой его стоимость. Недопустимые соединения отказывают вслух и объясняют почему, а пока идёт облачная операция, полотно запирается и полоса об этом говорит.

### IRC (⌥⌘3)

Полноценный клиент внутри IDE: TLS с настоящей проверкой имени, SASL, расширения IRCv3, дополнение по табуляции, подсветки, ссылки, открывающиеся во встроенном браузере, запись на диск, собственные фильтры и список каналов, который вы отсеиваете по мере набора.

### Встроенный веб-сайт

**Справка ▸ Сайт NMOX Studio (локально)** отдаёт сайт продукта из его же стойки, на локальном интерфейсе. Он говорит на тех же тринадцати языках, что и IDE; переключатель — внизу страницы.

### Браузер (⌥⌘4)

Настоящий браузер внутри IDE, со своими инструментами разработчика — консоль, DOM, сеть, хранилище и панели для Vue, Svelte и Angular — потому что у движка нет своего инспектора, и этот наш. Он знает ваши исходники: выберите элемент, откройте породившую его строку, измените стиль прямо там — и объявление ляжет в исходную таблицу стилей. Сохранение файла перезагружает страницу, а настоящие размеры устройств служат проверке отзывчивой вёрстки.

<a id="7-docker"></a>
## 7. Docker

Вкладка Docker — это пульт: состояние движка, контейнеры, образы, тома и сети, с запуском, остановкой, журналами и очисткой. Устройство HARBOR на стойке показывает то же самое одним взглядом. И как уже сказано: поднимите контейнер Postgres, MySQL или Mongo — и Студия баз данных предложит вам готовое подключение.

Вкладка **Dockerize** создаёт `Dockerfile` промышленного качества, `.dockerignore` и файл композиции, подогнанные под набор инструментов вашего проекта — Node, PHP-FPM с nginx и другие.

<a id="8-wizards-and-kits"></a>
## 8. Мастера и наборы

Все они живут в *Новый файл…* и в контекстном меню проекта, и все они **идемпотентны и никогда не затирают чужое**: повторный запуск обновляет только то, что принадлежит самому набору, и не трогает ваши правки; то, что переписать нельзя, ложится рядом файлом `.suggested`.

### Набор стандартов

`robots.txt`, `sitemap.xml`, веб-манифест, `security.txt` по RFC 9116 и `humans.txt`, созданные из ваших ответов.

### Набор PWA

Полный комплект значков, выкованный из одного изображения, вместе с маскируемыми вариантами; читаемый сервис-воркер — оболочка приложения или сеть сначала, на ваш выбор, — страница для работы без сети и обвязка в `index.html`, которая связывает всё вместе.

### Набор доступности

Доступность как точка отсчёта, а не как проверка задним числом: `a11y.css` (видимое кольцо фокуса, утилита для текста, который читают только программы чтения с экрана, стили ссылки пропуска и блок для тех, кто предпочитает меньше движения), `A11Y-NOTES.md` с проходом по клавиатуре и вопросами, на которые не отвечает никакая автоматика, и идемпотентная обвязка `index.html` — язык, ссылка пропуска, таблица стилей. О viewport, запрещающем увеличение, вас предупредят, но не перепишут его; то, что набор починить не может, он называет, а не трогает.

### Набор интернационализации

Переводимо с первого дня, брат набора доступности: `locales/en.json` и `locales/es.json` (по каталогу на язык, с одинаковыми ключами), `i18n.js` без зависимостей, который применяет каталог к разметке `data-i18n`, держит `<html lang>` честным и показывает пропавший ключ им самим, а не молчаливой пустотой; плюс `I18N-NOTES.md` — никаких склеенных кусков, `Intl` для дат и чисел, проход справа налево и псевдолокализация.

### Набор контрактов (Web3)

Выберите цепочку — Solidity с Foundry, Soroban, Solana, CosmWasm, ink!, Cairo, Move, Bitcoin с Miniscript, Clarity на Stacks, Cardano с Aiken или TON с Tact — и имя контракта, и набор соберёт проверенное вживую начало: манифест, контракт, родной тест и CONTRACT-NOTES.md, называющий устройства стойки и разовые шаги. Ключи никогда не касаются среды.

### Классический набор

Добавьте к любому коду jQuery, MooTools, Prototype, Backbone с Underscore или Knockout — либо в самом репозитории (закреплённые версии, sha256 записан), либо зависимостями npm; плюс заготовки webpack, grunt, gulp или bower.

<a id="9-quick-search-status-line-and-staying-oriented"></a>
## 9. Быстрый поиск, строка состояния и как не потерять нить

### Значок ⇄ обслуживает

В строке состояния появляется значок **⇄ обслуживает**, как только работают серверы: запуск самой среды, обслуживающие устройства и любая команда, напечатавшая местный адрес. Нажмите и выберите один — он откроется во встроенном браузере или в системном, если та вкладка его не берёт.

### ⌘I, всеобщий искатель

Одно поле достаёт до ваших проектов (недавних и известных), до каждого устройства стойки — сразу к его органам управления, — до **работающих серверов** (Ввод открывает их в браузере), до запросов Студии API, до подключений и таблиц Студии баз данных, до контрактов, до узлов инфраструктуры и до карточек Доски задач, причём найденное называет столбец, в котором карточка стоит.

### Строка состояния говорит, что живо

Рядом со значком серверов — нацеленный проект с его набором инструментов и ветка Git с числом изменённых файлов. Всё это читается с диска или из записей, которые продукт и так ведёт: посмотреть не стоит ни одного процесса.

### Рабочее место

Это домашняя гавань: текущий проект, открытые и недавние файлы, недавние проекты и запуск для каждой поверхности. Пока что-то работает, страницу возглавляет раздел **ВЫПОЛНЯЕТСЯ** — каждая команда, которую продукт запустил за вас, с её адресом, если она его объявила, и с того часа, как она идёт, плюс каждый сервер, который обслуживает устройство стойки. В каждой строке настоящие кнопки **Открыть** и **Остановить**, достижимые с клавиатуры и программой чтения с экрана, так что один запуск можно остановить, не роняя остальные. Все заголовки на Рабочем месте — настоящие кнопки: Tab доходит, Ввод открывает. ⌘I достаёт до тех же запусков: наберите «остановить», и Ввод остановит именно этот. То, что вы остановили сами, читается как *остановлено* везде, где сообщают об исходе, и никогда как сбой.

### Сочетания клавиш Emacs (а также Eclipse и IntelliJ)

Сервис ▸ Параметры ▸ Раскладка клавиш меняет весь профиль: перемещения и вырезание Emacs в каждом редакторе или наборы Eclipse и IDEA, если ваша мышечная память там. Каждое сочетание NMOX записано во всех пяти профилях, так что смена профиля никогда не отнимет у вас сочетания студий.
