Эта страница запускает один из ваших собственных проектов внутри NMOX Studio.
Здесь только то, что для этого нужно. Полное руководство —
[руководство пользователя](user-guide.ru.md). Если вы работаете в VS Code,
дальше прочитайте [переход с VS Code](coming-from-vscode.ru.md).

<a id="1-install-one-minute"></a>
## 1. Установка (одна минута)

**macOS, через Homebrew:**

```bash
brew trust --cask nmox/nmox-studio/nmox-studio
brew install nmox/nmox-studio/nmox-studio
```

Homebrew один раз просит выполнить `brew trust` для любого стороннего tap.
При обновлениях он больше не спросит.

**macOS, Windows, Linux без Homebrew:** скачайте последний выпуск для своей
системы со
[страницы выпусков](https://github.com/NMOX/NMOX-Studio/releases/latest):

| Система | Файл | Затем |
|---|---|---|
| macOS | `NMOX-Studio-<version>-macos.dmg` | Перетащите приложение в «Программы». |
| Windows | `NMOX-Studio-<version>-windows-setup.exe` | Запустите установщик. |
| Debian, Ubuntu | `nmox-studio_<version>_amd64.deb` | `sudo apt install ./nmox-studio_<version>_amd64.deb` |
| Другой Linux | `NMOX-Studio-<version>-linux.tar.gz` | Распакуйте и запустите `bin/nmoxstudio`. |

В каждом из этих файлов есть своя среда выполнения Java, так что больше
ничего ставить не нужно. Только переносному zip нужна Java 21 или новее,
уже установленная на машине.

В macOS приложение нотаризовано Apple. При первом открытии macOS спросит,
открыть ли приложение, загруженное из интернета: нажмите **Открыть**.

<a id="2-open-your-project-one-minute"></a>
## 2. Откройте свой проект (одна минута)

Запустите **NMOX Studio**. Она открывает три вкладки: **Добро пожаловать**,
**Стойка задач** и **Браузер**.

Чтобы открыть проект, выберите **Файл ▸ Открыть папку…** (⌥⌘O в macOS,
Ctrl+Alt+O в Windows и Linux) и укажите его папку. То же можно сделать из
терминала, как с `code .`:

```bash
cd ~/code/my-app
nmox .
```

Команда возвращается сразу. Если NMOX Studio уже работает, она получает
папку; если нет, запускается. Homebrew, установщик Windows и пакеты Linux
ставят `nmox` в PATH. Для установки из DMG смотрите
[как поставить `nmox` в PATH](user-guide.ru.md#2-first-launch).

Папка считается проектом, если в ней есть `package.json`, `Cargo.toml`,
`go.mod`, `pom.xml`, `composer.json`, `pyproject.toml` или один из ещё 57
файлов проекта. Папка с простыми файлами HTML тоже считается.

Когда вы открываете проект, происходят три вещи:

- **Студия проекта** слева показывает ваши файлы.
- Строка состояния внизу показывает ветку git и число изменённых файлов.
- **Стойка задач** настраивается под вид проекта. Проект Vite получает
  консоль Vite, проект Cargo — дорожки запуска, отладки и тестов, и так
  далее.

<a id="3-run-it-one-minute"></a>
## 3. Запустите его (одна минута)

Нажмите **▶** на панели инструментов или F6. Проект запускается так, как
его запускают его инструменты: скрипт `dev`, `start` или `serve` из
`package.json`, `cargo run`, `go run`. Используется собственный менеджер
пакетов проекта: npm, pnpm или yarn, либо bun для проекта Bun.

Когда вы впервые что-то запускаете в проекте, NMOX Studio спрашивает,
доверяете ли вы этой папке. Проект, которому вы не доверяете, не запускает
ни строчки своего кода: ни скриптов, ни сборок, ни тестов. Для своего кода
нажмите **Доверять рабочей области**.

Если ваш проект — сервер разработки, его адрес появляется в строке
состояния рядом со значком **⇄**, а страница открывается на вкладке
**Браузер**. Измените файл и сохраните — страница перезагрузится.

Чтобы остановить всё, что работает, нажмите **■** рядом с ▶ или ⌥⌘.
(Option, Command и точка).

Если ничего не происходит, загляните во вкладку **Output** внизу. Она
объясняет, почему запуск не смог начаться, например что инструмент не
установлен или что зависимости ещё не установлены, и предлагает это
исправить. **Сервис ▸ Диагностика окружения…** перечисляет все
инструменты, которыми может пользоваться NMOX Studio, и показывает,
какие из них установлены.

<a id="4-find-anything-thirty-seconds"></a>
## 4. Найдите что угодно (тридцать секунд)

Нажмите **⌘I** (Ctrl+I в Windows и Linux) и печатайте. Быстрый поиск
находит файлы, действия меню, символы, устройства стойки, работающие
серверы и команды, а также скрипты из вашего `package.json`. Нажмите Ввод,
чтобы открыть или запустить найденное.

Нажмите **⌘P**, чтобы открыть файл по имени.

<a id="5-test-it-thirty-seconds"></a>
## 5. Проверьте его тестами (тридцать секунд)

Нажмите **⌃F6** (Ctrl+F6), чтобы запустить тесты проекта. Чтобы увидеть все
тесты проекта ещё до запуска, откройте окно **Тесты** сочетанием ⌥⌘2.

<a id="if-you-have-no-project-handy"></a>
## Если проекта под рукой нет

- **Файл ▸ Новый проект…** создаёт настоящий проект по шаблону (Angular,
  Vue, Svelte, React на Vite, чистый JavaScript, PHP, Phoenix и другие).
  Он создаёт файлы, настраивает git и устанавливает зависимости.
- **Файл ▸ Новое учебное пространство…** открывает урок с проводником.
  *Ваша первая веб-страница* стоит в списке первой.

<a id="where-to-go-next"></a>
## Куда дальше

- **[Стойка задач](user-guide.ru.md#4-the-task-rack)**. Каждый
  инструмент, который вы запускаете, — это устройство в стойке, а кабели
  между устройствами связывают их в цепочки: например, запускать тесты
  всякий раз, когда проходит сборка.
- **[Редактор](user-guide.ru.md#5-the-editor)**. Emmet, образцы цветов,
  отладка с точками останова для Node и Chrome, шаблоны Angular.
- **[Студии](user-guide.ru.md#6-the-studios)**. Студии API, баз данных,
  контрактов и блоков, а также Доска задач.
- **[Глоссарий](glossary.ru.md)** объясняет собственные слова продукта:
  стойка, патч, гнездо, дорожка, нацеливание, KVASIR.
