Слова, которые NMOX Studio использует, а другая IDE — нет, плюс термины
NetBeans, которые проступают наружу. Каждая статья говорит, что слово
значит здесь и где прочитать больше.

<a id="the-rack"></a>
## Стойка

**Стойка задач** (Task Rack, ⌘9) — Окно, в котором работают ваши инструменты. Каждая задача (установка, сборка, тесты, сервер, линтер, развёртывание) — это *устройство*, установленное в стойку, как аппаратура в студии звукозаписи.
[Руководство, §4](user-guide.ru.md#4-the-task-rack).

**Устройство** (device) — Один инструмент в стойке, например VELOCITY (Vite), VERITAS (тесты) или
PURITY (линтер). Руководство называет их также приборами. У устройства есть передняя панель (*лицевая панель*) с ручками,
кнопками, лампочками и небольшим экраном и задняя панель с *гнёздами*.
Встроенных устройств 53, их список — в [справочнике устройств](devices.md).
Можно добавить и своё — файлом JSON в `~/.nmox/devices.d/`
([файлы устройств](device-files.md)).

**Лицевая панель** (faceplate) — Передняя панель устройства. Нажмите **Tab** в стойке, чтобы развернуть её и увидеть
заднюю панель.

**Гнездо** (jack) — Разъём на задней панели устройства. Выходные гнёзда посылают сигналы, входные их
принимают. Сигналы бывают трёх видов:
- **Триггер** — один импульс: «сборка закончилась», «OK», «FAIL».
- **Затвор** (gate) остаётся включённым или выключенным: «сервер работает».
- **Данные** несут текст, например URL или строку вывода.

**Кабель** (cable) — Соединение выходного гнезда с входным. Подключите гнездо OK сборки ко
входу RUN запускателя тестов — и тесты будут запускаться всякий раз, когда
сборка проходит. Чтобы соединить два гнезда, протяните от одного к другому
или щёлкните по одному, а затем по другому.

**Патч** (patch) — Вся стойка целиком: её устройства, их настройки и кабели. Сохраняется рядом
с проектом как `.nmoxrack.json`, так что его стоит класть в репозиторий.

**Пресет** (preset) — Готовый патч, который загружается из меню **Пресеты** стойки, например
*Ship Gate* или *E2E Loop*. Сохраните любой патч в `~/.nmox/presets.d/` —
и он тоже появится в меню.

**Стартовая стойка** (starter rack) — Патч, который проект получает при первом открытии, выбранный по
виду проекта: консоль Vite для приложения на Vite, дорожки запуска, отладки
и тестов для крейта Cargo, и так далее.

**Дорожка** (lane) — Два значения, оба про запуск:
- **Конвейер**: цепочка устройств, соединённых кабелями, например установка →
  сборка → тесты. Несколько дорожек могут идти бок о бок, а QUORUM ждёт,
  пока закончатся все.
- **Дорожка AUTO** устройства: команда, которую оно выбирает для этого
  проекта. В положении AUTO устройство тестов запускает `npm test` в
  проекте Node и `cargo test` в проекте Rust.

**Поделиться… / Импорт…** (Share… / Import…) — Сохранить стойку в файл для кого-то ещё или загрузить стойку, которую прислали вам. Прежде
чем что-либо установится, «Импорт» показывает всё, что есть в файле, и
каждое устройство приходит выключенным.

**Галерея стоек** (Rack Gallery) — **Сервис ▸ Галерея стоек…** перечисляет стойки сообщества, пресеты, стартовые стойки
и ваши сохранённые стойки. У каждой видно, для чего она и какие
инструменты ей нужны. [Стойки сообщества](racks.md).

<a id="projects-and-running"></a>
## Проекты и запуск

**Нацеливание** / **нацеленный проект** (aim) — Проект, с которым IDE сейчас работает. Открыть проект значит нацелить
на него IDE: стойка, студии, строка состояния и запуск следуют за
нацеленным проектом. Нацелить другой — значит переключить их все, а всё,
что ещё работает, сначала останавливается, после вопроса.

**Доверие рабочей области** (Workspace Trust) — Вопрос, который NMOX Studio задаёт, прежде чем впервые запустить собственный
код проекта (скрипты, сборки, тесты). Если вы ответите
**Оставить в безопасности**, из проекта не запустится ничего; **Доверять рабочей области** разрешает запуск. Ответ запоминается
для каждой папки.

**▶ и ■** — Запуск и остановка на панели инструментов. ▶ (F6) запускает нацеленный проект. ■ (⌥⌘.)
останавливает все команды, которые NMOX Studio запустила для вас.

**Значок ⇄** / **обслуживание** (serving) — Когда то, что вы запустили, печатает локальный адрес, например
`http://localhost:5173/`, адрес появляется в строке состояния после
значка ⇄. Такой работающий сервер и есть *обслуживание*. Щёлкните адрес,
чтобы открыть его в Браузере. Быстрый поиск перечисляет их под заголовком
*Активные серверы*.

**Эксперимент** (experiment) — Одноразовый проект из шаблона в `~/.nmox/experiments`. Его
зависимости уже установлены, и ему уже доверяют. **Повысить** — чтобы
оставить, **Удалить** — чтобы убрать. **Файл ▸ Новый эксперимент…**.

**Учебное пространство** (learning space) — Урок с проводником по языку или каркасу. Он создаёт настоящий
проект, пошаговое описание и стойку с живым REPL, а
**Файл ▸ Проверить мою работу** проверяет ваши упражнения. Их 93.
**Файл ▸ Новое учебное пространство…**.

**PREFLIGHT** — Устройство проверки перед отправкой. Оно запускает проверки, которые определяет ваш проект (линтер,
типы, тесты, сборка), одним проходом с итогом «прошло» или «не прошло».

**Первые шаги** (First Steps) — Список на вкладке «Добро пожаловать». Шаги отмечаются сами, когда вы их
выполняете, и отметка уже не снимается.

<a id="the-windows"></a>
## Окна

**Студия** (studio) — Окно со своим инструментом для одного вида работы. Их
пять: **Студия API** (⌥⌘8), **Студия баз данных** (⌥⌘7), **Студия контрактов** (⌥⌘6,
смарт-контракты), **Студия блоков** (⌥⌘5, веб-компоненты из блоков)
и **Конструктор инфраструктуры** (⌥⌘9, облачная инфраструктура). Каждая хранит свою работу
рядом с проектом в файле `.nmox*.json`. **Студия проекта** носит похожее
имя, но это дерево файлов и шаблоны проектов.

**Рабочее место** (Workbench, ⌥⌘0) — Домашняя база: что работает, что открыто, а также недавние проекты и
файлы.

**Доска задач** (Task Board, ⌥⌘1) — Канбан-доска для каждого проекта, со спринтами и учётом времени, сохраняется как
`.nmoxtasks.json`.

**Добро пожаловать** (Welcome) — Стартовая вкладка: действия, с которых можно начать, недавние проекты, столбец
*ИНСТРУМЕНТЫ*, где перечислено каждое окно, и «Первые шаги».

<a id="ai"></a>
## ИИ

**KVASIR** — Имя ИИ-возможностей NMOX Studio: спросить, изменить, дополнить, объяснить,
составить сообщение коммита. Работает с Claude, ChatGPT или Gemini на вашем
собственном ключе API, который хранится в связке ключей системы. Каждая
возможность один раз спрашивает согласия и прямо называет, что отправит.
Ничего не отправляется, пока вы не воспользуетесь возможностью. В ранних
выпусках он назывался ORACLE.

**Agent Port** — **Сервис ▸ Agent Port (MCP)…** даёт ИИ-агенту, работающему на вашей
машине, например помощнику по программированию, доступ только для чтения к состоянию IDE
через MCP: открытые файлы, диагностика, запуски, символы. Он только для чтения
по построению и слушает только вашу собственную машину.
[Учебник](tutorials/agent-port.md).

<a id="netbeans-terms-you-may-see"></a>
## Термины NetBeans, которые вы можете встретить

NMOX Studio построена на платформе NetBeans, и некоторые её слова
проступают наружу.

**Модуль** / **NBM** (module) — Часть приложения. *NBM* — это файл, в котором модуль поставляется.
**Сервис ▸ Плагины** устанавливает обновления модуль за модулем.

**Центр обновлений** (update center) — Откуда **Сервис ▸ Плагины ▸ Обновления** берёт новые версии модулей
NMOX Studio. Он читает каталог, публикуемый с каждым выпуском на GitHub.

**userdir** — Папка, где NMOX Studio хранит настройки, расположение окон, журналы и
установленные обновления. Где она, показывает окно «О программе» (оно в меню
Справка в Windows и Linux, в меню NMOX Studio в macOS). Журнал лежит в
`var/log/messages.log`. Чтобы начать с чистыми настройками, запустите с
`--userdir <пустая папка>`.

**Настройки** (Options / Settings…) — Диалог параметров. В Windows и Linux это **Сервис ▸ Настройки**,
а в macOS — **NMOX Studio ▸ Settings…**.

**Задачи** (Action Items) — Окно со списком проблем, найденных в проекте: ошибки и предупреждения
языковых серверов, а также результаты линтера и проверки типов из стойки. Щёлкните проблему,
чтобы перейти к этой строке.
