आपके हाथ पहले से जानते हैं कि चीज़ें कहाँ हैं। यह पन्ना उन आदतों से NMOX Studio तक का नक्शा है: पहले कुंजी-संयोजन, फिर यह कि VS Code का हर विचार यहाँ कहाँ रहता है, और फिर वह जो ईमानदारी से अलग है।

VS Code उपयोगकर्ता जो पहले चार संयोजन दबाता है, वे वही करते हैं जिसकी वह अपेक्षा करता है: **⇧⌘P** कमांड पैलेट खोलता है, **⇧⌘E** फ़ाइल वृक्ष, **⇧⌘X** प्लगिन, और **⌃\`** टर्मिनल। ये मंच के साथ आने वाली पाँचों कीमैप प्रोफ़ाइलों में दर्ज हैं, और एक बिल्ड-द्वार हर एक को macOS, Windows और Linux पर संयोजित कीमैप के ज़रिए हल करता है, ताकि उसकी जगह कुछ और न चल जाए।

<a id="the-chords"></a>
## कुंजी-संयोजन

macOS वाले स्तंभ मेनू-पट्टी के चिह्न इस्तेमाल करते हैं (⌃ Control, ⌥ Option, ⇧ Shift, ⌘ Command); Windows और Linux वाले स्तंभ PC कीबोर्ड पर वही संयोजन हैं।

| आप चाहते हैं | VS Code, macOS | NMOX, macOS | VS Code, Win/Linux | NMOX, Win/Linux |
|---|---|---|---|---|
| कमांड पैलेट | ⇧⌘P | **⇧⌘P** (या ⌘I) — त्वरित खोज | Ctrl+Shift+P | **Ctrl+Shift+P** (या Ctrl+I) |
| नाम से कोई फ़ाइल खोलना | ⌘P | **⌘P** — फ़ाइल पर जाएँ | Ctrl+P | **Ctrl+P** |
| फ़ाइल वृक्ष | ⇧⌘E | **⇧⌘E** — प्रोजेक्ट स्टूडियो | Ctrl+Shift+E | **Ctrl+Shift+E** |
| एक्सटेंशन | ⇧⌘X | **⇧⌘X** — उपकरण ▸ प्लगिन | Ctrl+Shift+X | **Ctrl+Shift+X** |
| प्रोजेक्ट फ़ोल्डर में टर्मिनल | ⌃\` | **⌃\`** | Ctrl+\` | **Ctrl+\`** |
| हाल का कोई प्रोजेक्ट खोलना | ⌃R | **⌥⌘P** — प्रोजेक्ट बदलें… | Ctrl+R | **Ctrl+Alt+P** |
| प्रोजेक्ट में किसी प्रतीक पर जाना | ⌘T | **⌥⇧⌘O** | Ctrl+T | **Ctrl+Alt+Shift+O** |
| परिभाषा पर जाना | F12 | **⌘B** | F12 | **Ctrl+B** |
| किसी प्रतीक का नाम बदलना | F2 | **⌃R** | F2 | **Ctrl+R** |
| किसी पंक्ति पर जाना | ⌃G | **⌃G** | Ctrl+G | **Ctrl+G** |
| पंक्ति-टिप्पणी चालू/बंद | ⌘/ | **⌘/** | Ctrl+/ | **Ctrl+/** |
| सुझाव दिखाना | ⌃Space | **⌃Space** | Ctrl+Space | **Ctrl+Space** |
| अगली घटना को चयन में जोड़ना | ⌘D | **⌘J** | Ctrl+D | **Ctrl+J** |
| हर घटना चुनना | ⇧⌘L | **⌃⇧⌘J** | Ctrl+Shift+L | **Ctrl+Alt+Shift+J** |
| ऊपर / नीचे एक कर्सर जोड़ना | ⌥⌘↑ / ⌥⌘↓ | **⌥⌘↑ / ⌥⌘↓** | Ctrl+Alt+↑ / ↓ | **Alt+Shift+[ / ]** |
| पंक्ति ऊपर / नीचे ले जाना | ⌥↑ / ⌥↓ | **⌃⇧↑ / ⌃⇧↓** | Alt+↑ / ↓ | **Alt+Shift+↑ / ↓** |
| पंक्ति नीचे कॉपी करना | ⇧⌥↓ | **⌥⇧↓** | Shift+Alt+↓ | **Ctrl+Shift+↓** |
| पंक्ति हटाना | ⇧⌘K | **⌘E** | Ctrl+Shift+K | **Ctrl+E** |
| दस्तावेज़ को फ़ॉर्मैट करना | ⇧⌥F | **⌃⇧F** | Shift+Alt+F | **Alt+Shift+F** |
| संपादक टैब बंद करना | ⌘W | **⌘W** | Ctrl+W | **Ctrl+W** |
| समस्याओं का पैनल | ⇧⌘M | **⌘6** — कार्य आइटम (यहाँ ⇧⌘M बुकमार्क लगाता या हटाता है) | Ctrl+Shift+M | **Ctrl+6** |
| ब्रेकपॉइंट लगाना या हटाना | F9 | **⌘F8** | F9 | **Ctrl+F8** |
| डिबगिंग शुरू करना | F5 | **⇧⌘F5** — फ़ाइल डिबग करें | F5 | **Ctrl+Shift+F5** |
| बिना डिबगिंग के चलाना | ⌃F5 | **F6** — प्रोजेक्ट चलाएँ | Ctrl+F5 | **F6** |
| सेटिंग | ⌘, | **⌘,** — NMOX Studio ▸ Settings… | Ctrl+, | उपकरण ▸ विकल्प (कोई संयोजन नहीं) |

तालिका का हर NMOX संयोजन शिप हुए कीमैप से पढ़ा गया है, याद से नहीं लिखा गया (⌘, macOS के ऐप मेनू का अपना है)। कुछ बातें जो तालिका का कोई ख़ाना नहीं कह सकता:

- **डिबगिंग के दौरान F5 व्यस्त रहता है।** यहाँ इसका अर्थ *जारी रखें* है, जैसा NetBeans परिवार के हर IDE में होता है, इसलिए डिबग रन **⇧⌘F5** (Ctrl+Shift+F5) से शुरू होता है और F5 से आगे बढ़ता है।
- **यहाँ ⌃R नाम बदलना है**, इसीलिए *प्रोजेक्ट बदलें* VS Code के Open Recent वाले संयोजन की जगह ⌥⌘P पर रहता है। नाम बदलना वहाँ काम करता है जहाँ फ़ाइल के पीछे की भाषा उसका समर्थन करती है।
- **Windows और Linux पर Ctrl+,** आपके संपादन-इतिहास में पीछे ले जाता है, जैसा NetBeans में हमेशा से होता है; सेटिंग उपकरण ▸ विकल्प में रहती हैं (macOS पर ऐप मेनू का **Settings…**, ⌘,)।

**सहायता ▸ कीबोर्ड शॉर्टकट…** आपकी सक्रिय कीमैप का हर NMOX संयोजन गिनाता है, चारों VS Code संयोजनों समेत, चलती हुई कीमैप से पढ़कर, इसलिए वह कुंजियों के असली काम से अलग नहीं हो सकता।

<a id="from-the-terminal"></a>
## टर्मिनल से

`code .` यहाँ `nmox .` है:

```bash
cd ~/code/my-app
nmox .          # open this folder (manifest or not) and aim the IDE at it
nmox src/app.ts # open one file
nmox            # just start the IDE
```

यह तुरंत लौट आता है, और दूसरा `nmox` अपना फ़ोल्डर पहले से चल रहे IDE को सौंप देता है। Homebrew, Windows संस्थापक (*Add "nmox" to PATH*) और Linux पैकेज इसे आपके PATH पर रख देते हैं; DMG से संस्थापन हो तो [उपयोगकर्ता मार्गदर्शिका](user-guide.hi.md#2-first-launch) एक पंक्ति वाला लिंक दिखाती है।

<a id="where-each-vs-code-idea-lives"></a>
## VS Code का हर विचार कहाँ रहता है

| VS Code में | NMOX Studio में |
|---|---|
| **Explorer** | **प्रोजेक्ट स्टूडियो** (⇧⌘E) — फ़ाइल वृक्ष, टेम्पलेट, और प्रोजेक्ट का `package.json` संपादक। **वर्कबेंच** (⌥⌘0) घर का ठिकाना है: खुली फ़ाइलें, हाल की फ़ाइलें, हाल के प्रोजेक्ट, और जो कुछ भी चल रहा है। |
| **Command Palette** | **त्वरित खोज** (⇧⌘P या ⌘I) — क्रियाएँ, फ़ाइलें, हाल के प्रोजेक्ट, रैक डिवाइस, लाइव सर्वर, API स्टूडियो के अनुरोध, प्रतीक। |
| **Extensions** | **उपकरण ▸ प्लगिन** मॉड्यूल संस्थापित और अपडेट करता है, NMOX के अपने अपडेट भी। VS Code में जो कुछ कोई एक्सटेंशन जोड़ता है, उसमें से बहुत कुछ यहाँ एक **रैक डिवाइस** है — और आप `~/.nmox/devices.d` में एक JSON फ़ाइल के रूप में अपना डिवाइस लिख सकते हैं ([device files](device-files.md))। |
| **`tasks.json`** | आपके प्रोजेक्ट की अपनी स्क्रिप्टें, वैसे ही चलाई जाती हैं जैसे लिखी गई हैं: टूलबार का चलाएँ / बिल्ड / टेस्ट (F6, F11, ⌃F6), `package.json` की किसी scripts पंक्ति पर **स्क्रिप्ट चलाएँ**, **NPM एक्सप्लोरर**, और **टास्क रैक** (⌘9), जहाँ कार्य ऐसे डिवाइस हैं जिन्हें आप आपस में जोड़ते हैं। |
| **`launch.json`** | **फ़ाइल डिबग करें** (⇧⌘F5) और टूलबार का डिबग बटन ख़ुद प्रोजेक्ट से तय करते हैं कि क्या चलाना है — `start` स्क्रिप्ट का प्रवेश-बिंदु, `main`, `index.js` — और **INSPECTOR** रैक डिवाइस किसी पाइपलाइन के एक क़दम के रूप में डिबगर शुरू करता है। |
| **Integrated terminal** | **टर्मिनल** विंडो (⌃\`): पहला दबाव प्रोजेक्ट फ़ोल्डर में एक शेल शुरू करता है, बाद के दबाव उसे वापस ले आते हैं। |
| **`settings.json`** | उपकरण ▸ विकल्प (macOS पर NMOX Studio ▸ Settings…)। आपके प्रोजेक्ट की `.editorconfig` का सहेजते समय पालन होता है। |
| **Problems panel** | **कार्य आइटम** (⌘6): रैक के PURITY और TYPEGUARD डिवाइसों से मिली लिंट और टाइप की समस्याएँ, संपादक की लहरदार रेखाओं के साथ। |
| **Outline** | **नेविगेटर** (⌘7)। |
| **Source Control** | स्थिति-पट्टी पर git चिह्न (शाखा और बदलाव, एक क्लिक में इतिहास) और **टीम** मेनू। |
| **Workspace Trust** | वही विचार, और रिपॉज़िटरी का चुना हुआ कुछ भी चलने से पहले लागू होता है: किसी क्लोन किए गए प्रोजेक्ट को खोलने पर तब तक कुछ नहीं चलता जब तक आप उस पर भरोसा न करें। |
| **Keyboard Shortcuts editor** | उपकरण ▸ विकल्प ▸ कीमैप (macOS पर Settings… ▸ कीमैप) — कोई भी संयोजन बदलिए, या पूरी प्रोफ़ाइल Eclipse, Emacs या IntelliJ पर कर दीजिए। |

<a id="what-is-honestly-different"></a>
## जो ईमानदारी से अलग है

- **यहाँ ⌘D बहु-कर्सर नहीं है।** वही काम **⌘J** (Ctrl+J) करता है; ⌘D ख़ुद किसी काम से बँधा नहीं है। अगर आपकी उँगलियाँ ज़िद करें तो उसे कीमैप में बाँध लीजिए।
- **⌃\` टर्मिनल को खोलता है और उस पर फ़ोकस करता है; उसे छिपाता नहीं।** और जब तक टर्मिनल पर फ़ोकस है, कुंजियाँ आपके शेल की हैं, इसलिए दूसरा दबाव आपको संपादक पर लौटाने के बजाय शेल तक पहुँचता है।
- **`.vscode/tasks.json` और `launch.json` पढ़े नहीं जाते।** कोई कार्य एक ऐसा आदेश है जिसे रिपॉज़िटरी ने चुना है, और उसे पढ़ने के लिए वर्कस्पेस ट्रस्ट के इर्द-गिर्द अपनी एक रचना चाहिए; तब तक प्रोजेक्ट की अपनी स्क्रिप्टें और ऊपर के डिबग-प्रवेश नियम यह काम करते हैं।
- **कोई "VS Code" कीमैप प्रोफ़ाइल नहीं है।** ऊपर के संयोजन डिफ़ॉल्ट प्रोफ़ाइल और बाकी चारों में दर्ज हैं। एक जान-बूझकर अपवाद: **Eclipse** प्रोफ़ाइल में ⇧⌘E Eclipse का अपना *Switch to Editor* ही रहता है, और संपादक के भीतर ⇧⌘P और ⇧⌘X Eclipse के अर्थ रखते हैं (मेल खाता कोष्ठक, बड़े अक्षर) — जिसने Eclipse चुना वह Eclipse की अपेक्षा करता है।
- **Linux पर Ctrl+\` पहले विंडो-स्विचर खोलता था** — उन डेस्कटॉप (KDE) के लिए मंच का विकल्प जो Ctrl+Tab पकड़ लेते हैं। अब यह टर्मिनल खोलता है; स्विचर अब भी Ctrl+Tab पर है।
- **Ctrl+Alt वाले संयोजन AltGr से टकरा सकते हैं।** Windows पर जो कीबोर्ड लेआउट AltGr से अक्षर टाइप करते हैं (जैसे पोलिश), वे उसके लिए Ctrl+Alt भेजते हैं। अगर Ctrl+Alt+P या Ctrl+Alt+K आपके लिए कोई अक्षर टाइप करता है, तो *प्रोजेक्ट बदलें* या प्रयोग वाले संयोजनों को कीमैप में कहीं और ले जाइए।
- **VS Code के एक्सटेंशन यहाँ संस्थापित नहीं होते।** भाषा की समझ उन भाषा-सर्वरों से आती है जिन्हें NMOX जानता है (परिवेश डॉक्टर बताता है कि क्या ग़ायब है और उसे कैसे संस्थापित करें), संपादक के अपने व्याकरणों से, और NetBeans Platform के लिए बने प्लगिन से।
