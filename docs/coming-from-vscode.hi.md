आपके हाथ पहले से जानते हैं कि चीज़ें कहाँ हैं। यह पन्ना उन आदतों से NMOX Studio तक का नक्शा है: पहले कुंजी-संयोजन, फिर यह कि VS Code का हर विचार यहाँ कहाँ रहता है, और फिर वह जो ईमानदारी से अलग है।

VS Code उपयोगकर्ता जो पहले चार संयोजन दबाता है, वे वही करते हैं जिसकी वह अपेक्षा करता है: **⇧⌘P** कमांड पैलेट खोलता है, **⇧⌘E** फ़ाइल वृक्ष, **⇧⌘X** प्लगिन, और **⌃\`** टर्मिनल। ये मंच के साथ आने वाली पाँचों कीमैप प्रोफ़ाइलों में दर्ज हैं, और एक बिल्ड-द्वार हर एक को macOS, Windows और Linux पर संयोजित कीमैप के ज़रिए हल करता है, ताकि उसकी जगह कुछ और न चल जाए।

<a id="the-chords"></a>
## कुंजी-संयोजन

macOS वाले स्तंभ मेनू-पट्टी के चिह्न इस्तेमाल करते हैं (⌃ Control, ⌥ Option, ⇧ Shift, ⌘ Command); Windows और Linux वाले स्तंभ PC कीबोर्ड पर वही संयोजन हैं।

| आप चाहते हैं | VS Code, macOS | NMOX, macOS | VS Code, Win/Linux | NMOX, Win/Linux |
|---|---|---|---|---|
| कमांड पैलेट | ⇧⌘P | **⇧⌘P** (या ⌘I) — त्वरित खोज | Ctrl+Shift+P | **Ctrl+Shift+P** (या Ctrl+I) |
| नाम से कोई फ़ाइल खोलना | ⌘P | **⌘P** — फ़ाइल पर जाएँ | Ctrl+P | **Ctrl+P** |
| फ़ाइल वृक्ष | ⇧⌘E | **⇧⌘E** — प्रोजेक्ट स्टूडियो | Ctrl+Shift+E | **Ctrl+Shift+E** |
| एक्सटेंशन | ⇧⌘X | **⇧⌘X** — उपकरण ▸ प्लगिन | Ctrl+Shift+X | **Ctrl+Shift+X** |
| प्रोजेक्ट फ़ोल्डर में टर्मिनल | ⌃\` | **⌃\`** | Ctrl+\` | **Ctrl+\`** |
| हाल का कोई प्रोजेक्ट खोलना | ⌃R | **⌥⌘P** — प्रोजेक्ट बदलें… | Ctrl+R | **Ctrl+Alt+P** |
| प्रोजेक्ट में किसी प्रतीक पर जाना | ⌘T | **⌥⇧⌘O** | Ctrl+T | **Ctrl+Alt+Shift+O** |
| परिभाषा पर जाना | F12 | **F12** या ⌘B | F12 | **F12** या Ctrl+B |
| संदर्भ खोजना | ⇧F12 | **⇧F12** — उपयोग खोजें | Shift+F12 | **Shift+F12** |
| किसी प्रतीक का नाम बदलना | F2 | **F2** या ⌃R | F2 | **F2** या Ctrl+R |
| त्वरित सुधार | ⌘. | **⌘.** या ⌃↩ | Ctrl+. | **Alt+Enter** |
| किसी पंक्ति पर जाना | ⌃G | **⌃G** | Ctrl+G | **Ctrl+G** |
| पीछे / आगे जाना | ⌃- / ⌃⇧- | **⌃- / ⌃⇧-** | Alt+← / Alt+→ | **Alt+← / Alt+→** |
| पंक्ति-टिप्पणी चालू/बंद | ⌘/ | **⌘/** | Ctrl+/ | **Ctrl+/** |
| सुझाव दिखाना | ⌃Space | **⌃Space** | Ctrl+Space | **Ctrl+Space** |
| अगली घटना को चयन में जोड़ना | ⌘D | **⌘D** या ⌘J | Ctrl+D | **Ctrl+D** या Ctrl+J |
| हर घटना चुनना | ⇧⌘L | **⌃⇧⌘J** | Ctrl+Shift+L | **Ctrl+Alt+Shift+J** |
| ऊपर / नीचे एक कर्सर जोड़ना | ⌥⌘↑ / ⌥⌘↓ | **⌥⌘↑ / ⌥⌘↓** | Ctrl+Alt+↑ / ↓ | **Alt+Shift+[ / ]** |
| पंक्ति ऊपर / नीचे ले जाना | ⌥↑ / ⌥↓ | **⌃⇧↑ / ⌃⇧↓** | Alt+↑ / ↓ | **Alt+Shift+↑ / ↓** |
| पंक्ति नीचे कॉपी करना | ⇧⌥↓ | **⌥⇧↓** | Shift+Alt+↓ | **Ctrl+Shift+↓** |
| पंक्ति हटाना | ⇧⌘K | **⌘E** | Ctrl+Shift+K | **Ctrl+E** |
| पंक्ति को इंडेंट करना | ⌘] | **⌘]** | Ctrl+] | **Alt+Shift+→** |

| संपादक टैब बंद करना | ⌘W | **⌘W** | Ctrl+W | **Ctrl+W** |

| उसका सापेक्ष पथ कॉपी करना | ⇧⌥⌘C | संपादन ▸ सापेक्ष पथ कॉपी करें (कोई संयोजन नहीं) | Ctrl+K Ctrl+Shift+Alt+C | संपादन ▸ सापेक्ष पथ कॉपी करें (कोई संयोजन नहीं) |
| समस्याओं का पैनल | ⇧⌘M | **⌘6** — कार्य आइटम (यहाँ ⇧⌘M बुकमार्क लगाता या हटाता है) | Ctrl+Shift+M | **Ctrl+6** |
| ब्रेकपॉइंट लगाना या हटाना | F9 | **⌘F8** | F9 | **Ctrl+F8** |
| डिबगिंग शुरू करना | F5 | **⇧⌘F5** — फ़ाइल डिबग करें | F5 | **Ctrl+Shift+F5** |
| बिना डिबगिंग के चलाना | ⌃F5 | **F6** — प्रोजेक्ट चलाएँ | Ctrl+F5 | **F6** |
| सेटिंग | ⌘, | **⌘,** — NMOX Studio ▸ Settings… | Ctrl+, | उपकरण ▸ विकल्प (कोई संयोजन नहीं) |

तालिका का हर NMOX संयोजन शिप हुए कीमैप से पढ़ा गया है, याद से नहीं लिखा गया (⌘, macOS के ऐप मेनू का अपना है)। कुछ बातें जो तालिका का कोई ख़ाना नहीं कह सकता:

- **डिबगिंग के दौरान F5 व्यस्त रहता है।** यहाँ इसका अर्थ *जारी रखें* है, जैसा NetBeans परिवार के हर IDE में होता है, इसलिए डिबग रन **⇧⌘F5** (Ctrl+Shift+F5) से शुरू होता है और F5 से आगे बढ़ता है।
- **यहाँ ⌃R नाम बदलना है**, इसीलिए *प्रोजेक्ट बदलें* VS Code के Open Recent वाले संयोजन की जगह ⌥⌘P पर रहता है। नाम बदलना वहाँ काम करता है जहाँ फ़ाइल के पीछे की भाषा उसका समर्थन करती है।
- **सापेक्ष पथ कॉपी करें का कोई संयोजन नहीं है।** VS Code का ⇧⌥⌘C PC पर Ctrl+Alt+Shift+C है, जो हर कीमैप प्रोफ़ाइल में प्लेटफ़ॉर्म का *Clear Split* है; यह पंक्ति संपादन मेनू में है, और ⇧⌘P इसे VS Code के अपने शीर्षक *File: Copy Relative Path of Active File* से ढूँढ़ लेता है।
- **Windows और Linux पर Ctrl+,** आपके संपादन-इतिहास में पीछे ले जाता है, जैसा NetBeans में हमेशा से होता है; सेटिंग उपकरण ▸ विकल्प में रहती हैं (macOS पर ऐप मेनू का **Settings…**, ⌘,)।

**सहायता ▸ कीबोर्ड शॉर्टकट…** आपकी सक्रिय कीमैप का हर NMOX संयोजन गिनाता है, चारों VS Code संयोजनों समेत, चलती हुई कीमैप से पढ़कर, इसलिए वह कुंजियों के असली काम से अलग नहीं हो सकता।

### संपादन का हर संयोजन, मापा हुआ

VS Code के आदी आपके हाथ संपादन करते समय जिन संयोजनों की ओर जाते हैं, उनमें से हर एक को macOS पर डिफ़ॉल्ट प्रोफ़ाइल की भेजी गई कीमैप में देखा गया। जहाँ VS Code का संयोजन यहाँ खाली था, वहाँ अब वह वही करता है जो VS Code करता है (जिन पंक्तियों में **वही:** लिखा है); जहाँ उसका पहले से कोई ऐसा मतलब था जिस पर NetBeans के उपयोगकर्ता निर्भर हैं, वहाँ वह मतलब बना रहता है और पंक्ति बताती है कि VS Code की वह क्रिया कहाँ है।

| VS Code, macOS | VS Code क्या करता है | NMOX Studio में |
|---|---|---|
| F12 | Go to Definition | **वही:** घोषणा पर जाएँ, जैसे ⌘B करता है |
| ⇧F12 | Go to References | **वही:** उपयोग खोजें, जैसे ⌃F7 करता है |
| F2 | Rename Symbol | **वही:** नाम बदलें, जैसे ⌃R करता है |
| ⌘. | Quick Fix | **वही:** पंक्ति के सुधार, जैसे ⌃↩ उन्हें दिखाता है |
| ⌥↑ / ⌥↓ | Move Line Up / Down | पिछली / अगली चिह्नित घटना; पंक्ति खिसकाना ⌃⇧↑ / ⌃⇧↓ है |
| ⇧⌥↑ / ⇧⌥↓ | Copy Line Up / Down | वही, जैसा हमेशा से था |
| ⇧⌘K | Delete Line | अगला मिलता-जुलता शब्द डालें (फ़ाइल से शब्द पूरा करता है); पंक्ति हटाना ⌘E है |
| ⌘L | Expand Line Selection | आइडेंटिफ़ायर चुनें; पंक्ति चुनने का कोई संयोजन नहीं है |
| ⇧⌘L | Select All Occurrences | एडिटर में लाइनों के रूप में पेस्ट करें; हर घटना चुनना ⌃⇧⌘J है |
| ⌘/ | Toggle Line Comment | वही, जैसा हमेशा से था |
| ⇧⌥A | Toggle Block Comment | कुछ नहीं: ब्लॉक-टिप्पणी की कोई अलग क्रिया नहीं है, और ⌘/ टिप्पणी चालू/बंद करता है |
| ⌘] | Indent Line | **वही:** दाएँ खिसकाएँ |
| ⌘[ | Outdent Line | मिलते हुए कोष्ठक पर जाना, जैसा हमेशा से था; इंडेंट घटाना ⇧Tab या ⌃⇧← है |
| ⌘B | Toggle Sidebar | घोषणा पर जाएँ; ⇧⌘↩ सिर्फ़ एडिटर दिखाता है, ⇧Esc उस विंडो को बड़ा करता है जिसमें आप हैं |
| ⌘J | Toggle Panel | एडिटर में अगली घटना जोड़ता है (जैसे ⌘D); **Output** विंडो ⌘4 है |
| ⌘\ | Split Editor | एडिटर में कोड पूरा करें; एडिटर को बाँटना ⌃⇧⌘V है |
| ⇧⌘T | Reopen Closed Editor | वही, जैसा हमेशा से था: हाल की फ़ाइल खोलें का संयोजन आख़िरी बंद की गई फ़ाइल को फिर से खोलता है |
| ⌃- / ⌃⇧- | Go Back / Go Forward | **वही:** जहाँ-जहाँ आपने संपादन किया, उनके बीच पीछे और आगे, जैसे ⌃← / ⌃→ (ऐसे संयोजन जिन्हें macOS आम तौर पर डेस्कटॉप बदलने के लिए रखता है) |
| ⌘G / ⇧⌘G | Find Next / Previous | वही, जैसा हमेशा से था |
| ⌥⌘F | Replace | **वही:** बदलें, जैसे ⌘R करता है |
| ⇧⌘F | Find in Files | वही, जैसा हमेशा से था: प्रोजेक्ट में खोजें |
| ⇧⌘O | Go to Symbol in Editor | प्रोजेक्ट खोलें; फ़ाइल के सिंबल नेविगेटर (⌘7) में हैं |
| ⌘T | Go to Symbol in Workspace | एडिटर में कर्सर के दोनों ओर के दो अक्षरों की जगह बदलता है; प्रोजेक्ट के सिंबल ⌥⇧⌘O हैं |
| ⌃G | Go to Line | वही, जैसा हमेशा से था |
| ⌘K ⌘S | Keyboard Shortcuts | ⌘K पिछला मिलता-जुलता शब्द डालें है; सूची **सहायता ▸ कीबोर्ड शॉर्टकट…** है |
| ⌘, | Settings | वही, जैसा हमेशा से था: NMOX Studio ▸ Settings… |
| ⇧⌥F | Format Document | **वही:** फ़ॉर्मैट करें, जैसे ⌃⇧F करता है |

**वही:** वाले संयोजन हर उस कीमैप प्रोफ़ाइल में लगे हैं जो उन्हें खाली छोड़ती है, और जो प्रोफ़ाइल उनमें से किसी को अपना मतलब देती है, वह उसे बनाए रखती है: Eclipse, Emacs और NetBeans 5.5 प्रोफ़ाइलों में F12, डिफ़ॉल्ट को छोड़कर हर प्रोफ़ाइल में F2, Emacs और NetBeans 5.5 में ⇧F12, Emacs और IntelliJ में ⌃- और ⌃⇧-, IntelliJ में ⇧⌥F। Windows और Linux पर F12, ⇧F12 और F2 इसी तरह काम करते हैं; VS Code के बाक़ी संयोजन वहाँ अलग हैं, और ऊपर की तालिका दोनों देती है।

## टर्मिनल से

`code .` यहाँ `nmox .` है:

```bash
cd ~/code/my-app
nmox .          # open this folder (manifest or not) and aim the IDE at it
nmox src/app.ts # open one file
nmox src/app.ts:42  # open it at line 42 (code -g's form; -g itself is accepted)
nmox            # just start the IDE
```

यह तुरंत लौट आता है, और दूसरा `nmox` अपना फ़ोल्डर पहले से चल रहे IDE को सौंप देता है। स्तंभ (`src/app.ts:42:7`) भी स्वीकार होता है और संपादक पंक्ति की शुरुआत पर खुलता है; जो नाम मौजूद नहीं है, उसे कुछ भी शुरू करने के बजाय टर्मिनल पर ही अस्वीकार कर दिया जाता है। `-r` स्वीकार होता है, `-n` उसी एक विंडो में खोलता है, और `-a` तथा `-v` नाम लेकर अस्वीकार किए जाते हैं।

`-w` (`--wait`) एक फ़ाइल खोलता है और तब तक रुकता है जब तक आप उसका टैब बंद न कर दें, और `-d` (`--diff`) दो फ़ाइलों की अगल-बगल तुलना करता है, इसलिए NMOX Studio git का संपादक, difftool और mergetool बन सकता है, ठीक वैसे जैसे `code --wait` बनता है:

```bash
git config --global core.editor "nmox -w"
git config --global diff.tool nmox
git config --global difftool.nmox.cmd 'nmox -w -d "$LOCAL" "$REMOTE"'
git config --global merge.tool nmox
git config --global mergetool.nmox.cmd 'nmox -w "$MERGED"'
git config --global mergetool.nmox.trustExitCode false
```

फिर `git commit` संदेश को IDE में खोलता है; उसे सहेजें और टैब बंद करें, और git आगे बढ़ जाता है। कोई फ़ाइल खुली रहते IDE से बाहर निकलना भी उसे लौटा देता है, जितना सहेजा गया था उसके साथ। इसी तरह `git mergetool` टकराव वाली हर फ़ाइल खोलता है। जहाँ VS Code टकराव के ऊपर *Accept Current Change | Accept Incoming Change | Accept Both Changes* रखता है, वहाँ NMOX Studio दोनों पक्षों को रंग देता है और `<<<<<<<` वाली पंक्ति पर चेतावनी रखता है; हाशिये का बल्ब, या उस पंक्ति पर कर्सर रखकर त्वरित सुधार (Mac पर ⌘., बाक़ी जगह Alt+Enter), वही तीन विकल्प देता है, और हर एक ऐसा संपादन है जिसे पलटा जा सकता है। सहेजें, टैब बंद करें, और git अगली फ़ाइल पर चला जाता है। रंग और तीनों विकल्प टकराव-चिह्नों वाली किसी भी फ़ाइल में मौजूद हैं, `git mergetool` के साथ या उसके बिना। **टीम ▸ NMOX Studio को Git के साथ इस्तेमाल करें…** पहले दिखाता है कि हर एक अभी किस पर सेट है, फिर वही पंक्तियाँ आपके लिए सेट कर देता है। Homebrew, Windows संस्थापक (*Add "nmox" to PATH*) और Linux पैकेज इसे आपके PATH पर रख देते हैं; DMG से संस्थापन हो तो [उपयोगकर्ता मार्गदर्शिका](user-guide.hi.md#2-first-launch) एक पंक्ति वाला लिंक दिखाती है।

<a id="where-each-vs-code-idea-lives"></a>
## VS Code का हर विचार कहाँ रहता है

| VS Code में | NMOX Studio में |
|---|---|
| **Explorer** | **प्रोजेक्ट स्टूडियो** (⇧⌘E) — फ़ाइल वृक्ष (किसी फ़ाइल पर दायाँ-क्लिक करने पर **पथ कॉपी करें**, **सापेक्ष पथ कॉपी करें** और **Finder में दिखाएँ** मिलते हैं), टेम्पलेट, और प्रोजेक्ट का `package.json` संपादक। **वर्कबेंच** (⌥⌘0) घर का ठिकाना है: खुली फ़ाइलें, हाल की फ़ाइलें, हाल के प्रोजेक्ट, और जो कुछ भी चल रहा है। |
| **Command Palette** | **त्वरित खोज** (⇧⌘P या ⌘I) — क्रियाएँ, फ़ाइलें, हाल के प्रोजेक्ट, रैक डिवाइस, लाइव सर्वर, API स्टूडियो के अनुरोध, प्रतीक। VS Code के अपने कमांड-नाम भी काम करते हैं: *Format Document*, *Toggle Terminal*, *Git: Commit* या *Open Settings* लिखने पर **VS Code कमांड** के नीचे वह क्रिया सूची में आती है जो यहाँ वही काम करती है, उसके अपने नाम और संयोजन के साथ। |
| **Extensions** | **उपकरण ▸ प्लगिन** मॉड्यूल संस्थापित और अपडेट करता है, NMOX के अपने अपडेट भी। VS Code में जो कुछ कोई एक्सटेंशन जोड़ता है, उसमें से बहुत कुछ यहाँ एक **रैक डिवाइस** है — और आप `~/.nmox/devices.d` में एक JSON फ़ाइल के रूप में अपना डिवाइस लिख सकते हैं ([device files](device-files.md))। |
| **`tasks.json`** | आपकी रिपॉज़िटरी की `.vscode/tasks.json` पढ़ी जाती है: त्वरित खोज (⇧⌘P या ⌘I) में किसी टास्क का नाम लिखिए, और *टास्क चलाएँ: build — make all* पर Enter उसे चलाता है — जिस प्रोजेक्ट पर आपने भरोसा नहीं किया, उस पर वर्कस्पेस ट्रस्ट पहले पूछता है, आउटपुट **Output** विंडो में आता है और टूलबार का ■ उसे रोकता है। उसके बग़ल में प्रोजेक्ट की अपनी स्क्रिप्टें वैसे ही चलाई जाती हैं जैसे लिखी गई हैं: टूलबार का चलाएँ / बिल्ड / टेस्ट (F6, F11, ⌃F6), `package.json` की किसी scripts पंक्ति पर **स्क्रिप्ट चलाएँ**, **NPM एक्सप्लोरर**, और **टास्क रैक** (⌘9), जहाँ कार्य ऐसे डिवाइस हैं जिन्हें आप आपस में जोड़ते हैं। |
| **`launch.json`** | आपकी रिपॉज़िटरी की `.vscode/launch.json` पढ़ी जाती है: त्वरित खोज (⇧⌘P या ⌘I) में किसी कॉन्फ़िगरेशन का नाम लिखिए, और *डिबग करें: Launch Program — ${workspaceFolder}/server.js* पर Enter उस प्रोग्राम पर ब्रेकपॉइंट डिबगर शुरू करता है, वर्कस्पेस ट्रस्ट के पहले पूछ लेने के बाद। Node (`node`, `pwa-node`) और Python (`python`, `debugpy`) कॉन्फ़िगरेशन अपने `cwd` में, अपने `args` और `env` के साथ, अपना `program` डिबग करते हैं; Chrome (`chrome`, `pwa-chrome`) कॉन्फ़िगरेशन अपने `webRoot` के साथ अपना `url` (या `file`) खोलते हैं। `launch.json` न हो तो **फ़ाइल डिबग करें** (⇧⌘F5) और टूलबार का डिबग बटन ख़ुद प्रोजेक्ट से तय करते हैं कि क्या चलाना है — `start` स्क्रिप्ट का प्रवेश-बिंदु, `main`, `index.js` — और **INSPECTOR** रैक डिवाइस किसी पाइपलाइन के एक क़दम के रूप में डिबगर शुरू करता है। |
| **Integrated terminal** | **टर्मिनल** विंडो (⌃\`): पहला दबाव प्रोजेक्ट फ़ोल्डर में एक शेल शुरू करता है, बाद के दबाव उसे वापस ले आते हैं। |
| **`settings.json`** | उपकरण ▸ विकल्प (macOS पर NMOX Studio ▸ Settings…)। किसी रिपॉज़िटरी की `.vscode/settings.json` भी पढ़ी जाती है: `editor.tabSize`, `editor.insertSpaces` और `editor.indentSize` टाइप करते समय उसका इंडेंटेशन तय करते हैं, `files.trimTrailingWhitespace` और `files.insertFinalNewline` (`true` होने पर) सहेजते समय लागू होते हैं, और `"[typescript]"` जैसा कोई भाषा-खंड अपनी भाषा के लिए इन्हें बदल देता है। अगर रिपॉज़िटरी में `.editorconfig` भी है, तो जिन बातों पर दोनों कुछ कहते हैं उन पर `.editorconfig` की चलती है। |
| **Problems panel** | **कार्य आइटम** (⌘6), या स्थिति-पट्टी पर **✕ ⚠** गिनती पर क्लिक कीजिए: भाषा सर्वरों की त्रुटियाँ और चेतावनियाँ, और रैक के PURITY और TYPEGUARD डिवाइसों से मिली लिंट और टाइप की समस्याएँ। VS Code की तरह, कुछ सर्वर केवल खुली फ़ाइलों के बारे में बताते हैं; gopls पूरे पैकेज के बारे में बताता है। |
| **Search view** (`search.useIgnoreFiles`) | **प्रोजेक्ट में खोजें** (⇧⌘F)। VS Code की तरह, यह वह छोड़ देता है जिसे रिपॉज़िटरी की `.gitignore` फ़ाइलें और `.git/info/exclude` अनदेखा करती हैं, इसलिए जब `.gitignore` उन्हें सूचीबद्ध करती है तो `node_modules` और `dist/` परिणामों से बाहर रहते हैं; रिपॉज़िटरी के बाहर यह `node_modules`, `dist`, `build` और बाकी बिल्ड फ़ोल्डरों को नाम से छोड़ता है। उनमें भी खोजने के लिए इसके डायलॉग में **जनरेट किए स्रोतों में खोजें** पर सही का निशान लगाइए। आपकी वैश्विक git excludes फ़ाइल नहीं पढ़ी जाती। |
| **Outline** | **नेविगेटर** (⌘7)। |
| **Source Control** | स्थिति-पट्टी पर git चिह्न (शाखा और बदलाव, एक क्लिक में इतिहास) और **टीम** मेनू। |
| **Workspace Trust** | वही विचार, और रिपॉज़िटरी का चुना हुआ कुछ भी चलने से पहले लागू होता है: किसी क्लोन किए गए प्रोजेक्ट को खोलने पर तब तक कुछ नहीं चलता जब तक आप उस पर भरोसा न करें। |
| **Keyboard Shortcuts editor** | उपकरण ▸ विकल्प ▸ कीमैप (macOS पर Settings… ▸ कीमैप) — कोई भी संयोजन बदलिए, या पूरी प्रोफ़ाइल Eclipse, Emacs या IntelliJ पर कर दीजिए। |

जब आप पहली बार कोई ऐसी रिपॉज़िटरी खोलते हैं जिसमें `.vscode/tasks.json`, `launch.json` या `settings.json` है, तो एक सूचना बताती है कि क्या मिला और वह कहाँ रहता है; उस पर क्लिक करने से त्वरित खोज खुलती है। यह हर प्रोजेक्ट के लिए एक ही बार कहा जाता है।

<a id="what-is-honestly-different"></a>
## जो ईमानदारी से अलग है

- **⌘D डिफ़ॉल्ट कीमैप में अगली घटना जोड़ता है, हर प्रोफ़ाइल में नहीं।** Eclipse प्रोफ़ाइल ⌘D को Eclipse का *Delete Line* ही रखती है, NetBeans 5.5 प्रोफ़ाइल *Shift Line Left* और Emacs प्रोफ़ाइल *kill word* (और Windows और Linux पर Ctrl+D को *delete character*); IntelliJ प्रोफ़ाइल में macOS पर ⌘D है, और Windows और Linux पर वह Ctrl+D को *Duplicate Line* ही रखती है। इस काम का दूसरा संयोजन भी प्रोफ़ाइल के हिसाब से बदलता है: डिफ़ॉल्ट में ⌘J (Ctrl+J), Eclipse और IntelliJ में ⌃J (Alt+J), और Emacs और NetBeans 5.5 में कोई नहीं, जहाँ कीमैप उसे एक दे सकता है।
- **⌃\` टर्मिनल को खोलता है और उस पर फ़ोकस करता है; उसे छिपाता नहीं।** और जब तक टर्मिनल पर फ़ोकस है, कुंजियाँ आपके शेल की हैं, इसलिए दूसरा दबाव आपको संपादक पर लौटाने के बजाय शेल तक पहुँचता है।
- **`launch.json` पढ़ी जाती है, और जिसे डिबगर निभा नहीं सकता वह अस्वीकार होता है।** यहाँ का डिबगर एक प्रोग्राम, उसका कार्य-फ़ोल्डर, उसके `args` (स्ट्रिंग्स की एक सूची) और उसका `env` (विरासत में मिले परिवेश में जोड़ी गई स्ट्रिंग्स) पहुँचाता है, इसलिए जो कॉन्फ़िगरेशन `envFile`, `runtimeExecutable`, `runtimeArgs`, `preLaunchTask` या कोई और ऐसा फ़ील्ड सेट करता है जो उसे सिखाया नहीं गया, वह सूची में आता है पर शुरू नहीं होता: Enter स्थिति-पट्टी पर उन फ़ील्डों के नाम बताता है। प्रोग्राम को इनके बिना शुरू करना कुछ और डिबग करना होगा, वह नहीं जो फ़ाइल कहती है। एक ही स्ट्रिंग के रूप में लिखे `args` (VS Code उसे शेल को सौंपता है) और `null` मान वाले `env` (जो किसी चर को हटा देता है) भी इसी तरह अस्वीकार होते हैं, और इसी तरह `"request": "attach"`, कोई `compounds` प्रविष्टि, ऐसा प्रकार जिसका यहाँ कोई अडैप्टर नहीं (`go`, `msedge`, `cppdbg` और बाकी), ऐसा मान जो केवल VS Code दे सकता है (`${file}`, `${input:…}`), और प्रोजेक्ट से बाहर का पथ भी। जो फ़ील्ड केवल यह तय करते हैं कि डिबगर क्या दिखाता है — `skipFiles`, `outFiles`, `sourceMaps`, `console`, `justMyCode`, `presentation` — वे स्वीकार होते हैं पर लागू नहीं होते; प्रोग्राम का आउटपुट **Output** विंडो में जाता है।
- **`tasks.json` पढ़ी जाती है, और जो लिखे अनुसार नहीं चल सकता वह अस्वीकार होता है।** जो टास्क ऐसा मान इस्तेमाल करता है जो केवल VS Code दे सकता है (`${input:…}`, `${file}`, `${config:…}`, `${command:…}`), या जो किसी दूसरे टास्क पर `dependsOn` रखता है, वह सूची में आता है पर चलता नहीं: Enter स्थिति-पट्टी पर बताता है कि कौन-सा चर या कौन-सा टास्क। मान को ख़ाली छोड़कर, या जिस टास्क पर वह निर्भर है उसके बिना, उसे चलाना कुछ और चलाना होगा, वह नहीं जो फ़ाइल कहती है। किसी एक्सटेंशन का दिया टास्क प्रकार (`gulp`, `typescript`) और प्रोजेक्ट से बाहर का कार्य-फ़ोल्डर भी ऐसा ही होगा।
- **`"type": "shell"` टास्क उसी शेल में चलता है जिसे VS Code इस्तेमाल करता।** macOS और Linux पर वह आपका `$SHELL` है `-c` के साथ (macOS पर zsh, bash या fish लॉगिन शेल के रूप में शुरू होता है, `-l`, जैसा VS Code की डिफ़ॉल्ट प्रोफ़ाइलें करती हैं); Windows पर वह PowerShell है, संस्थापित हो तो `pwsh`। `options.shell` का पालन VS Code के तरीक़े से होता है: कोई `executable` बताइए और वह ठीक उन्हीं `args` के साथ चलता है जो आप देते हैं, इसलिए bash को `"args": ["-c"]` चाहिए। Windows पर केवल PowerShell (`args` जिनके अंत में `-Command` हो) और `cmd.exe` (`args` जिनके अंत में `/c` हो) चलाए जाते हैं; वहाँ कोई भी दूसरा शेल अनुमान से उद्धृत की गई आदेश-पंक्ति थमाए जाने के बजाय नाम लेकर अस्वीकार किया जाता है।
- **कोई "VS Code" कीमैप प्रोफ़ाइल नहीं है।** ऊपर के संयोजन डिफ़ॉल्ट प्रोफ़ाइल और बाकी चारों में दर्ज हैं। एक जान-बूझकर अपवाद: **Eclipse** प्रोफ़ाइल में ⇧⌘E Eclipse का अपना *Switch to Editor* ही रहता है, और संपादक के भीतर ⇧⌘P और ⇧⌘X Eclipse के अर्थ रखते हैं (मेल खाता कोष्ठक, बड़े अक्षर) — जिसने Eclipse चुना वह Eclipse की अपेक्षा करता है।
- **Linux पर Ctrl+\` टर्मिनल खोलता है, विंडो-स्विचर नहीं।** स्विचर Ctrl+Tab पर है। जो डेस्कटॉप Ctrl+Tab अपने लिए ले लेता है (जैसे KDE), उस पर **विंडो ▸ दस्तावेज़…** खुली फ़ाइलों की सूची देता है।
- **Ctrl+Alt वाले संयोजन AltGr से टकरा सकते हैं।** Windows पर जो कीबोर्ड लेआउट AltGr से अक्षर टाइप करते हैं (जैसे पोलिश), वे उसके लिए Ctrl+Alt भेजते हैं। अगर Ctrl+Alt+P या Ctrl+Alt+K आपके लिए कोई अक्षर टाइप करता है, तो *प्रोजेक्ट बदलें* या प्रयोग वाले संयोजनों को कीमैप में कहीं और ले जाइए।
- **VS Code के एक्सटेंशन यहाँ संस्थापित नहीं होते।** भाषा की समझ उन भाषा-सर्वरों से आती है जिन्हें NMOX जानता है (परिवेश डॉक्टर बताता है कि क्या ग़ायब है और उसे कैसे संस्थापित करें), संपादक के अपने व्याकरणों से, और NetBeans Platform के लिए बने प्लगिन से।
