# VS Code से आने वालों के लिए

आपके हाथ पहले से जानते हैं कि चीज़ें कहाँ हैं। यह पन्ना उन आदतों से NMOX Studio तक का नक्शा है: पहले कुंजी-संयोजन, फिर यह कि VS Code का हर विचार यहाँ कहाँ रहता है, और फिर वह जो ईमानदारी से अलग है।

VS Code उपयोगकर्ता जो पहले चार संयोजन दबाता है, वे वही करते हैं जिसकी वह अपेक्षा करता है: **⇧⌘P** कमांड पैलेट खोलता है, **⇧⌘E** फ़ाइल वृक्ष, **⇧⌘X** प्लगिन, और **⌃\`** टर्मिनल। ये मंच के साथ आने वाली पाँचों कीमैप प्रोफ़ाइलों में दर्ज हैं, और एक बिल्ड-द्वार हर एक को macOS, Windows और Linux पर संयोजित कीमैप के ज़रिए हल करता है, ताकि उसकी जगह कुछ और न चल जाए।

<a id="the-chords"></a>
## कुंजी-संयोजन

macOS वाले स्तंभ मेनू-पट्टी के चिह्न इस्तेमाल करते हैं (⌃ Control, ⌥ Option, ⇧ Shift, ⌘ Command); Windows और Linux वाले स्तंभ PC कीबोर्ड पर वही संयोजन हैं।

| आप चाहते हैं | VS Code, macOS | NMOX, macOS | VS Code, Win/Linux | NMOX, Win/Linux |
|---|---|---|---|---|
| कमांड पैलेट | ⇧⌘P | **⇧⌘P** (या ⌘I) — त्वरित खोज | Ctrl+Shift+P | **Ctrl+Shift+P** (या Ctrl+I) |
| नाम से कोई फ़ाइल खोलना | ⌘P | **⌘P** — फ़ाइल पर जाएँ | Ctrl+P | **Ctrl+P** |
| फ़ाइल वृक्ष | ⇧⌘E | **⇧⌘E** — प्रोजेक्ट स्टूडियो | Ctrl+Shift+E | **Ctrl+Shift+E** |
| एक्सटेंशन | ⇧⌘X | **⇧⌘X** — उपकरण ▸ प्लगिन | Ctrl+Shift+X | **Ctrl+Shift+X** |
| प्रोजेक्ट फ़ोल्डर में टर्मिनल | ⌃\` | **⌃\`** | Ctrl+\` | **Ctrl+\`** |
| हाल का कोई प्रोजेक्ट खोलना | ⌃R | **⌥⌘P** — प्रोजेक्ट बदलें… | Ctrl+R | **Ctrl+Alt+P** |
| प्रोजेक्ट में किसी प्रतीक पर जाना | ⌘T | **⌥⇧⌘O** | Ctrl+T | **Ctrl+Alt+Shift+O** |
| परिभाषा पर जाना | F12 | **F12** या ⌘B | F12 | **F12** या Ctrl+B |
| संदर्भ खोजना | ⇧F12 | **⇧F12** — उपयोग खोजें | Shift+F12 | **Shift+F12** |
| किसी प्रतीक का नाम बदलना | F2 | **F2** या ⌃R | F2 | **F2** या Ctrl+R |
| त्वरित सुधार | ⌘. | **⌘.** या ⌃↩ | Ctrl+. | **Alt+Enter** |
| किसी पंक्ति पर जाना | ⌃G | **⌃G** | Ctrl+G | **Ctrl+G** |
| पीछे / आगे जाना | ⌃- / ⌃⇧- | **⌃- / ⌃⇧-** | Alt+← / Alt+→ | **Alt+← / Alt+→** |
| पंक्ति-टिप्पणी चालू/बंद | ⌘/ | **⌘/** | Ctrl+/ | **Ctrl+/** |
| ब्लॉक-टिप्पणी चालू/बंद | ⇧⌥A | **⇧⌥A** | Shift+Alt+A (Linux पर Ctrl+Shift+A) | **Shift+Alt+A** (और Linux पर Ctrl+Shift+A भी) |
| वर्ड रैप चालू/बंद | ⌥Z | **⌥Z** — दृश्य ▸ वर्ड रैप | Alt+Z | **Alt+Z** |
| सुझाव दिखाना | ⌃Space | **⌃Space** | Ctrl+Space | **Ctrl+Space** |
| अगली घटना को चयन में जोड़ना | ⌘D | **⌘D** या ⌘J | Ctrl+D | **Ctrl+D** या Ctrl+J |
| हर घटना चुनना | ⇧⌘L | **⌃⇧⌘J** | Ctrl+Shift+L | **Ctrl+Alt+Shift+J** |
| ऊपर / नीचे एक कर्सर जोड़ना | ⌥⌘↑ / ⌥⌘↓ | **⌥⌘↑ / ⌥⌘↓** | Ctrl+Alt+↑ / ↓ | **Alt+Shift+[ / ]** |
| पंक्ति ऊपर / नीचे ले जाना | ⌥↑ / ⌥↓ | **⌃⇧↑ / ⌃⇧↓** | Alt+↑ / ↓ | **Alt+Shift+↑ / ↓** |
| पंक्ति नीचे कॉपी करना | ⇧⌥↓ | **⌥⇧↓** | Shift+Alt+↓ | **Ctrl+Shift+↓** |
| पंक्ति हटाना | ⇧⌘K | **⌘E** | Ctrl+Shift+K | **Ctrl+E** |
| पंक्ति को इंडेंट करना | ⌘] | **⌘]** | Ctrl+] | **Alt+Shift+→** |
| खोजकर बदलना | ⌥⌘F | **⌥⌘F** या ⌘R | Ctrl+H | **Ctrl+H** |
| दस्तावेज़ को फ़ॉर्मैट करना | ⇧⌥F | **⇧⌥F** या ⌃⇧F | Shift+Alt+F | **Alt+Shift+F** |
| संपादक टैब बंद करना | ⌘W | **⌘W** | Ctrl+W | **Ctrl+W** |
| जिस फ़ाइल का संपादन कर रहे हैं उसका पथ कॉपी करना | ⌥⌘C | **⌥⌘C** — संपादन ▸ पथ कॉपी करें | Shift+Alt+C | **Ctrl+Alt+C** |
| उसका सापेक्ष पथ कॉपी करना | ⇧⌥⌘C | संपादन ▸ सापेक्ष पथ कॉपी करें (कोई संयोजन नहीं) | Ctrl+K Ctrl+Shift+Alt+C | संपादन ▸ सापेक्ष पथ कॉपी करें (कोई संयोजन नहीं) |
| समस्याओं का पैनल | ⇧⌘M | **⌘6** — कार्य आइटम (यहाँ ⇧⌘M बुकमार्क लगाता या हटाता है) | Ctrl+Shift+M | **Ctrl+6** |
| ब्रेकपॉइंट लगाना या हटाना | F9 | **⌘F8** | F9 | **Ctrl+F8** |
| डिबगिंग शुरू करना | F5 | **⇧⌘F5** — फ़ाइल डिबग करें | F5 | **Ctrl+Shift+F5** |
| बिना डिबगिंग के चलाना | ⌃F5 | **F6** — प्रोजेक्ट चलाएँ | Ctrl+F5 | **F6** |
| सेटिंग | ⌘, | **⌘,** — NMOX Studio ▸ Settings… | Ctrl+, | उपकरण ▸ विकल्प (कोई संयोजन नहीं) |

तालिका का हर NMOX संयोजन शिप हुए कीमैप से पढ़ा गया है, याद से नहीं लिखा गया (⌘, macOS के ऐप मेनू का अपना है)। कुछ बातें जो तालिका का कोई ख़ाना नहीं कह सकता:

- **डिबगिंग के दौरान F5 व्यस्त रहता है।** यहाँ इसका अर्थ *जारी रखें* है, जैसा NetBeans परिवार के हर IDE में होता है, इसलिए डिबग रन **⇧⌘F5** (Ctrl+Shift+F5) से शुरू होता है और F5 से आगे बढ़ता है।
- **यहाँ ⌃R नाम बदलना है**, इसीलिए *प्रोजेक्ट बदलें* VS Code के Open Recent वाले संयोजन की जगह ⌥⌘P पर रहता है। नाम बदलना वहाँ काम करता है जहाँ फ़ाइल के पीछे की भाषा उसका समर्थन करती है।
- **सापेक्ष पथ कॉपी करें का कोई संयोजन नहीं है।** VS Code का ⇧⌥⌘C PC पर Ctrl+Alt+Shift+C है, जो हर कीमैप प्रोफ़ाइल में प्लेटफ़ॉर्म का *Clear Split* है; यह पंक्ति संपादन मेनू में है, और ⇧⌘P इसे VS Code के अपने शीर्षक *File: Copy Relative Path of Active File* से ढूँढ़ लेता है।
- **Windows और Linux पर Ctrl+,** आपके संपादन-इतिहास में पीछे ले जाता है, जैसा NetBeans में हमेशा से होता है; सेटिंग उपकरण ▸ विकल्प में रहती हैं (macOS पर ऐप मेनू का **Settings…**, ⌘,)।

**सहायता ▸ कीबोर्ड शॉर्टकट…** आपकी सक्रिय कीमैप का हर NMOX संयोजन गिनाता है, चारों VS Code संयोजनों समेत, चलती हुई कीमैप से पढ़कर, इसलिए वह कुंजियों के असली काम से अलग नहीं हो सकता।

### संपादन का हर संयोजन, मापा हुआ

VS Code के आदी आपके हाथ संपादन करते समय जिन संयोजनों की ओर जाते हैं, उनमें से हर एक को macOS पर डिफ़ॉल्ट प्रोफ़ाइल की भेजी गई कीमैप में देखा गया। जहाँ VS Code का संयोजन यहाँ खाली था, वहाँ अब वह वही करता है जो VS Code करता है (जिन पंक्तियों में **वही:** लिखा है); जहाँ उसका पहले से कोई ऐसा मतलब था जिस पर NetBeans के उपयोगकर्ता निर्भर हैं, वहाँ वह मतलब बना रहता है और पंक्ति बताती है कि VS Code की वह क्रिया कहाँ है।

| VS Code, macOS | VS Code क्या करता है | NMOX Studio में |
|---|---|---|
| F12 | Go to Definition | **वही:** घोषणा पर जाएँ, जैसे ⌘B करता है |
| ⇧F12 | Go to References | **वही:** उपयोग खोजें, जैसे ⌃F7 करता है |
| F2 | Rename Symbol | **वही:** नाम बदलें, जैसे ⌃R करता है |
| ⌘. | Quick Fix | **वही:** पंक्ति के सुधार, जैसे ⌃↩ उन्हें दिखाता है |
| ⌥↑ / ⌥↓ | Move Line Up / Down | पिछली / अगली चिह्नित घटना; पंक्ति खिसकाना ⌃⇧↑ / ⌃⇧↓ है |
| ⇧⌥↑ / ⇧⌥↓ | Copy Line Up / Down | वही, जैसा हमेशा से था |
| ⇧⌘K | Delete Line | अगला मिलता-जुलता शब्द डालें (फ़ाइल से शब्द पूरा करता है); पंक्ति हटाना ⌘E है |
| ⌘L | Expand Line Selection | आइडेंटिफ़ायर चुनें, जो डिफ़ॉल्ट कीमैप में यह संयोजन अपने पास रखता है; “पंक्ति चयन बढ़ाएँ” त्वरित खोज में इसी नाम से मिलता है, और IntelliJ तथा Emacs कीमैप प्रोफ़ाइलों में ख़ुद ⌘L पर है, क्योंकि वे इस संयोजन को खाली छोड़ती हैं |
| ⇧⌘L | Select All Occurrences | एडिटर में लाइनों के रूप में पेस्ट करें; हर घटना चुनना ⌃⇧⌘J है |
| ⌘/ | Toggle Line Comment | वही, जैसा हमेशा से था |
| ⇧⌥A | Toggle Block Comment | **वही:** चयन को, या कर्सर वाली पंक्ति को, भाषा के ब्लॉक-टिप्पणी डेलिमिटरों में लपेटता है, और फिर उन्हें हटा भी देता है; जिस चयन में पहले से कोई डेलिमिटर है, उसे तोड़ने के बजाय अस्वीकार कर दिया जाता है |
| ⌘] | Indent Line | **वही:** दाएँ खिसकाएँ |
| ⌘[ | Outdent Line | मिलते हुए कोष्ठक पर जाना, जैसा हमेशा से था; इंडेंट घटाना ⇧Tab या ⌃⇧← है |
| ⌥Z | Toggle Word Wrap | **वही:** दृश्य ▸ वर्ड रैप। यह रैप को फ़ाइल की भाषा के हर एडिटर के लिए बदलता है, किसी एक टैब के लिए नहीं, और यह चुनाव सहेजा जाता है |
| ⌘B | Toggle Sidebar | घोषणा पर जाएँ; ⇧⌘↩ सिर्फ़ एडिटर दिखाता है, ⇧Esc उस विंडो को बड़ा करता है जिसमें आप हैं |
| ⌘J | Toggle Panel | एडिटर में अगली घटना जोड़ता है (जैसे ⌘D); **Output** विंडो ⌘4 है |
| ⌘\ | Split Editor | एडिटर में कोड पूरा करें; एडिटर को बाँटना ⌃⇧⌘V है |
| ⇧⌘T | Reopen Closed Editor | वही, जैसा हमेशा से था: हाल की फ़ाइल खोलें का संयोजन आख़िरी बंद की गई फ़ाइल को फिर से खोलता है |
| ⌃- / ⌃⇧- | Go Back / Go Forward | **वही:** जहाँ-जहाँ आपने संपादन किया, उनके बीच पीछे और आगे, जैसे ⌃← / ⌃→ (ऐसे संयोजन जिन्हें macOS आम तौर पर डेस्कटॉप बदलने के लिए रखता है) |
| ⌘G / ⇧⌘G | Find Next / Previous | वही, जैसा हमेशा से था |
| ⌥⌘F | Replace | **वही:** बदलें, जैसे ⌘R करता है |
| ⇧⌘F | Find in Files | वही, जैसा हमेशा से था: प्रोजेक्ट में खोजें |
| ⇧⌘O | Go to Symbol in Editor | प्रोजेक्ट खोलें; फ़ाइल के सिंबल त्वरित खोज में हैं: ⌘I, फिर VS Code की तरह `@name` (नेविगेट ▸ इस फ़ाइल में सिंबल पर जाएँ… आपके लिए `@` टाइप कर देता है), और वृक्ष के रूप में नेविगेटर (⌘7) में |
| ⌘T | Go to Symbol in Workspace | एडिटर में कर्सर के दोनों ओर के दो अक्षरों की जगह बदलता है; प्रोजेक्ट के सिंबल ⌥⇧⌘O हैं |
| ⌃G | Go to Line | वही, जैसा हमेशा से था |
| ⌘K ⌘S | Keyboard Shortcuts | ⌘K पिछला मिलता-जुलता शब्द डालें है; सूची **सहायता ▸ कीबोर्ड शॉर्टकट…** है |
| ⌘, | Settings | वही, जैसा हमेशा से था: NMOX Studio ▸ Settings… |
| ⇧⌥F | Format Document | **वही:** फ़ॉर्मैट करें, जैसे ⌃⇧F करता है |

**वही:** वाले संयोजन हर उस कीमैप प्रोफ़ाइल में लगे हैं जो उन्हें खाली छोड़ती है, और जो प्रोफ़ाइल उनमें से किसी को अपना मतलब देती है, वह उसे बनाए रखती है: Eclipse, Emacs और NetBeans 5.5 प्रोफ़ाइलों में F12, डिफ़ॉल्ट को छोड़कर हर प्रोफ़ाइल में F2, Emacs और NetBeans 5.5 में ⇧F12, Emacs और IntelliJ में ⌃- और ⌃⇧-, IntelliJ में ⇧⌥F। Windows और Linux पर F12, ⇧F12 और F2 इसी तरह काम करते हैं; VS Code के बाक़ी संयोजन वहाँ अलग हैं, और ऊपर की तालिका दोनों देती है।

“ब्लॉक कमेंट टॉगल करें” और “वर्ड रैप टॉगल करें” Windows और Linux पर भी अपने VS Code वाले संयोजन रखते हैं। वर्ड रैप हर प्रोफ़ाइल में Alt+Z है। “ब्लॉक कमेंट टॉगल करें” डिफ़ॉल्ट, Emacs और IntelliJ प्रोफ़ाइलों में Shift+Alt+A है (Eclipse और NetBeans 5.5 प्रोफ़ाइलें वहाँ अपना Alt+Shift+A बनाए रखती हैं), और Linux पर वह पाँचों प्रोफ़ाइलों में Ctrl+Shift+A भी है, जो Linux पर VS Code का संयोजन है। “पंक्ति चयन बढ़ाएँ” Windows और Linux पर केवल IntelliJ प्रोफ़ाइल में Ctrl+L है; Emacs प्रोफ़ाइल में वहाँ Ctrl+L अब भी Emacs का अपना recenter है।

जिस भाषा में ब्लॉक टिप्पणी नहीं होती, जैसे Python, उसके लिए स्थिति-पट्टी यही बता देती है। HTML, Vue या Svelte फ़ाइल में `<script>` या `<style>` खंड पर उसकी अपनी भाषा के हिसाब से टिप्पणी लगती है। चयन न हो तो संयोजन पंक्ति पर टिप्पणी लगाता या हटाता है; वह ऐसी टिप्पणी नहीं खोजता जो बस कर्सर के आसपास फैली हो, इसलिए कई पंक्तियों की टिप्पणी हटाने के लिए उसे चुनिए।

त्वरित खोज में फ़ाइल के सिंबल **इस फ़ाइल के सिंबल** श्रेणी में हैं। अकेला `@` टाइप करने पर वे फ़ाइल के ऊपर से शुरू होकर सूचीबद्ध होते हैं; `m name` (यह अक्षर, एक स्पेस, फिर नाम) केवल इसी श्रेणी में खोजता है, किसी और में नहीं।

<a id="from-the-terminal"></a>
## टर्मिनल से

`code .` यहाँ `nmox .` है:

```bash
cd ~/code/my-app
nmox .          # open this folder (manifest or not) and aim the IDE at it
nmox src/app.ts # open one file
nmox src/app.ts:42  # open it at line 42 (code -g's form; -g itself is accepted)
nmox            # just start the IDE
```

यह तुरंत लौट आता है, और दूसरा `nmox` अपना फ़ोल्डर पहले से चल रहे IDE को सौंप देता है। स्तंभ (`src/app.ts:42:7`) भी स्वीकार होता है और संपादक पंक्ति की शुरुआत पर खुलता है; जो नाम मौजूद नहीं है, उसे कुछ भी शुरू करने के बजाय टर्मिनल पर ही अस्वीकार कर दिया जाता है। `-r` स्वीकार होता है, `-n` उसी एक विंडो में खोलता है, और `-a` तथा `-v` नाम लेकर अस्वीकार किए जाते हैं।

`-w` (`--wait`) एक फ़ाइल खोलता है और तब तक रुकता है जब तक आप उसका टैब बंद न कर दें, और `-d` (`--diff`) दो फ़ाइलों की अगल-बगल तुलना करता है, इसलिए NMOX Studio git का संपादक, difftool और mergetool बन सकता है, ठीक वैसे जैसे `code --wait` बनता है:

```bash
git config --global core.editor "nmox -w"
git config --global diff.tool nmox
git config --global difftool.nmox.cmd 'nmox -w -d "$LOCAL" "$REMOTE"'
git config --global merge.tool nmox
git config --global mergetool.nmox.cmd 'nmox -w "$MERGED"'
git config --global mergetool.nmox.trustExitCode false
```

फिर `git commit` संदेश को IDE में खोलता है; उसे सहेजें और टैब बंद करें, और git आगे बढ़ जाता है। कोई फ़ाइल खुली रहते IDE से बाहर निकलना भी उसे लौटा देता है, जितना सहेजा गया था उसके साथ। इसी तरह `git mergetool` टकराव वाली हर फ़ाइल खोलता है। जहाँ VS Code टकराव के ऊपर *Accept Current Change | Accept Incoming Change | Accept Both Changes* रखता है, वहाँ NMOX Studio दोनों पक्षों को रंग देता है और `<<<<<<<` वाली पंक्ति पर चेतावनी रखता है; हाशिये का बल्ब, या उस पंक्ति पर कर्सर रखकर त्वरित सुधार (Mac पर ⌘., बाक़ी जगह Alt+Enter), वही तीन विकल्प देता है, और हर एक ऐसा संपादन है जिसे पलटा जा सकता है। सहेजें, टैब बंद करें, और git अगली फ़ाइल पर चला जाता है। रंग और तीनों विकल्प टकराव-चिह्नों वाली किसी भी फ़ाइल में मौजूद हैं, `git mergetool` के साथ या उसके बिना। **टीम ▸ NMOX Studio को Git के साथ इस्तेमाल करें…** पहले दिखाता है कि हर एक अभी किस पर सेट है, फिर वही पंक्तियाँ आपके लिए सेट कर देता है। Homebrew, Windows संस्थापक (*Add "nmox" to PATH*) और Linux पैकेज इसे आपके PATH पर रख देते हैं; DMG से संस्थापन हो तो [उपयोगकर्ता मार्गदर्शिका](user-guide.hi.md#2-first-launch) एक पंक्ति वाला लिंक दिखाती है।

<a id="where-each-vs-code-idea-lives"></a>
## VS Code का हर विचार कहाँ रहता है

| VS Code में | NMOX Studio में |
|---|---|
| **Explorer** | **प्रोजेक्ट स्टूडियो** (⇧⌘E) — फ़ाइल वृक्ष (किसी फ़ाइल पर दायाँ-क्लिक करने पर **पथ कॉपी करें**, **सापेक्ष पथ कॉपी करें** और **Finder में दिखाएँ** मिलते हैं), टेम्पलेट, और प्रोजेक्ट का `package.json` संपादक। **वर्कबेंच** (⌥⌘0) घर का ठिकाना है: खुली फ़ाइलें, हाल की फ़ाइलें, हाल के प्रोजेक्ट, और जो कुछ भी चल रहा है। |
| **Command Palette** | **त्वरित खोज** (⇧⌘P या ⌘I) — क्रियाएँ, फ़ाइलें, हाल के प्रोजेक्ट, रैक डिवाइस, लाइव सर्वर, API स्टूडियो के अनुरोध, प्रतीक। VS Code के अपने कमांड-नाम भी काम करते हैं: *Format Document*, *Toggle Terminal*, *Git: Commit* या *Open Settings* लिखने पर **VS Code कमांड** के नीचे वह क्रिया सूची में आती है जो यहाँ वही काम करती है, उसके अपने नाम और संयोजन के साथ। |
| **Extensions** | **उपकरण ▸ प्लगिन** मॉड्यूल संस्थापित और अपडेट करता है, NMOX के अपने अपडेट भी। VS Code के एक्सटेंशन यहाँ संस्थापित नहीं होते, इसलिए **उपकरण ▸ सुझाए गए VS Code एक्सटेंशन…** उस सवाल का जवाब देता है जो किसी रिपॉज़िटरी की `.vscode/extensions.json` उठाती है: वह जिस-जिस एक्सटेंशन को सुझाती है, NMOX Studio में उसका काम कौन करता है — कोई अंतर्निहित सुविधा, कोई विंडो जिसे वह खोल सकता है, कोई रैक डिवाइस, कोई भाषा सर्वर (और वह सर्वर संस्थापित है या नहीं), या कुछ भी नहीं — और जिस एक्सटेंशन को वह नहीं जानता, उसके बारे में अंदाज़ा लगाने के बजाय यही कहा जाता है कि वह अज्ञात है। VS Code में जो कुछ कोई एक्सटेंशन जोड़ता है, उसमें से बहुत कुछ यहाँ एक **रैक डिवाइस** है — और आप `~/.nmox/devices.d` में एक JSON फ़ाइल के रूप में अपना डिवाइस लिख सकते हैं ([device files](device-files.md))। |
| **`tasks.json`** | आपकी रिपॉज़िटरी की `.vscode/tasks.json` पढ़ी जाती है: त्वरित खोज (⇧⌘P या ⌘I) में किसी टास्क का नाम लिखिए, और *टास्क चलाएँ: build — make all* पर Enter उसे चलाता है — या उसे उस सूची से चुनिए जो **चलाएँ ▸ टास्क चलाएँ…** दिखाता है — जिस प्रोजेक्ट पर आपने भरोसा नहीं किया, उस पर वर्कस्पेस ट्रस्ट पहले पूछता है, आउटपुट **Output** विंडो में आता है और टूलबार का ■ उसे रोकता है। जिन टास्क पर वह `dependsOn` रखता है वे पहले चलते हैं, `${file}` संपादक में खुली फ़ाइल है, और `${input:…}` कुछ भी शुरू होने से पहले आपसे पूछता है। उसके बग़ल में प्रोजेक्ट की अपनी स्क्रिप्टें वैसे ही चलाई जाती हैं जैसे लिखी गई हैं: टूलबार का चलाएँ / बिल्ड / टेस्ट (F6, F11, ⌃F6), `package.json` की किसी scripts पंक्ति पर **स्क्रिप्ट चलाएँ**, **NPM एक्सप्लोरर**, और **टास्क रैक** (⌘9), जहाँ कार्य ऐसे डिवाइस हैं जिन्हें आप आपस में जोड़ते हैं। |
| **`launch.json`** | आपकी रिपॉज़िटरी की `.vscode/launch.json` पढ़ी जाती है: त्वरित खोज (⇧⌘P या ⌘I) में किसी कॉन्फ़िगरेशन का नाम लिखिए, और *डिबग करें: Launch Program — ${workspaceFolder}/server.js* पर Enter उस प्रोग्राम पर ब्रेकपॉइंट डिबगर शुरू करता है — **डीबग ▸ डिबगिंग शुरू करें…** यही कॉन्फ़िगरेशन सूचीबद्ध करता है — वर्कस्पेस ट्रस्ट के पहले पूछ लेने के बाद। Node (`node`, `pwa-node`) कॉन्फ़िगरेशन अपने `cwd` में अपना `program` डिबग करते हैं, अपने `args`, अपने `env` और `envFile` के साथ, अपने `runtimeExecutable` और `runtimeArgs` के अधीन — इसलिए `npm run dev`, `tsx` या `--experimental-strip-types` वाला कॉन्फ़िगरेशन वैसे ही शुरू होता है जैसा वह लिखा है — और Node का `"request": "attach"` इसी मशीन की किसी `node --inspect` प्रोसेस से अटैच होता है। Python (`python`, `debugpy`) कॉन्फ़िगरेशन अपना `program` `args`, `env`, `envFile` और उस इंटरप्रेटर के साथ डिबग करते हैं जिसका नाम उनका `python` देता है; Chrome (`chrome`, `pwa-chrome`) कॉन्फ़िगरेशन अपने `webRoot` के साथ अपना `url` (या `file`) खोलते हैं। `"program": "${file}"` वह फ़ाइल डिबग करता है जो आपका संपादक दिखा रहा है, और जो `preLaunchTask` आपकी `tasks.json` के किसी टास्क का नाम लेता है वह पहले चलता है: डिबगर तब शुरू होता है जब टास्क सफल हो चुका हो। `launch.json` न हो तो **फ़ाइल डिबग करें** (⇧⌘F5) और टूलबार का डिबग बटन ख़ुद प्रोजेक्ट से तय करते हैं कि क्या चलाना है — `start` स्क्रिप्ट का प्रवेश-बिंदु, `main`, `index.js` — और **INSPECTOR** रैक डिवाइस किसी पाइपलाइन के एक क़दम के रूप में डिबगर शुरू करता है। |
| **Integrated terminal** | **टर्मिनल** विंडो (⌃\`): पहला दबाव प्रोजेक्ट फ़ोल्डर में एक शेल शुरू करता है, बाद के दबाव उसे वापस ले आते हैं। |
| **`settings.json`** | उपकरण ▸ विकल्प (macOS पर NMOX Studio ▸ Settings…)। किसी रिपॉज़िटरी की `.vscode/settings.json` भी पढ़ी जाती है: `editor.tabSize`, `editor.insertSpaces` और `editor.indentSize` टाइप करते समय उसका इंडेंटेशन तय करते हैं, `files.trimTrailingWhitespace` और `files.insertFinalNewline` (`true` होने पर) सहेजते समय लागू होते हैं, `files.eol` वह पंक्ति-अंत है जिसके साथ फ़ाइलें लिखी जाती हैं, `"editor.formatOnSave": false` सहेजते समय फ़ाइल को दोबारा फ़ॉर्मैट होने से रोकता है, और `"[typescript]"` जैसा कोई भाषा-खंड अपनी भाषा के लिए इन्हें बदल देता है। अगर रिपॉज़िटरी में `.editorconfig` भी है, तो जिन बातों पर दोनों कुछ कहते हैं उन पर `.editorconfig` की चलती है। |
| **Problems panel** | **कार्य आइटम** (⌘6), या स्थिति-पट्टी पर **✕ ⚠** गिनती पर क्लिक कीजिए: भाषा सर्वरों की त्रुटियाँ और चेतावनियाँ, और रैक के PURITY और TYPEGUARD डिवाइसों से मिली लिंट और टाइप की समस्याएँ। VS Code की तरह, कुछ सर्वर केवल खुली फ़ाइलों के बारे में बताते हैं; gopls पूरे पैकेज के बारे में बताता है। |
| **Search view** (`search.useIgnoreFiles`) | **प्रोजेक्ट में खोजें** (⇧⌘F)। VS Code की तरह, यह वह छोड़ देता है जिसे रिपॉज़िटरी की `.gitignore` फ़ाइलें और `.git/info/exclude` अनदेखा करती हैं, इसलिए जब `.gitignore` उन्हें सूचीबद्ध करती है तो `node_modules` और `dist/` परिणामों से बाहर रहते हैं; रिपॉज़िटरी के बाहर यह `node_modules`, `dist`, `build` और बाकी बिल्ड फ़ोल्डरों को नाम से छोड़ता है। उनमें भी खोजने के लिए इसके डायलॉग में **जनरेट किए स्रोतों में खोजें** पर सही का निशान लगाइए। आपकी वैश्विक git excludes फ़ाइल नहीं पढ़ी जाती। |
| **Outline** | **नेविगेटर** (⌘7)। |
| **Snippets** (`.vscode/*.code-snippets`) | आपकी टीम की कमिट की हुई स्निपेट फ़ाइलें जैसी हैं वैसी ही पढ़ी जाती हैं: कोई प्रीफ़िक्स टाइप कीजिए, ⌃Space दबाइए, और स्निपेट *प्रीफ़िक्स — नाम (विवरण)* के रूप में सूची में आता है, बग़ल में उसकी फ़ाइल के साथ, और केवल उन भाषाओं में जिनका नाम उसका `scope` लेता है। उसे स्वीकार करने पर उसका मुख्य भाग अपने टैब स्टॉप, मिरर, चरों (`TM_FILENAME`, `CURRENT_YEAR`, `UUID` और बाक़ी) और `/regex/format/` रूपांतरणों के साथ डाला जाता है; Tab स्टॉपों के बीच घूमता है, और Enter आगे बढ़ता है और आख़िरी स्टॉप के बाद `$0` पर पहुँचता है। |

जब आप पहली बार कोई ऐसी रिपॉज़िटरी खोलते हैं जिसमें `.vscode/tasks.json`, `launch.json`, `settings.json` या `extensions.json` है, तो एक सूचना बताती है कि क्या मिला और वह कहाँ रहता है; उस पर क्लिक करने से त्वरित खोज खुलती है (या, एक्सटेंशन के मामले में, वह सूची जो बताती है कि यहाँ हर एक का काम कौन करता है)। यह हर प्रोजेक्ट के लिए एक ही बार कहा जाता है।

<a id="what-is-honestly-different"></a>
## जो ईमानदारी से अलग है

- **⌘D डिफ़ॉल्ट कीमैप में अगली घटना जोड़ता है, हर प्रोफ़ाइल में नहीं।** Eclipse प्रोफ़ाइल ⌘D को Eclipse का *Delete Line* ही रखती है, NetBeans 5.5 प्रोफ़ाइल *Shift Line Left* और Emacs प्रोफ़ाइल *kill word* (और Windows और Linux पर Ctrl+D को *delete character*); IntelliJ प्रोफ़ाइल में macOS पर ⌘D है, और Windows और Linux पर वह Ctrl+D को *Duplicate Line* ही रखती है। इस काम का दूसरा संयोजन भी प्रोफ़ाइल के हिसाब से बदलता है: डिफ़ॉल्ट में ⌘J (Ctrl+J), Eclipse और IntelliJ में ⌃J (Alt+J), और Emacs और NetBeans 5.5 में कोई नहीं, जहाँ कीमैप उसे एक दे सकता है।
- **⌃\` टर्मिनल को खोलता है और उस पर फ़ोकस करता है; उसे छिपाता नहीं।** और जब तक टर्मिनल पर फ़ोकस है, कुंजियाँ आपके शेल की हैं, इसलिए दूसरा दबाव आपको संपादक पर लौटाने के बजाय शेल तक पहुँचता है।
- **`launch.json` पढ़ी जाती है, और जिसे डिबगर निभा नहीं सकता वह अस्वीकार होता है।** यहाँ का डिबगर एक प्रोग्राम, उसका कार्य-फ़ोल्डर, उसके `args` (स्ट्रिंग्स की एक सूची), उसका `env` और `envFile`, और उसे शुरू करने वाला रनटाइम (Node के लिए `runtimeExecutable` और `runtimeArgs`, Python के लिए `python`) पहुँचाता है; Node के लिए वह पहले से चल रही प्रोसेस से अटैच भी होता है। जो कॉन्फ़िगरेशन `postDebugTask`, `restart` या कोई और ऐसा फ़ील्ड सेट करता है जो उसे सिखाया नहीं गया, वह सूची में आता है पर शुरू नहीं होता: Enter स्थिति-पट्टी पर उन फ़ील्डों के नाम बताता है। प्रोग्राम को इनके बिना शुरू करना कुछ और डिबग करना होगा, वह नहीं जो फ़ाइल कहती है। एक ही स्ट्रिंग के रूप में लिखे `args` या `runtimeArgs` (VS Code उसे शेल को सौंपता है) और `null` मान वाला `env` (जो किसी चर को हटा देता है) भी इसी तरह अस्वीकार होते हैं, और इसी तरह कोई `compounds` प्रविष्टि, ऐसा प्रकार जिसका यहाँ कोई अडैप्टर नहीं (`go`, `msedge`, `cppdbg` और बाकी), Node के अलावा किसी और चीज़ से अटैच, ऐसा मान जो केवल VS Code दे सकता है (`${input:…}`, `${command:…}`), और प्रोजेक्ट से बाहर का प्रोग्राम, कार्य-फ़ोल्डर या `envFile` भी। जो फ़ील्ड केवल यह तय करते हैं कि डिबगर क्या दिखाता है — `skipFiles`, `outFiles`, `sourceMaps`, `console`, `justMyCode`, `presentation` — वे स्वीकार होते हैं पर लागू नहीं होते; प्रोग्राम का आउटपुट **Output** विंडो में जाता है। Enter दबाने से पहले पाँच बातें जान लेना अच्छा है:
  - **`preLaunchTask` पहले चलता है, और उसका सफल होना ज़रूरी है।** टास्क वैसे ही चलाया जाता है जैसे त्वरित खोज में उस पर Enter उसे चलाता — जिन टास्क पर वह `dependsOn` रखता है, उसके प्रश्न, उसका अपना Output टैब — और डिबगर तब शुरू होता है जब वह एग्ज़िट कोड 0 के साथ ख़त्म हो चुका हो; जहाँ VS Code किसी विफल टास्क के बाद *Debug Anyway?* पूछता है, वहाँ यहाँ स्थिति-पट्टी बताती है कि कॉन्फ़िगरेशन शुरू नहीं किया गया। जो `program` टास्क बनाता है (`dist/server.js`), उसे टास्क के बाद खोजा जाता है, पहले नहीं। ऐसा लेबल जिसे `tasks.json` परिभाषित नहीं करती, ऐसा लेबल जो दो टास्क का है, ऑब्जेक्ट रूप (`{"type": "npm", "script": "build"}`) और बैकग्राउंड टास्क (`"isBackground": true`, ऐसा वॉचर जो कभी ख़त्म नहीं होता) कुछ भी चलने से पहले नाम लेकर अस्वीकार किए जाते हैं।
  - **जो `envFile` मौजूद नहीं है वह अस्वीकार होता है**, जबकि VS Code उसके बिना ही प्रोग्राम शुरू कर देता है। उसके चर परिवेश में जोड़े जाते हैं और `env` की प्रविष्टि फ़ाइल पर भारी पड़ती है, जैसे VS Code में। फ़ाइल सादी `NAME=value` पंक्तियों के रूप में पढ़ी जाती है (टिप्पणी वाली पंक्तियाँ, `export`, और मान के चारों ओर उद्धरण-चिह्नों का एक जोड़ा ठीक हैं); जिस पंक्ति को VS Code अलग तरह से पढ़ता — दोहरे उद्धरण-चिह्नों के भीतर कोई एस्केप, मान के बाद `#`, कोई बैक-टिक, और Python कॉन्फ़िगरेशन में `export` या `${NAME}` — वह फ़ाइल और पंक्ति-संख्या का नाम लेकर अस्वीकार होती है, मान का कभी नहीं।
  - **`${file}`, `${relativeFile}`, `${fileBasename}`, `${fileBasenameNoExtension}`, `${fileExtname}`, `${fileDirname}` और फ़ाइल वाले बाक़ी चर सक्रिय संपादक की फ़ाइल को दर्शाते हैं**: फ़ोकस वाला टैब, अगर वह संपादक है, नहीं तो संपादक क्षेत्र में दिख रहा टैब — वही फ़ाइल जिसे किसी टास्क का `${file}` दर्शाता है। कोई फ़ाइल खुली न हो तो कॉन्फ़िगरेशन उस चर का नाम लेकर अस्वीकार होता है, और प्रोजेक्ट के बाहर का `${file}` वहाँ के किसी भी दूसरे प्रोग्राम की तरह अस्वीकार होता है।
  - **`runtimeExecutable` या तो एक नाम होता है या एक निरपेक्ष पथ।** नाम (`npm`, `tsx`, `nodemon`) पहले आपके PATH पर और फिर प्रोजेक्ट के `node_modules/.bin` में खोजा जाता है; `${workspaceFolder}/node_modules/.bin/tsx` का वहाँ होना ज़रूरी है; सापेक्ष पथ अस्वीकार होता है, क्योंकि VS Code उसे नाम की तरह खोजता। जब रनटाइम ही पूरा कमांड हो (`program` के बिना `npm run dev`), तो वह जो स्क्रिप्ट शुरू करता है उसे अपने अलग सत्र के रूप में डिबग किया जाता है, जो **Sessions** विंडो में सूचीबद्ध होता है।
  - **अटैच इसी मशीन से होता है।** `port` (लिखा न हो तो 9229) और `localhost`, `127.0.0.1` या `::1` का `address`; कोई भी दूसरा पता अस्वीकार होता है, क्योंकि यह रिमोट डेवलपमेंट नहीं है। अगर कुछ भी सुन नहीं रहा हो तो स्थिति-पट्टी यही बताती है, और सत्र ख़त्म करने पर आपका प्रोग्राम चलता रहता है।
- **`tasks.json` पढ़ी जाती है, और जो लिखे अनुसार नहीं चल सकता वह अस्वीकार होता है।** टास्क उन टास्क के साथ चलता है जिन पर वह `dependsOn` रखता है, और वे पहले चलते हैं (एक साथ, या `"dependsOrder": "sequence"` हो तो एक के बाद एक); `${file}`, `${relativeFile}`, `${lineNumber}`, `${selectedText}` और उस परिवार के बाक़ी चर संपादक में खुली फ़ाइल से भरे जाते हैं; और उसके `${input:…}` प्रश्न (`promptString`, `pickString`) कुछ भी शुरू होने से पहले पूछ लिए जाते हैं। पूरा रन पहले तय किया जाता है: अगर उसका एक भी टास्क लिखे अनुसार नहीं चल सकता, तो कुछ भी नहीं चलता, और Enter स्थिति-पट्टी पर बताता है कि कौन-सा टास्क और क्यों। इसमें ये सब आते हैं: ऐसा `dependsOn` लेबल जिसे फ़ाइल परिभाषित नहीं करती, ऐसी निर्भरता जो बैकग्राउंड टास्क है (problem matcher नहीं पढ़े जाते, इसलिए कुछ भी नहीं बताता कि वह कब तैयार है), कोई फ़ाइल खुली न होने पर `${file}`, और ऐसा प्रश्न जिसे आप रद्द कर दें। जो निर्भरता विफल होती है वह रन को वहीं रोक देती है। अब भी नाम लेकर अस्वीकार होते हैं: ऐसा मान जो केवल VS Code दे सकता है (`${config:…}`, `${command:…}`, `"type": "command"` वाला इनपुट), लेबल की जगह ऑब्जेक्ट के रूप में लिखी निर्भरता (`{"type": "npm", …}`), किसी एक्सटेंशन का दिया टास्क प्रकार (`gulp`, `typescript`), और प्रोजेक्ट से बाहर का कार्य-फ़ोल्डर।
- **स्निपेट आपकी रिपॉज़िटरी के हैं, और तीन बातें अलग हैं।** कोई विकल्प-सूची (`${1|a,b|}`) अपने पहले विकल्प से शुरू होती है, और चुनने के लिए कोई सूची नहीं आती; किसी दूसरे प्लेसहोल्डर के डिफ़ॉल्ट के भीतर रखा प्लेसहोल्डर उसी डिफ़ॉल्ट का हिस्सा बन जाता है; और जिस स्निपेट का रूपांतरण सुरक्षित रूप से नहीं चलाया जा सकता (ऐसा रेगुलर एक्सप्रेशन जिसे Java कंपाइल नहीं कर सकता, या जो बेक़ाबू चल सकता है), उसे आधा-अधूरा डालने के बजाय छोड़ दिया जाता है और लॉग में उसका नाम दर्ज होता है। प्रीफ़िक्स टाइप करने भर से सूची नहीं खुलती: ⌃Space उसे खोलता है। बिना `prefix` वाले स्निपेट, उपयोगकर्ता-स्तर के स्निपेट और `isFileTemplate` नहीं पढ़े जाते।
- **`"type": "shell"` टास्क उसी शेल में चलता है जिसे VS Code इस्तेमाल करता।** macOS और Linux पर वह आपका `$SHELL` है `-c` के साथ (macOS पर zsh, bash या fish लॉगिन शेल के रूप में शुरू होता है, `-l`, जैसा VS Code की डिफ़ॉल्ट प्रोफ़ाइलें करती हैं); Windows पर वह PowerShell है, संस्थापित हो तो `pwsh`। `options.shell` का पालन VS Code के तरीक़े से होता है: कोई `executable` बताइए और वह ठीक उन्हीं `args` के साथ चलता है जो आप देते हैं, इसलिए bash को `"args": ["-c"]` चाहिए। Windows पर केवल PowerShell (`args` जिनके अंत में `-Command` हो) और `cmd.exe` (`args` जिनके अंत में `/c` हो) चलाए जाते हैं; वहाँ कोई भी दूसरा शेल अनुमान से उद्धृत की गई आदेश-पंक्ति थमाए जाने के बजाय नाम लेकर अस्वीकार किया जाता है।
- **कोई "VS Code" कीमैप प्रोफ़ाइल नहीं है।** ऊपर के संयोजन डिफ़ॉल्ट प्रोफ़ाइल और बाकी चारों में दर्ज हैं। एक जान-बूझकर अपवाद: **Eclipse** प्रोफ़ाइल में ⇧⌘E Eclipse का अपना *Switch to Editor* ही रहता है, और संपादक के भीतर ⇧⌘P और ⇧⌘X Eclipse के अर्थ रखते हैं (मेल खाता कोष्ठक, बड़े अक्षर) — जिसने Eclipse चुना वह Eclipse की अपेक्षा करता है।
- **Linux पर Ctrl+\` टर्मिनल खोलता है, विंडो-स्विचर नहीं।** स्विचर Ctrl+Tab पर है। जो डेस्कटॉप Ctrl+Tab अपने लिए ले लेता है (जैसे KDE), उस पर **विंडो ▸ दस्तावेज़…** खुली फ़ाइलों की सूची देता है।
- **Ctrl+Alt वाले संयोजन AltGr से टकरा सकते हैं।** Windows पर जो कीबोर्ड लेआउट AltGr से अक्षर टाइप करते हैं (जैसे पोलिश), वे उसके लिए Ctrl+Alt भेजते हैं। अगर Ctrl+Alt+P या Ctrl+Alt+K आपके लिए कोई अक्षर टाइप करता है, तो *प्रोजेक्ट बदलें* या प्रयोग वाले संयोजनों को कीमैप में कहीं और ले जाइए।
- **VS Code के एक्सटेंशन यहाँ संस्थापित नहीं होते।** भाषा की समझ उन भाषा-सर्वरों से आती है जिन्हें NMOX जानता है (परिवेश डॉक्टर बताता है कि क्या ग़ायब है और उसे कैसे संस्थापित करें), संपादक के अपने व्याकरणों से, और NetBeans Platform के लिए बने प्लगिन से।
