Ця сторінка запускає один із ваших власних проєктів у NMOX Studio. Тут лише те, що для цього потрібно. Повний посібник — [посібник користувача](user-guide.uk.md). Якщо ви працюєте у VS Code, далі прочитайте [перехід із VS Code](coming-from-vscode.uk.md).

<a id="1-install-one-minute"></a>
## 1. Встановлення (одна хвилина)

**macOS, з Homebrew:**

```bash
brew trust --cask nmox/nmox-studio/nmox-studio
brew install nmox/nmox-studio/nmox-studio
```

Homebrew один раз просить виконати `brew trust` для будь-якого стороннього tap. Під час оновлень більше не питатиме.

**macOS, Windows, Linux, без Homebrew:** завантажте останній випуск для своєї системи зі [сторінки випусків](https://github.com/NMOX/NMOX-Studio/releases/latest):

| Система | Файл | Далі |
|---|---|---|
| macOS | `NMOX-Studio-<version>-macos.dmg` | Перетягніть застосунок до «Програм». |
| Windows | `NMOX-Studio-<version>-windows-setup.exe` | Запустіть інсталятор. |
| Debian, Ubuntu | `nmox-studio_<version>_amd64.deb` | `sudo apt install ./nmox-studio_<version>_amd64.deb` |
| Інший Linux | `NMOX-Studio-<version>-linux.tar.gz` | Розпакуйте й запустіть `bin/nmoxstudio`. |

Кожен із цих файлів несе власне середовище виконання Java, тож більше нічого встановлювати не треба. Лише переносний zip потребує Java 21 або новішої, уже встановленої на машині.

На macOS застосунок нотаризовано Apple. Першого разу macOS спитає, чи відкрити застосунок, завантажений з інтернету: натисніть **Відкрити**.

<a id="2-open-your-project-one-minute"></a>
## 2. Відкрийте свій проєкт (одна хвилина)

Запустіть **NMOX Studio**. Відкриються три вкладки: **Ласкаво просимо**, **Стійка задач** і **Браузер**.

Щоб відкрити проєкт, оберіть **Файл ▸ Відкрити теку…** (⌥⌘O на macOS, Ctrl+Alt+O у Windows і Linux) і вкажіть його теку. Можна й з термінала, як із `code .`:

```bash
cd ~/code/my-app
nmox .
```

Команда повертається одразу. Якщо NMOX Studio вже працює, вона отримує теку; якщо ні — запускається. Homebrew, інсталятор Windows і пакети Linux кладуть `nmox` у PATH. Для встановлення з DMG див. [як додати `nmox` у PATH](user-guide.uk.md#2-first-launch).

Тека вважається проєктом, якщо в ній є `package.json`, `Cargo.toml`, `go.mod`, `pom.xml`, `composer.json`, `pyproject.toml` або один із 57 інших файлів проєкту. Тека зі звичайними файлами HTML теж вважається.

Коли ви відкриваєте проєкт, стається три речі:

- **Студія проєкту** ліворуч показує ваші файли.
- Рядок стану внизу показує вашу гілку git і кількість змінених файлів.
- **Стійка задач** налаштовується під вид проєкту. Проєкт Vite отримує консоль Vite, проєкт Cargo — доріжки запуску, зневадження й тестів і так далі.

<a id="3-run-it-one-minute"></a>
## 3. Запустіть його (одна хвилина)

Натисніть **▶** на панелі інструментів або F6. Проєкт запуститься так, як його запускають його інструменти: скрипт `dev`, `start` чи `serve` із `package.json`, `cargo run`, `go run`. Використовується власний менеджер пакетів проєкту: npm, pnpm чи yarn, або bun для проєкту Bun.

Коли ви вперше щось запускаєте в проєкті, NMOX Studio питає, чи довіряєте ви цій теці. Проєкт, якому ви не довірилися, не виконує жодного власного коду: ні скриптів, ні збирань, ні тестів. Для власного коду натисніть **Довіряти робочій області**.

Якщо ваш проєкт — сервер розробки, його адреса з’являється в рядку стану поруч із символом **⇄**, а сторінка відкривається у вкладці **Браузер**. Змініть файл і збережіть — сторінка перезавантажиться.

Щоб зупинити все, що працює, натисніть **■** поруч із ▶ або ⌥⌘. (Option, Command і крапка).

Якщо нічого не відбувається, погляньте на вкладку **Output** унизу. Вона пояснює, чому запуск не зміг початися — наприклад, інструмент не встановлено або залежності ще не встановлені, — і пропонує це виправити. **Інструменти ▸ Діагностика середовища…** перелічує кожен інструмент, яким може користуватися NMOX Studio, і показує, які з них встановлено.

<a id="4-find-anything-thirty-seconds"></a>
## 4. Знайдіть що завгодно (тридцять секунд)

Натисніть **⌘I** (Ctrl+I у Windows і Linux) і пишіть. Швидкий пошук знаходить файли, дії меню, символи, прилади стійки, працюючі сервери й команди, а також скрипти вашого `package.json`. Ввід відкриває або запускає знайдене.

Натисніть **⌘P**, щоб відкрити файл за назвою.

<a id="5-test-it-thirty-seconds"></a>
## 5. Протестуйте його (тридцять секунд)

Натисніть **⌃F6** (Ctrl+F6), щоб запустити тести проєкту. Щоб побачити всі тести проєкту ще до запуску, відкрийте вікно **Тести** через ⌥⌘2.

<a id="if-you-have-no-project-handy"></a>
## Якщо проєкту під рукою немає

- **Файл ▸ Новий проєкт…** створює справжній проєкт із шаблону (Angular, Vue, Svelte, React з Vite, чистий JavaScript, PHP, Phoenix та інші). Він створює файли, налаштовує git і встановлює залежності.
- **Файл ▸ Новий навчальний простір…** відкриває урок із провідником. *Ваша перша вебсторінка* стоїть у списку першою.
