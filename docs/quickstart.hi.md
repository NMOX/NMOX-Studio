यह पन्ना आपके अपने किसी प्रोजेक्ट को NMOX Studio के भीतर चालू कर देता है। इसमें केवल उतना ही है जितना इसके लिए ज़रूरी है। पूरी पुस्तिका [उपयोगकर्ता मार्गदर्शिका](user-guide.hi.md) है। यदि आप VS Code इस्तेमाल करते हैं, तो इसके बाद [VS Code से आने वालों के लिए](coming-from-vscode.hi.md) पढ़िए।

<a id="1-install-one-minute"></a>
## 1. संस्थापन (एक मिनट)

**macOS, Homebrew के साथ:**

```bash
brew trust --cask nmox/nmox-studio/nmox-studio
brew install nmox/nmox-studio/nmox-studio
```

Homebrew किसी भी बाहरी tap के लिए एक बार `brew trust` चलाने को कहता है। अपडेट करते समय वह दोबारा नहीं पूछेगा।

**macOS, Windows, Linux, बिना Homebrew के:** अपने ऑपरेटिंग सिस्टम के लिए नवीनतम रिलीज़ [रिलीज़ पृष्ठ](https://github.com/NMOX/NMOX-Studio/releases/latest) से डाउनलोड कीजिए:

| ऑपरेटिंग सिस्टम | फ़ाइल | फिर |
|---|---|---|
| macOS | `NMOX-Studio-<version>-macos.dmg` | ऐप को Applications में खींचिए। |
| Windows | `NMOX-Studio-<version>-windows-setup.exe` | संस्थापक चलाइए। |
| Debian, Ubuntu | `nmox-studio_<version>_amd64.deb` | `sudo apt install ./nmox-studio_<version>_amd64.deb` |
| दूसरे Linux | `NMOX-Studio-<version>-linux.tar.gz` | इसे खोलिए और `bin/nmoxstudio` चलाइए। |

इनमें से हर फ़ाइल अपना Java रनटाइम साथ लाती है, इसलिए आपको और कुछ संस्थापित नहीं करना पड़ता। केवल portable zip को मशीन पर पहले से Java 21 या नया चाहिए।

macOS पर ऐप Apple द्वारा नोटराइज़ किया हुआ है। पहली बार खोलने पर macOS पूछता है कि इंटरनेट से डाउनलोड किया गया ऐप खोला जाए या नहीं: **खोलें** पर क्लिक कीजिए (अंग्रेज़ी macOS पर **Open**)।

<a id="2-open-your-project-one-minute"></a>
## 2. अपना प्रोजेक्ट खोलिए (एक मिनट)

**NMOX Studio** शुरू कीजिए। यह तीन टैब खोलता है: **स्वागत**, **टास्क रैक** और **ब्राउज़र**।

अपना प्रोजेक्ट खोलने के लिए **फ़ाइल ▸ फ़ोल्डर खोलें…** चुनिए (macOS पर ⌥⌘O, Windows और Linux पर Ctrl+Alt+O) और उसका फ़ोल्डर चुनिए। आप यह टर्मिनल से भी कर सकते हैं, वैसे ही जैसे `code .` के साथ करते:

```bash
cd ~/code/my-app
nmox .
```

आदेश तुरंत लौट आता है। यदि NMOX Studio पहले से चल रहा है, तो फ़ोल्डर उसे मिल जाता है; नहीं तो वह शुरू हो जाता है। Homebrew, Windows संस्थापक और Linux पैकेज `nmox` को आपके PATH पर रख देते हैं। DMG से संस्थापन हो तो [`nmox` को PATH पर लाना](user-guide.hi.md#2-first-launch) देखिए।

कोई फ़ोल्डर प्रोजेक्ट तब गिना जाता है जब उसमें `package.json`, `Cargo.toml`, `go.mod`, `pom.xml`, `composer.json`, `pyproject.toml` या 57 दूसरी प्रोजेक्ट फ़ाइलों में से कोई एक हो। सादी HTML फ़ाइलों वाला फ़ोल्डर भी गिना जाता है।

प्रोजेक्ट खोलने पर तीन बातें होती हैं:

- बाईं ओर **प्रोजेक्ट स्टूडियो** आपकी फ़ाइलें दिखाता है।
- नीचे की स्थिति-पट्टी आपकी git शाखा और बदली हुई फ़ाइलों की गिनती दिखाती है।
- **टास्क रैक** प्रोजेक्ट के प्रकार के हिसाब से तैयार हो जाता है। Vite प्रोजेक्ट को Vite कंसोल मिलता है, Cargo प्रोजेक्ट को चलाने, डिबग करने और परखने की लेनें, इत्यादि।

<a id="3-run-it-one-minute"></a>
## 3. इसे चलाइए (एक मिनट)

टूलबार पर **▶** दबाइए, या F6। यह आपके प्रोजेक्ट को वैसे ही चलाता है जैसे उसके अपने औज़ार चलाते हैं: `package.json` की `dev`, `start` या `serve` स्क्रिप्ट, `cargo run`, `go run`। यह आपके प्रोजेक्ट का अपना पैकेज प्रबंधक इस्तेमाल करता है: npm, pnpm या yarn, या Bun प्रोजेक्ट के लिए bun।

किसी प्रोजेक्ट में पहली बार कुछ भी चलाने पर NMOX Studio पूछता है कि क्या आप उस फ़ोल्डर पर भरोसा करते हैं। जिस प्रोजेक्ट पर आपने भरोसा नहीं किया, वह अपना कोई कोड नहीं चलाता: न स्क्रिप्ट, न बिल्ड, न टेस्ट। अपने कोड के लिए **वर्कस्पेस पर भरोसा करें** पर क्लिक कीजिए।

यदि आपका प्रोजेक्ट डेवलपमेंट सर्वर है, तो उसका पता स्थिति-पट्टी पर **⇄** चिह्न के बग़ल में दिखता है, और पन्ना **ब्राउज़र** टैब में खुल जाता है। कोई फ़ाइल बदलिए और सहेजिए, और पन्ना फिर से लोड हो जाता है।

जो कुछ चल रहा है सब रोकने के लिए ▶ के बग़ल वाला **■** दबाइए, या ⌥⌘. (Option, Command और पूर्ण विराम)।

अगर कुछ नहीं होता, तो नीचे **Output** टैब देखिए। वह बताता है कि रन क्यों शुरू नहीं हो सका, जैसे कि कोई औज़ार संस्थापित नहीं है या डिपेंडेंसी अभी संस्थापित नहीं हुई हैं, और उसे ठीक करने की पेशकश करता है। **उपकरण ▸ परिवेश डॉक्टर…** हर वह औज़ार गिनाता है जिसे NMOX Studio इस्तेमाल कर सकता है, और दिखाता है कि कौन-से संस्थापित हैं।

<a id="4-find-anything-thirty-seconds"></a>
## 4. कुछ भी ढूँढिए (तीस सेकंड)

**⌘I** (Windows और Linux पर Ctrl+I) दबाइए और टाइप कीजिए। त्वरित खोज फ़ाइलें, मेनू की क्रियाएँ, प्रतीक, रैक डिवाइस, चल रहे सर्वर और आदेश, और आपकी `package.json` स्क्रिप्टें ढूँढती है। परिणाम खोलने या चलाने के लिए Enter दबाइए।

किसी फ़ाइल को नाम से खोलने के लिए **⌘P** दबाइए।

<a id="5-test-it-thirty-seconds"></a>
## 5. इसे परखिए (तीस सेकंड)

अपने प्रोजेक्ट के टेस्ट चलाने के लिए **⌃F6** (Ctrl+F6) दबाइए। कोई भी चलाने से पहले प्रोजेक्ट का हर टेस्ट देखने के लिए ⌥⌘2 से **टेस्ट** विंडो खोलिए।

<a id="if-you-have-no-project-handy"></a>
## अगर आपके पास कोई प्रोजेक्ट नहीं है

- **फ़ाइल ▸ नया प्रोजेक्ट…** किसी टेम्पलेट से असली प्रोजेक्ट बनाता है (Angular, Vue, Svelte, Vite के साथ React, सादा JavaScript, PHP, Phoenix और भी)। यह फ़ाइलें बनाता है, git तैयार करता है और डिपेंडेंसी संस्थापित करता है।
- **फ़ाइल ▸ नया लर्निंग स्पेस…** एक मार्गदर्शित पाठ खोलता है। सूची में सबसे पहले *आपका पहला वेब पेज* आता है।

## आगे कहाँ जाएँ

- **[टास्क रैक](user-guide.hi.md#4-the-task-rack)**। आप जो भी औज़ार चलाते हैं वह रैक पर एक डिवाइस है, और डिवाइसों के बीच की केबल उन्हें जोड़कर शृंखला बनाती हैं: उदाहरण के लिए, जब भी बिल्ड पास हो, टेस्ट चलाइए।
- **[संपादक](user-guide.hi.md#5-the-editor)**। इसमें Emmet, रंग के नमूने, Node और Chrome के लिए ब्रेकपॉइंट डिबगिंग, और Angular टेम्पलेट शामिल हैं।
- **[स्टूडियो](user-guide.hi.md#6-the-studios)**। API, डेटाबेस, कॉन्ट्रैक्ट और ब्लॉक स्टूडियो, और टास्क बोर्ड।
- **[शब्दावली](glossary.hi.md)** उत्पाद के अपने शब्द समझाती है: रैक, पैच, जैक, लेन, लक्ष्य, KVASIR।
