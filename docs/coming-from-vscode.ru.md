Ваши руки уже знают, где что лежит. Эта страница — карта от этих
привычек к NMOX Studio: сначала сочетания клавиш, потом где живёт каждая
идея VS Code, потом что здесь честно по-другому.

Первые четыре сочетания, которые нажимает пользователь VS Code, делают
то, чего он ждёт: **⇧⌘P** открывает палитру команд, **⇧⌘E** — дерево
файлов, **⇧⌘X** — плагины, а **⌃\`** — терминал. Они записаны во всех
пяти профилях раскладки, которые поставляет платформа, и проверка при
сборке разрешает каждое из них через собранную раскладку в macOS, Windows
и Linux, чтобы вместо него не сработало ничто другое.

Каждое сочетание NMOX в таблице (⌘, — собственное сочетание меню
приложения в macOS) прочитано из поставляемой раскладки, а не по памяти.
Несколько вещей таблица не может сказать в одной клетке:

- **F5 во время отладки занята.** Здесь она значит *Продолжить*, как в
  любой IDE семейства NetBeans, поэтому отладочный запуск начинается с
  **⇧⌘F5** (Ctrl+Shift+F5) и продолжается по F5.
- **⌃R здесь — «Переименовать»**, поэтому *Сменить проект* живёт на ⌥⌘P,
  а не на сочетании Open Recent из VS Code. Переименование работает там,
  где его поддерживает язык, стоящий за файлом.
- **У «Копировать относительный путь» нет сочетания.** ⇧⌥⌘C из VS Code
  на PC — это Ctrl+Alt+Shift+C, а это *Clear Split* платформы в каждом
  профиле клавиатуры; строка есть в меню «Правка», и ⇧⌘P находит её по
  собственному названию VS Code, *File: Copy Relative Path of Active
  File*.
- **Ctrl+, в Windows и Linux** возвращает назад по истории правок, как
  всегда было в NetBeans; настройки находятся в Сервис ▸ Настройки
  (в macOS — **Settings…** в меню приложения, ⌘,).

**Справка ▸ Сочетания клавиш…** перечисляет каждое сочетание NMOX в вашей
активной раскладке, включая четыре сочетания VS Code; список читается из
работающей раскладки, поэтому не может разойтись с тем, что делают клавиши.

### Каждое сочетание для правки, проверенное

Сочетания, к которым тянутся ваши руки из VS Code во время правки, каждое
найдено в поставляемой раскладке профиля по умолчанию в macOS. Где
сочетание VS Code здесь было свободно, теперь оно делает то же, что в VS
Code (строки с пометкой **То же:**); где оно уже значило что-то, на что
полагаются пользователи NetBeans, оно сохраняет это значение, а строка
говорит, где находится действие VS Code.

| VS Code, macOS | Что делает VS Code | В NMOX Studio |
|---|---|---|
| F12 | Go to Definition | **То же:** Перейти к объявлению, как ⌘B |
| ⇧F12 | Go to References | **То же:** Найти использования, как ⌃F7 |
| F2 | Rename Symbol | **То же:** Переименовать, как ⌃R |
| ⌘. | Quick Fix | **То же:** исправления для строки, которые показывает ⌃↩ |
| ⌥↑ / ⌥↓ | Move Line Up / Down | Предыдущее / следующее отмеченное вхождение; строку перемещают ⌃⇧↑ / ⌃⇧↓ |
| ⇧⌥↑ / ⇧⌥↓ | Copy Line Up / Down | То же, как было всегда |
| ⇧⌘K | Delete Line | Вставить следующее совпадающее слово (дополняет слово из файла); строку удаляет ⌘E |
| ⌘L | Expand Line Selection | Выделить идентификатор — в раскладке по умолчанию сочетание остаётся за этим действием; «Расширить выделение на строку» (*Expand Line Selection*) есть в Быстром поиске под этим именем, а в профилях раскладки IntelliJ и Emacs, где сочетание свободно, — на самой ⌘L |
| ⇧⌘L | Select All Occurrences | Вставить как строки в редакторе; все вхождения выделяет ⌃⇧⌘J |
| ⌘/ | Toggle Line Comment | То же, как было всегда |
| ⇧⌥A | Toggle Block Comment | **То же:** заключает выделение или строку с курсором в блочные ограничители языка и снимает их обратно; выделение, в котором уже есть ограничитель, отвергается, а не ломается |
| ⌘] | Indent Line | **То же:** Сдвинуть вправо |
| ⌘[ | Outdent Line | Переход к парной скобке, как было всегда; отступ убирают ⇧Tab или ⌃⇧← |
| ⌥Z | Toggle Word Wrap | **То же:** Вид ▸ Перенос по словам. Перенос переключается для всех редакторов языка файла, а не для одной вкладки, и выбор сохраняется |
| ⌘B | Toggle Sidebar | Перейти к объявлению; ⇧⌘↩ оставляет только редактор, ⇧Esc разворачивает окно, в котором вы находитесь |
| ⌘J | Toggle Panel | Добавляет следующее вхождение в редакторе (как ⌘D); окно **Output** — ⌘4 |
| ⌘\ | Split Editor | Дополнить код в редакторе; редактор разделяет ⌃⇧⌘V |
| ⇧⌘T | Reopen Closed Editor | То же, как было всегда: сочетание «Открыть недавний файл» заново открывает последний закрытый файл |
| ⌃- / ⌃⇧- | Go Back / Go Forward | **То же:** Назад и Вперёд по местам, где вы правили, как ⌃← / ⌃→ (сочетания, которые macOS обычно оставляет за переключением рабочих столов) |
| ⌘G / ⇧⌘G | Find Next / Previous | То же, как было всегда |
| ⌥⌘F | Replace | **То же:** Заменить, как ⌘R |
| ⇧⌘F | Find in Files | То же, как было всегда: Найти в проектах |
| ⇧⌘O | Go to Symbol in Editor | Открыть проект; символы файла — в Быстром поиске: ⌘I, затем `@name`, как в VS Code (Переход ▸ Перейти к символу в этом файле… вводит `@` за вас), и деревом в Навигаторе (⌘7) |
| ⌘T | Go to Symbol in Workspace | Меняет местами две буквы у курсора в редакторе; символы проекта — ⌥⇧⌘O |
| ⌃G | Go to Line | То же, как было всегда |
| ⌘K ⌘S | Keyboard Shortcuts | ⌘K — Вставить предыдущее совпадающее слово; список — **Справка ▸ Сочетания клавиш…** |
| ⌘, | Settings | То же, как было всегда: NMOX Studio ▸ Settings… |
| ⇧⌥F | Format Document | **То же:** Форматировать, как ⌃⇧F |

Сочетания с пометкой **То же:** назначены во всех профилях раскладки, где
они свободны, а профиль, который даёт одному из них своё значение, это
значение сохраняет: F12 в профилях Eclipse, Emacs и NetBeans 5.5, F2 во
всех профилях, кроме профиля по умолчанию, ⇧F12 в Emacs и NetBeans 5.5, ⌃-
и ⌃⇧- в Emacs и IntelliJ, ⇧⌥F в IntelliJ. В Windows и Linux F12, ⇧F12 и F2
работают так же; остальные сочетания VS Code там другие, и таблица выше
приводит оба варианта.

«Закомментировать/раскомментировать блок» и «Перенос по словам» несут свои
сочетания VS Code и в Windows и Linux. «Перенос по словам» — это Alt+Z в
каждом профиле. «Закомментировать/раскомментировать блок» — это Shift+Alt+A
в профиле по умолчанию и в профилях Emacs и IntelliJ (профили Eclipse и
NetBeans 5.5 оставляют там собственное Alt+Shift+A), а в Linux ещё и
Ctrl+Shift+A, сочетание VS Code для Linux, во всех пяти. «Расширить
выделение на строку» в Windows и Linux — это Ctrl+L только в профиле
IntelliJ; в профиле Emacs Ctrl+L там остаётся собственным *recenter* Emacs.

Если в языке нет блочного комментария (например, в Python), об этом
говорит строка состояния. В файле HTML, Vue или Svelte блок `<script>` или
`<style>` комментируется как его собственный язык. Без выделения сочетание
комментирует или раскомментирует строку; комментарий, который лишь
окружает курсор, оно не ищет, поэтому, чтобы снять комментарий из
нескольких строк, выделите его.

В Быстром поиске символы файла — это категория **Символы в этом файле**.
Если набрать один `@`, они перечисляются с начала файла; `m name` (буква,
пробел, затем имя) ищет в этой категории и ни в какой другой.


<a id="from-the-terminal"></a>
## Из терминала

`code .` — это `nmox .`:

```bash
cd ~/code/my-app
nmox .          # open this folder (manifest or not) and aim the IDE at it
nmox src/app.ts # open one file
nmox src/app.ts:42  # open it at line 42 (code -g's form; -g itself is accepted)
nmox            # just start the IDE
```

Команда возвращается сразу, а второй `nmox` передаёт свою папку уже
работающей IDE. Столбец (`src/app.ts:42:7`) тоже принимается, и редактор
открывается в начале строки; имя, которого нет, отвергается прямо в
терминале, и ничего не запускается. Ключ `-r` принимается, `-n` открывает
в том же единственном окне, а `-a` и `-v` отвергаются по имени.

`-w` (`--wait`) открывает файл и ждёт, пока вы не закроете его вкладку, а `-d`
(`--diff`) сравнивает два файла бок о бок, так что NMOX Studio может быть
редактором, difftool и mergetool для git, как `code --wait`:

```bash
git config --global core.editor "nmox -w"
git config --global diff.tool nmox
git config --global difftool.nmox.cmd 'nmox -w -d "$LOCAL" "$REMOTE"'
git config --global merge.tool nmox
git config --global mergetool.nmox.cmd 'nmox -w "$MERGED"'
git config --global mergetool.nmox.trustExitCode false
```

Тогда `git commit` открывает сообщение в IDE; сохраните его и закройте
вкладку, и git продолжит. Выход из IDE, пока файл ещё открыт, тоже
возвращает его — с тем, что было сохранено.
`git mergetool` открывает каждый файл с конфликтом так же. Там, где VS Code
ставит над конфликтом *Accept Current Change | Accept Incoming Change | Accept
Both Changes*, NMOX Studio подкрашивает обе стороны и ставит предупреждение на
строку `<<<<<<<`; лампочка на полях или быстрое исправление с курсором на этой
строке (⌘. на Mac, Alt+Enter в остальных системах) предлагают те же три
варианта, каждый — одна отменяемая правка. Сохраните, закройте вкладку, и git
перейдёт к следующему файлу. Подсветка и три варианта есть в любом файле с
маркерами конфликта, с `git mergetool` или без него.
**Команда ▸ Использовать NMOX Studio с Git…** выставляет те же строки за вас,
сначала показав, чему равна каждая из них сейчас.
Homebrew, установщик Windows (*Add "nmox" to PATH*) и
пакеты Linux ставят её в PATH; для установки из DMG
[руководство пользователя](user-guide.ru.md#2-first-launch) показывает
ссылку в одну строку.

<a id="where-each-vs-code-idea-lives"></a>
## Где живёт каждая идея VS Code

| В VS Code | В NMOX Studio |
|---|---|
| **Explorer** | **Студия проекта** (⇧⌘E) — дерево файлов (правый щелчок по файлу даёт «Копировать путь», «Копировать относительный путь» и «Показать в Finder»), шаблоны и редактор `package.json` проекта. **Рабочее место** (⌥⌘0) — домашняя база: открытые файлы, недавние файлы, недавние проекты и всё, что работает. |
| **Command Palette** | **Быстрый поиск** (⇧⌘P или ⌘I) — действия, файлы, недавние проекты, устройства стойки, активные серверы, запросы Студии API, символы. Работают и имена команд самого VS Code: *Format Document*, *Toggle Terminal*, *Git: Commit* или *Open Settings* показывает действие, которое делает здесь то же самое, в разделе **Команды VS Code** — с его собственным именем и сочетанием клавиш. |
| **Extensions** | **Сервис ▸ Плагины** устанавливает и обновляет модули, включая собственные обновления NMOX. Расширения VS Code здесь не устанавливаются, поэтому **Сервис ▸ Рекомендуемые расширения VS Code…** отвечает на вопрос, который ставит `.vscode/extensions.json` репозитория: что в NMOX Studio делает работу каждого рекомендованного расширения — встроенная функция, окно, которое оттуда можно открыть, устройство стойки, языковой сервер (и установлен ли он) или ничего; о расширении, которого NMOX Studio не знает, так и сказано, что оно неизвестно, без догадок. Многое из того, что в VS Code добавляет расширение, здесь — **устройство стойки**, и его можно написать файлом JSON в `~/.nmox/devices.d` ([файлы устройств](device-files.md)). |
| **`tasks.json`** | `.vscode/tasks.json` вашего репозитория читается: наберите имя задачи в Быстром поиске (⇧⌘P или ⌘I), и Ввод на *Запустить задачу: build — make all* запускает её (или выберите её в списке, который показывает **Запуск ▸ Запустить задачу…**); на проекте, которому вы ещё не доверяете, сначала спросит Доверие рабочей области, вывод идёт в окно **Output**, а остановит её ■ на панели инструментов. Задачи, названные в её `dependsOn`, выполняются первыми, `${file}` — это файл, открытый в редакторе, а `${input:…}` спрашивает вас до того, как что-либо запустится. Рядом собственные скрипты проекта запускаются так, как они написаны: Запуск / Сборка / Тесты на панели инструментов (F6, F11, ⌃F6), **Запустить скрипт** на строке раздела scripts в `package.json`, **Обозреватель NPM** и **Стойка задач** (⌘9), где задачи — это устройства, которые вы соединяете. |
| **`launch.json`** | `.vscode/launch.json` вашего репозитория читается: наберите имя конфигурации в Быстром поиске (⇧⌘P или ⌘I), и Ввод на *Отладить: Launch Program — ${workspaceFolder}/server.js* запускает отладчик с точками останова на этой программе (те же конфигурации перечисляет **Отладка ▸ Начать отладку…**), а сначала спросит Доверие рабочей области. Конфигурации Node (`node`, `pwa-node`) отлаживают свой `program` в своём `cwd`, со своими `args`, своими `env` и `envFile`, под своими `runtimeExecutable` и `runtimeArgs` — так что конфигурация с `npm run dev`, `tsx` или `--experimental-strip-types` запускается так, как она написана, — а `"request": "attach"` для Node подключается к процессу `node --inspect` на этом компьютере. Конфигурации Python (`python`, `debugpy`) отлаживают свой `program` с `args`, `env`, `envFile` и интерпретатором, который называет их `python`; конфигурации Chrome (`chrome`, `pwa-chrome`) открывают свой `url` (или `file`) со своим `webRoot`. `"program": "${file}"` отлаживает файл, который показывает ваш редактор, а `preLaunchTask`, называющая задачу из вашего `tasks.json`, выполняется первой: отладчик запускается, когда задача завершилась успешно. Без `launch.json` **Отладить файл** (⇧⌘F5) и кнопка отладки на панели инструментов сами понимают, что запускать, по самому проекту — точка входа скрипта `start`, `main`, `index.js`, — а устройство стойки **INSPECTOR** запускает отладчик как шаг конвейера. |
| **Integrated terminal** | Окно **Терминал** (⌃\`): первое нажатие запускает оболочку в папке проекта, следующие возвращают к ней. |
| **`settings.json`** | Сервис ▸ Настройки (в macOS — NMOX Studio ▸ Settings…). `.vscode/settings.json` репозитория тоже читается: `editor.tabSize`, `editor.insertSpaces` и `editor.indentSize` задают отступы его файлов, пока вы печатаете, `files.trimTrailingWhitespace` и `files.insertFinalNewline` (когда они `true`) действуют при сохранении, `files.eol` задаёт окончания строк, с которыми записываются файлы, `"editor.formatOnSave": false` не даёт сохранению переформатировать файл, а языковой блок вроде `"[typescript]"` переопределяет их для своего языка. Если в репозитории есть и `.editorconfig`, то `.editorconfig` побеждает везде, где высказываются оба. |
| **Problems panel** | **Задачи** (⌘6) или щелчок по счётчику **✕ ⚠** в строке состояния: ошибки и предупреждения языковых серверов, а также находки линтера и проверки типов от устройств стойки PURITY и TYPEGUARD. Как и в VS Code, некоторые серверы сообщают только об открытых файлах; gopls сообщает обо всём пакете. |
| **Search view** (`search.useIgnoreFiles`) | **Найти в проектах** (⇧⌘F). Как и в VS Code, поиск пропускает то, что игнорируют файлы `.gitignore` репозитория и `.git/info/exclude`, поэтому `node_modules` и `dist/` не попадают в результаты, если они перечислены в `.gitignore`; вне репозитория он пропускает по имени `node_modules`, `dist`, `build` и другие папки сборки. Отметьте **Искать в сгенерированных исходниках** в его диалоге, чтобы искать и в них. Ваш глобальный файл исключений git не читается. |
| **Outline** | **Навигатор** (⌘7). |
| **Snippets** (`.vscode/*.code-snippets`) | Файлы фрагментов кода, которые закоммитила ваша команда, читаются как есть: наберите префикс, нажмите ⌃Space, и фрагмент появится в списке как *префикс — Имя (описание)*, с именем своего файла рядом, и только в тех языках, которые называет его `scope`. Когда вы его принимаете, вставляется тело фрагмента с его позициями табуляции, зеркалами, переменными (`TM_FILENAME`, `CURRENT_YEAR`, `UUID` и прочими) и преобразованиями `/regex/format/`; Tab обходит позиции по кругу, а Ввод идёт к следующей и после последней останавливается на `$0`. |
| **Auto Save** (`files.autoSave`) | **Файл ▸ Автосохранение** включает и выключает его; как часто оно сохраняет и сохраняет ли ещё и тогда, когда файл теряет фокус, задаётся в настройках, на вкладке «Автосохранение» категории «Редактор». Это ваше личное предпочтение: `files.autoSave` репозитория не читается. |
| **Markdown preview** | Вкладка **Предпросмотр** вверху редактора Markdown, рядом с вкладкой **Исходный код**. |
| **Timeline** (local history) | Вкладка **История** вверху каждого редактора: версии файла, которые IDE сохраняла при ваших сохранениях; каждую можно сравнить с файлом в его нынешнем виде и восстановить. |
| **Breadcrumbs** | **Вид ▸ Показывать навигационную цепочку**. |

| **Workspace Trust** | Та же идея, соблюдаемая до того, как запустится что-либо, выбранное репозиторием: открытие клонированного проекта не запускает ничего, пока вы ему не доверитесь. |
| **Keyboard Shortcuts editor** | Сервис ▸ Настройки ▸ Сочетания клавиш (в macOS — Settings… ▸ Сочетания клавиш) — измените любое сочетание или переключите весь профиль на Eclipse, Emacs или IntelliJ. |

Когда вы впервые открываете репозиторий, в котором есть
`.vscode/tasks.json`, `launch.json`, `settings.json` или
`extensions.json`, уведомление говорит, что найдено и где это лежит;
щелчок по нему открывает Быстрый поиск (а для расширений — таблицу,
которая говорит, что заменяет каждое из них). Для каждого проекта оно
появляется один раз.

<a id="what-is-honestly-different"></a>
## Что здесь честно по-другому

- **В профиле по умолчанию ⌘D добавляет следующее вхождение, но не во всех
  профилях.** Профиль Eclipse оставляет ⌘D за *Delete Line* Eclipse,
  профиль NetBeans 5.5 — за *Shift Line Left*, а профиль Emacs — за *kill
  word* (и Ctrl+D — за *delete character* в Windows и Linux); в профиле
  IntelliJ ⌘D работает в macOS, а Ctrl+D в Windows и Linux остаётся за
  *Duplicate Line*. Второе сочетание для этого жеста тоже зависит от
  профиля: ⌘J (Ctrl+J) в профиле по умолчанию, ⌃J (Alt+J) в Eclipse и
  IntelliJ и никакого в Emacs и NetBeans 5.5, где его можно назначить в
  «Сочетаниях клавиш».
- **⌃\` открывает Терминал и переводит на него фокус, но не прячет его.**
  А пока фокус в Терминале, клавиши принадлежат вашей оболочке, поэтому
  второе нажатие достаётся оболочке, а не возвращает вас в редактор.
- **`launch.json` читается, а то, что отладчик не может выполнить,
  отвергается.** Отладчик здесь передаёт программу, её рабочую папку, её
  `args` (список строк), её `env` и `envFile` и среду выполнения, которая
  её запускает (`runtimeExecutable` и `runtimeArgs` для Node, `python`
  для Python); для Node он ещё и подключается к уже работающему процессу.
  Конфигурация, в которой заданы `postDebugTask`, `restart` или любое
  другое поле, которому его не научили, показывается в списке, но не
  запускается: Ввод называет эти поля в строке состояния. Запустить
  программу без них значило бы отлаживать не то, что написано в файле.
  Так же отвергаются `args` или `runtimeArgs`, записанные одной строкой
  (такую строку VS Code отдаёт оболочке), и значение `null` в `env` (оно
  удаляет переменную), а также запись `compounds`, тип, для которого
  здесь нет адаптера (`go`, `msedge`, `cppdbg` и прочие), подключение к
  чему-либо, кроме Node, значение, которое может подставить только
  VS Code (`${input:…}`, `${command:…}`), и программа, рабочая папка или
  `envFile` за пределами проекта. Поля, которые лишь меняют то, что
  показывает отладчик, — `skipFiles`, `outFiles`, `sourceMaps`,
  `console`, `justMyCode`, `presentation`, — принимаются, но не
  применяются; вывод программы идёт в окно Output. Пять вещей стоит
  знать до того, как нажать Ввод:
  - **`preLaunchTask` выполняется первой и должна завершиться успешно.**
    Задача выполняется так, как её выполнил бы Ввод на ней в Быстром
    поиске, — с задачами из её `dependsOn`, её вопросами, её собственной
    вкладкой в окне Output, — а отладчик запускается, когда она
    завершилась с кодом выхода 0; там, где VS Code после неудавшейся
    задачи спрашивает *Debug Anyway?*, здесь строка состояния говорит,
    что конфигурация не запущена. `program`, который задача собирает
    (`dist/server.js`), ищется после задачи, а не до неё. Метка, которую
    `tasks.json` не определяет, метка, общая для двух задач, запись
    объектом (`{"type": "npm", "script": "build"}`) и фоновая задача
    (`"isBackground": true`, наблюдатель, который никогда не завершается)
    отвергаются по имени до того, как что-либо запустится.
  - **`envFile`, которого нет, отвергается**, тогда как VS Code запускает
    программу без него. Его переменные добавляются к окружению, а запись
    в `env` побеждает файл, как в VS Code. Файл читается как простые
    строки `NAME=value` (строки-комментарии, `export` и одна пара кавычек
    вокруг значения допустимы); строка, которую VS Code прочитал бы
    иначе, — экранирование внутри двойных кавычек, `#` после значения,
    обратный апостроф, а в конфигурации Python ещё `export` или
    `${NAME}` — отвергается с указанием файла и номера строки, но
    никогда не значения.
  - **`${file}`, `${relativeFile}`, `${fileBasename}`,
    `${fileBasenameNoExtension}`, `${fileExtname}`, `${fileDirname}` и
    остальные файловые переменные означают файл активного редактора**:
    вкладку с фокусом, если это редактор, а иначе вкладку, показанную в
    области редактора, — тот же файл, который означает `${file}` в
    задаче. Если ни один файл не открыт, конфигурация отвергается с
    указанием переменной, а `${file}` за пределами проекта отвергается,
    как любая другая программа там.
  - **`runtimeExecutable` — это имя или абсолютный путь.** Имя (`npm`,
    `tsx`, `nodemon`) ищется в вашем PATH, а затем в `node_modules/.bin`
    проекта; `${workspaceFolder}/node_modules/.bin/tsx` должен
    существовать; относительный путь отвергается, потому что VS Code
    искал бы его как имя. Когда среда выполнения — это вся команда
    (`npm run dev` без `program`), скрипт, который она запускает,
    отлаживается как отдельный сеанс, показанный в окне Sessions.
  - **Подключение — только к этому компьютеру.** `port` (9229, если не
    записан) и `address`, равный `localhost`, `127.0.0.1` или `::1`;
    любой другой адрес отвергается, потому что это не удалённая
    разработка. Если никто не слушает, об этом говорит строка состояния,
    а завершение сеанса оставляет вашу программу работать.
- **`tasks.json` читается, а то, что нельзя выполнить так, как написано,
  отвергается.** Задача выполняется после задач из её `dependsOn` (они
  идут вместе или, с `"dependsOrder": "sequence"`, одна за другой),
  причём `${file}`, `${relativeFile}`, `${lineNumber}`, `${selectedText}`
  и остальные переменные этого семейства заполняются по файлу, открытому
  в редакторе, а её вопросы `${input:…}` (`promptString`, `pickString`)
  задаются до того, как что-либо запустится. Весь запуск решается
  заранее: если хотя бы одну его задачу нельзя выполнить так, как
  написано, не запускается ничего, а Ввод говорит в строке состояния,
  какая это задача и почему. Так происходит с меткой в `dependsOn`,
  которую файл не определяет, с зависимостью, которая оказалась фоновой
  задачей (сопоставители проблем не читаются, поэтому нечему сказать,
  когда она готова), с `${file}`, когда ни один файл не открыт, и с
  вопросом, который вы отменили. Зависимость, завершившаяся неудачей,
  останавливает запуск на этом месте. По-прежнему отвергаются по имени:
  значение, которое может подставить только VS Code (`${config:…}`,
  `${command:…}`, входное значение с `"type": "command"`), зависимость,
  записанная объектом (`{"type": "npm", …}`), а не меткой, тип задачи,
  который даёт расширение (`gulp`, `typescript`), и рабочая папка за
  пределами проекта.
- **Фрагменты кода — те, что лежат в вашем репозитории, и три вещи здесь
  иначе.** Выбор (`${1|a,b|}`) начинается со своего первого варианта, без
  списка для выбора; заполнитель, вложенный в значение по умолчанию
  другого заполнителя, становится частью этого значения; а фрагмент,
  преобразование которого нельзя выполнить безопасно (регулярное
  выражение, которое Java не может скомпилировать или которое могло бы
  выполняться бесконечно), пропускается и называется в журнале, а не
  вставляется наполовину. Ввод префикса сам список не открывает: его
  открывает ⌃Space. Фрагменты без `prefix`, пользовательские фрагменты и
  `isFileTemplate` не читаются.
- **Задача `"type": "shell"` выполняется в той оболочке, которую взял бы
  VS Code.** В macOS и Linux это ваш `$SHELL` с `-c` (zsh, bash или fish в
  macOS стартуют как оболочка входа, `-l`, как в профилях VS Code по
  умолчанию); в Windows — PowerShell, `pwsh`, если он установлен.
  `options.shell` соблюдается так, как это делает VS Code: укажите
  `executable`, и оболочка запустится ровно с теми `args`, что вы дали,
  так что bash нужен `"args": ["-c"]`. В Windows запускаются только
  PowerShell (аргументы оканчиваются на `-Command`) и `cmd.exe` (аргументы
  оканчиваются на `/c`); любая другая оболочка там отвергается по имени, а
  не получает командную строку, закавыченную наугад.
- **Профиля раскладки «VS Code» нет.** Сочетания выше записаны в профиль
  по умолчанию и в четыре остальных. Одно намеренное исключение: в профиле
  **Eclipse** ⇧⌘E остаётся собственным *Switch to Editor* Eclipse, а
  внутри редактора ⇧⌘P и ⇧⌘X сохраняют значения Eclipse (парная скобка,
  верхний регистр) — выбравший Eclipse ждёт Eclipse.
- **В Linux Ctrl+\` открывает Терминал, а не переключатель окон.**
  Переключатель находится на Ctrl+Tab. На рабочем столе, который забирает
  Ctrl+Tab себе (например, KDE), открытые файлы перечисляет
  **Окно ▸ Документы…**.
- **Сочетания с Ctrl+Alt могут столкнуться с AltGr.** В Windows раскладки,
  которые печатают символы через AltGr (например, польская), посылают вместо
  него Ctrl+Alt. Если Ctrl+Alt+P или Ctrl+Alt+K печатает вам символ,
  перенесите *Сменить проект* или сочетания экспериментов в разделе настроек «Сочетания клавиш».
- **Расширения VS Code здесь не устанавливаются.** Языковой интеллект
  берётся из языковых серверов, которые знает NMOX (Диагностика окружения
  перечисляет, чего не хватает и как это установить), из собственных
  грамматик редактора и из плагинов, созданных для платформы NetBeans.
