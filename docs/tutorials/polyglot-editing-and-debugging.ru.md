NMOX Studio правит более 70 языков с настоящей подсветкой синтаксиса,
структурой в Навигаторе и интеллектом языковых серверов — и сразу, без
настройки, отлаживает JavaScript/TypeScript (и браузер) с точками
останова, которые действительно останавливают. В этом уроке мы попадём в
точку останова в приложении Node.

![Сработала точка останова в JavaScript: выполнение приостановлено, стек вызовов Node и живые переменные V8](../images/debug-javascript.png)

## Перед началом

Откройте (или создайте) небольшой проект Node со скриптом, который можно
запустить, — например, маршрут Express или простой `node server.js`.

## Шаги

1. **Откройте исходный файл.** Подсветка, парные скобки, сворачивание кода
   и выделение вхождений включаются сами. **Навигатор** показывает
   структуру файла; языковые серверы (устанавливаются по подсказкам
   `Сервис ▸ Диагностика окружения…`) добавляют дополнение и диагностику.

2. **Поставьте точку останова.** Щёлкните по левому полю редактора на
   строке внутри обработчика — появится отметка точки останова.

3. **Запустите отладку файла.** Выберите **Отладить файл (точки
   останова)** (или «Отладка в Chrome (точки останова)» для страницы
   HTML/JS). Разовый запрос «Доверие рабочей области» охраняет запуск;
   затем встроенный адаптер `js-debug` запускает вашу программу.

4. **Попадите в точку останова.** Пройдите по нужному пути кода
   (отправьте запрос или дайте скрипту дойти до строки). Выполнение
   **останавливается** на вашей точке — смотрите переменные, ходите по
   стеку вызовов, шагайте с обходом или с заходом. При отладке в браузере
   Chrome открывается на одноразовом профиле по адресу вашего живого
   сервера разработки, а точки останова на странице отображаются обратно
   в IDE.

## Что вы узнали

- Редактор считает полноправными более 70 языков (грамматики TextMate +
  CSL + LSP); файлы настроек (YAML, TOML, Dockerfile, nginx…) тоже
  охвачены.
- Отладка JS/TS встроена: мультиплексор сеансов разворачивает дочерние
  сеансы `js-debug` в один, чтобы им мог управлять односеансовый
  отладчик платформы.
- Каждый отладочный запуск проходит через доверие и при остановке
  убивается целым деревом процессов (никаких сирот).
