Студія баз даних — набір для SQLite, PostgreSQL, MySQL/MariaDB, MongoDB і
CouchDB: вбудовані драйвери, консоль, що знає рушій, і таблиці результатів,
які можна редагувати на місці. Цей урок використовує SQLite, бо йому не
потрібен сервер.

![Підключення SQLite, запит, живі рядки в таблиці — і рядок стану з чесною причиною, коли таблиця лише для читання](../images/db-studio.png)

## Як відкрити

`⌥⌘7` або вкладка **Студія баз даних**.

## Кроки

1. **Створіть підключення SQLite.** Натисніть **Додати**, оберіть
   **SQLite** і вкажіть шлях до файлу (діалог у стилі збереження дає
   створити новий `.db`). Підключення з’явиться в дереві підключень.

2. **Виконайте трохи SQL.** Наберіть у консолі й виконайте:

   ```sql
   CREATE TABLE users (id INTEGER PRIMARY KEY, name TEXT, active BOOLEAN);
   INSERT INTO users (name, active) VALUES ('Ada', 1), ('Bob', 0);
   SELECT * FROM users;
   ```

   Кожна інструкція отримує власну таблицю результатів нижче, з часом виконання.

3. **Змініть рядок у таблиці.** Двічі клацніть клітинку `name` у рядку Bob,
   змініть її й натисніть **Застосувати…**. Студія баз даних дозволяє правки в
   таблиці лише тоді, коли може побудувати безпечний однорядковий `UPDATE`
   (одна таблиця, є первинний ключ), — вона показує точний SQL перед
   виконанням, а потім перезапитує дані, щоб показати правду.
   Якщо рядок не можна змінити безпечно, вона каже чому.

4. **Експортуйте.** Натисніть **CSV** або **JSON** на будь-якій таблиці
   результатів. Експорт у CSV сам знешкоджує ін’єкції формул електронних таблиць.

5. **EXPLAIN для запиту.** Виділіть `SELECT` і натисніть **EXPLAIN** —
   отримаєте рідний план запиту рушія.

6. **Нехай KVASIR пояснить невдачу.** Виконайте `SELECT * FROM user;`
   (зверніть увагу на помилку в назві). Під повідомленням про помилку з’явиться
   кнопка **Пояснити…**. Натисніть її — і діалог згоди назве рівно те, що
   буде надіслано: виконаний SQL (разом із будь-якими літеральними
   значеннями в ньому), повідомлення про помилку й тип рушія; ніколи —
   підключення, пароль чи будь-які рядки. Погодьтеся — і KVASIR пояснить
   помилку й запропонує виправлення у вікні бесіди, де можна ставити
   уточнювальні запитання.

## Що ви щойно дізналися

- Паролі живуть лише у в’язці ключів ОС, ніколи в `.nmoxdb.json`.
- Консоль знає рушій: SQL для рушіїв SQL, консоль JSON-документів для
  MongoDB/CouchDB.
- Історія та збережені запити зберігаються для кожного проєкту; файли `.env`
  самі пропонують свої підключення `DATABASE_URL`/`DB_*`.
