*ביצוע commit, סקירה, פתרון, הצעה — בלי לעבור לכלי אחר.*

השעה הראשונה היא לפתוח פרויקט ולהריץ אותו. השבוע השני הוא כל מה שמסביב
לקוד: עשרים commits ביום, diff לקרוא לפני כל אחד מהם, התנגשות אחרי pull,
בקשת משיכה אחרי push, עקבת מחסנית לרדוף אחריה, README שצריך להישאר כן.
הסיור הזה הוא ישיבה אחת במאגר git שכבר יש לכם, וכל צעד בו הוא משהו
שתעשו שוב מחר.

## 1. הפכו את NMOX Studio לעורך של git

**עשו:** צוות ‏◂‏ **שימוש ב־NMOX Studio עם Git…**

**ראו:** שש ההגדרות הגלובליות של git שהופכות את NMOX Studio לעורך, ל‑difftool
ול‑mergetool של git, כל אחת לצד הערך שיש לה **עכשיו**, כך ששום דבר לא
מוחלף בלי שתראו. **החלה** קובעת אותן (**סגירה** היא לחצן ברירת המחדל, כי
זה כותב את תצורת ה‑git הגלובלית שלכם); **העתקת הפקודות** שמה במקום זאת
את שורות ה‑`git config` בלוח. כש‑git כבר משתמש ב‑NMOX Studio, תיבת
הדו‑שיח אומרת זאת ולא מציעה החלה.

אותן שורות, אם אתם מעדיפים מסוף:

```bash
git config --global core.editor "nmox -w"
git config --global diff.tool nmox
git config --global difftool.nmox.cmd 'nmox -w -d "$LOCAL" "$REMOTE"'
git config --global merge.tool nmox
git config --global mergetool.nmox.cmd 'nmox -w "$MERGED"'
git config --global mergetool.nmox.trustExitCode false
```

## 2. בצעו commit

**עשו:** שנו קובץ, ואז במסוף:

```bash
git commit -a
```

**ראו:** הודעת ה‑commit נפתחת ב‑NMOX Studio, ושורת המצב אומרת שמסוף
מחכה לה. שורות ה‑`#` של git הן הערות; רק מה שאתם כותבים עובר בדיקת
איות; שורת סיכום ארוכה מ‑72 תווים, המקום שבו הכלים של git עצמו חותכים
אותה, מקבלת אזהרה אחרי התו ה‑72. שמרו, סגרו את הלשונית, וה‑commit
נכנס — המסוף חיכה עד שתעשו את זה. יציאה מה‑IDE כשההודעה עדיין פתוחה
מחזירה אותה ל‑git גם כן, עם מה שנשמר.

גם ‎`git rebase -i` פותח את הרשימה שלו באותה דרך: כל פקודה וכל commit
מודגשים, ו‑**החלפת מצב הערה** מוציאה שורה בלי למחוק אותה.

## 3. דעו איפה אתם עומדים

**ראו:** **השבב ⎇** בשורת המצב — ‎`⎇ main ±3 ↑2 ↓1` הוא הענף שלכם,
שלושה קבצים שהשתנו, שני commits לדחיפה ואחד למשיכה (החצים מופיעים רק
כשיש מה לדחוף או למשוך). התפריט שלו מתחיל ב‑**החלפת ענף…**, ב‑**ביצוע commit…**, ב‑**משיכה (pull)…** וב‑**דחיפה (push)…**.

**עשו:** הציבו את הסמן על שורה כלשהי בקובץ שנמצא במעקב.

**ראו:** לצד השבב, מי שינה את השורה הזו לאחרונה, לפני כמה זמן ולמה:
`Ada Lovelace, לפני 3 ימים · Fix the parser`. שורה שעוד לא ביצעתם לה
commit אומרת זאת, וקובץ עם שינויים שלא נשמרו אומר את זה במקום לנקוב בשם
המחבר הלא נכון. לחצו על ההערה כדי לראות את הייחוס של הקובץ כולו;
**תצוגה ‏◂‏ מחבר השורה** מכבה אותה.

## 4. סקרו diff

**עשו:**

```bash
git difftool
```

**ראו:** כל קובץ שהשתנה, זה לצד זה, בתצוגת ההבדלים של NMOX Studio, עם
**ההבדל הקודם / ההבדל הבא** ו"הבדל 2 מתוך 5" מעליה. קובץ שנוסף או נמחק
מציג את הצד החסר שלו כחלונית ריקה ("אין קובץ"); קובץ בינארי מוצג כבינארי,
והסרגל אומר אם שני קבצים בינאריים שונים. סגרו את הלשונית ו‑git עובר לקובץ
הבא.

## 5. פתרו התנגשות

**עשו:** מזגו ענף שמתנגש, ואז:

```bash
git mergetool
```

**ראו:** הקובץ שבהתנגשות בעורך, הצד הנוכחי והצד הנכנס צבועים, ואזהרה על
כל שורת ‎`<<<<<<<`‎. הציבו עליה את הסמן ולחצו ⌘. ‏(Alt+Enter במקומות
אחרים), או השתמשו ב‑**קוד מקור ‏◂‏ תיקון קוד…**: **קבלת השינוי הנוכחי**,
**קבלת השינוי הנכנס** או **קבלת שני השינויים**, כל אחת עריכה אחת שאפשר
לבטל. בלוק שהשתנה מאז ההצעה נדחה במקום שינחשו אותו. שמרו, סגרו את
הלשונית וענו ל‑git.

## 6. הציעו את זה

**עשו:** דחפו, ואז צוות ‏◂‏ **בקשת משיכה חדשה ב‑GitHub** (גם בתפריט של
השבב).

**ראו:** דף ה‑New Pull Request של GitHub עצמו עבור הענף שלכם, בדפדפן
שלכם, שבו אתם מחוברים. מתוך עורך, **עריכה ‏◂‏ פתיחה ב‑GitHub**
ו‑**העתקת קישור ל‑GitHub** נותנות את השורה או השורות שאתם עומדים עליהן;
בעץ של אולפן הפרויקטים הן נותנות קובץ או תיקייה.

## 7. רדפו אחרי כישלון

**עשו:** הריצו את הבדיקות שלכם במסוף (⌃\`) עד שאחת נכשלת.

**ראו:** מיקום בפלט — `src/app.ts:42:7`, מסגרת מחסנית
‎`(/abs/app.js:10:5)`‎, ‎`--> src/main.rs:3:5`, `File "x.py", line 12` —
נפתח בשורה ובעמודה האלה בלחיצת ⌘ ‏(לחיצת Ctrl ב‑Windows וב‑Linux). כתובת
URL או `localhost:3000` אף פעם אינן קישור, ונתיב שלא קיים נדחה בשמו במקום
שינחשו אותו.

## 8. שמרו על README כן

**עשו:** כלים ‏◂‏ **בדיקת קישורי Markdown…**

**ראו:** כל קישור יחסי וכל תמונה ב‑Markdown של הפרויקט נבדקים כפי
ש‑GitHub מציג אותם — הקובץ חייב להתקיים, ו‑‎`#heading` חייב להיות
כותרת של אותו קובץ. קישור מת הוא שגיאה, כותרת חסרה היא אזהרה, שניהם כקווים
מסולסלים וב‑פריטי פעולה, עם משפט אחד בשורת המצב. שום דבר לא יוצא
מהמחשב שלכם: קישור עם סכמה לא נבדק.

## 9. מסרו את זה לסוכן

**עשו:** כלים ‏◂‏ **Agent Port ‏(MCP)…**‏, סמנו **שמירת הכתובת והאסימון
האלה**, ואז **העתקה עבור Claude Code**, והריצו את השורה שהועתקה פעם אחת.

**ראו:** סוכן שיכול לקרוא את מה שה‑IDE יודע — הפרויקט שמכוונים אליו, מה
מוגש ומה רץ, מה אתם עורכים, הכישלון האחרון — ושעדיין מתחבר מחר, כי האסימון
נשמר במחזיק המפתחות של המערכת שלכם והפורט חוזר לשימוש. הפורט נשאר לקריאה
בלבד מעצם התכנון. ביטול הסימון של **שמירת הכתובת והאסימון האלה** מוחק את
הרשומה ממחזיק המפתחות.

## מה עשיתם

כתבתם הודעת commit, קראתם diff, פתרתם התנגשות, פתחתם בקשת משיכה, גיליתם
מי כתב שורה, עקבתם אחרי עקבת מחסנית ובדקתם README — הכול בחלון שבו כבר
הייתם. שום דבר מזה לא החליף את git: כל צעד הוא הצעד של git עצמו, נפתח
במקום שבו אתם עובדים.
