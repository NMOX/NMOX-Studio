Панель Docker — пульт управления локальным движком Docker: контейнеры,
образы, тома, сети, — а также вкладка **Dockerize**, которая создаёт для
вашего проекта промышленный Dockerfile. Её двойник в стойке — прибор
**HARBOR**.

![Движок запущен, работает контейнер postgres — индикатор состояния, порты и ряд действий: запуск, остановка, журналы, осмотр](../images/docker-panel.png)

## Перед началом

Docker должен работать локально (`docker version` должна выполняться
успешно; `Сервис ▸ Диагностика окружения…` это подтвердит).

## Шаги

1. **Откройте панель.** Нажмите `⌘8` или щёлкните **Панель Docker** в
   столбце ИНСТРУМЕНТЫ страницы приветствия. Обзор **Движок** показывает,
   работает ли демон.

2. **Осмотрите контейнеры.** Вкладка **Контейнеры** перечисляет то, что
   работает, — имена, образы, порты, состояние. У **Образов**, **Томов** и
   **Сетей** свои вкладки.

3. **Соберите Docker-обвязку для проекта.** Откройте вкладку
   **Dockerize**, наведясь на проект. Она создаёт промышленный
   `Dockerfile`, `.dockerignore` и файл `compose`, подогнанные под ваш
   инструментарий (многоэтапная сборка для Node, `php-fpm` с соседним
   nginx для PHP и т. д.), — и никогда не затирает существующие файлы
   (если файл уже есть, рядом пишется `.suggested`).

4. **Получите подключение к БД.** Если работает контейнер с базой данных,
   Студия баз данных сама предложит к нему подключение — по имени образа,
   а затем по порту, по одному разу на контейнер.

## Что вы узнали

- Панель — настоящая асинхронная обёртка над CLI `docker`; о зависшем
  демоне она сообщает, а не зависает вместе с ним.
- Dockerize знает ваш инструментарий и идемпотентен.

## Дальше

- Поставьте **HARBOR** в стойку, чтобы PANEL/PRUNE/REFRESH были под рукой
  на лицевой панели.
- Подключитесь к базе в контейнере из [Студии баз данных](db-studio.ru.md).
