# Урок: напишите свой прибор для стойки

*За один присест. Вы добавите в стойку прибор с помощью текстового
редактора, нажмёте его кнопку, увидите, как он выполняет настоящую
команду, и подключите его вывод к MONITOR — не написав ни строчки на Java.*

Новое в 2.0.0. Стойка поставлялась с пятьюдесятью тремя приборами, и до
сих пор добавить пятьдесят четвёртый можно было одним способом: написать
плагин для NetBeans. Это другой способ.

![Стойка задач: слева полка приборов, где рядом со встроенными появляется прибор из ~/.nmox/devices.d](../images/tabs/the-task-rack.png)

## 1. Создайте папку

```bash
mkdir -p ~/.nmox/devices.d
```

Это вся установка. Стойка читает папку лениво, так что перезапускать
ничего не нужно.

## 2. Опишите прибор

Положите это в `~/.nmox/devices.d/counter.json`:

```json
{
  "id": "com.example.counter",
  "title": "COUNTER",
  "tagline": "counts the files in the project",
  "accent": "#7FB3D5",
  "category": "OBSERVE",
  "usage": "COUNT lists the project's files of the dialled KIND and shows how many.\nPatch OUT into MONITOR to read the list, or DONE onward to chain.",
  "knobs": [
    { "key": "kind", "label": "KIND", "options": ["js", "ts", "css", "md"] }
  ],
  "ports": [
    { "id": "count", "label": "COUNT", "direction": "IN", "signal": "TRIGGER" },
    { "id": "done", "label": "DONE", "direction": "OUT", "signal": "TRIGGER" },
    { "id": "out", "label": "OUT", "direction": "OUT", "signal": "DATA" }
  ],
  "buttons": [
    { "label": "COUNT", "role": "QUERY",
      "command": ["git", "ls-files", "*.{{kind}}"],
      "emit": "done", "trigger": "count" }
  ]
}
```

Здесь каждая строчка работает: **ручка** становится `{{kind}}` в
команде, роль **QUERY** красит кнопку в синий (закон цвета: синий
спрашивает, зелёный делает, красный останавливает), а два порта делают
прибор подключаемым.

## 3. Поставьте его в стойку

Откройте **Стойку задач** (`⌘9` или вкладка «Стойка задач») и загляните
в ящик полки **Наблюдение**. COUNTER уже там, под ним ваш слоган.
Перетащите его на рельс.

Наведите указатель на его карточку «Как использовать» — это ваш текст
`usage`, и именно поэтому формат требует двух настоящих строк.

## 4. Нажмите

> Обратите внимание: строки `units` нет. Полка измеряет переднюю панель
> и выбирает наименьшую высоту, в которую она помещается (этому прибору
> из-за ручки нужно 2U). Указывайте `units`, только когда хотите лишнего
> места.

Наведите стойку на git-проект, поверните **KIND** на `js` и нажмите
**COUNT**.

Первое нажатие вызывает запрос **Доверие рабочей области**: файл прибора
выполняет настоящие команды, и хозяин охраняет каждый запуск так же, как
у встроенного прибора. Разрешите — и ЖК-экран покажет команду, а затем
последнюю строку вывода. Гнездо DONE мигнёт зелёным.

Откажите — и ничего не запустится. Отказ и есть задуманное поведение.

## 5. Подключите его

Протяните кабель от **OUT** прибора COUNTER к **TAP** прибора MONITOR.
Нажмите COUNT ещё раз: каждая строка попадёт на монитор, потому что
объявленный порт `OUT`/`DATA` получает вывод запуска без дополнительной
настройки.

Теперь протяните кабель от тика TEMPO ко входу **COUNT** прибора COUNTER.
Прибор, который вы написали в текстовом редакторе, теперь работает по
часам.

## 6. Сломайте его нарочно

Отредактируйте файл и замените команду на что-нибудь с конвейером:

```json
"command": ["sh", "-c", "git ls-files | wc -l"]
```

Сохраните — и COUNTER *исчезнет* с полки. Это формат отказывается от
строки оболочки: команда — это массив аргументов, чтобы читатель (вы
через полгода или коллега на ревью) видел ровно то, что будет выполнено.
Журнал IDE называет пропущенный файл и причину:

```
device file counter.json skipped: button "COUNT" command token
"git ls-files | wc -l" contains "|" — commands are argv, never a shell line
```

Верните форму массива — и прибор вернётся. То же самое с инструментом,
указанным по пути (`./x.sh`), с неизвестной `{{variable}}` или с
однострочным `usage`: файл пропускается целиком, а не загружается
наполовину, потому что прибор с лживой надписью хуже, чем никакого.

## Что вы узнали

- Прибор — это **файл**: `~/.nmox/devices.d/*.json`, читается лениво,
  без перезапуска и без сборки.
- Ручки становятся `{{variables}}`; роли выбирают цвета; порты делают
  прибор подключаемым, а его вывод — читаемым.
- **Законы держит хозяин**: доверие рабочей области при каждом запуске,
  закон цвета, словарь портов, закон полки. Поэтому файл прибора не
  может выразить неохраняемую команду или красную кнопку GO, даже если
  попытается.
- Отказы громко звучат в журнале и действуют полностью.
