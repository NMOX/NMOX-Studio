Студия API читает файлы, которые у вас уже есть: коллекцию или
окружение Postman, экспорт Insomnia v4 (структура рабочего пространства и
`{{ _.templates }}` переводятся), запись HAR из инструментов разработчика,
команду curl, файл `.http`, спецификацию OpenAPI.
В этом разборе мы проведём настоящий экспорт Postman от начала до конца —
и покажем то единственное, что NMOX Studio намеренно делает иначе:
**секреты попадают в связку ключей ОС, а не в файл для репозитория.**

![Студия API, куда попадает импорт: дерево коллекций, отправленный запрос и его оценка заголовков безопасности](../images/api-studio.png)

## Перед началом

Экспортируйте коллекцию из Postman: коллекция ▸ … ▸ Export ▸
**Collection v2.1**. (Экспорт v1 отклоняется с прямым указанием, что
делать, — экспортируйте заново как v2.1.) Окружения экспортируются
отдельно и импортируются через **Импорт… ▸ Окружение Postman…**: обычные
значения переносятся, импорт с тем же именем сливается, не затирая уже
заданное, а значения, которые Postman помечает как *secret*, остаются
снаружи — с пометкой, указывающей на поле Auth в связке ключей, потому
что окружения Студии API живут в `.nmoxapi.json`, который кладут в
репозиторий.

## Шаги

1. **Откройте Студию API** (⌥⌘8) и нажмите **Импорт… ▸ Коллекция
   Postman…**. Выберите экспортированный `.json`.

2. **Проверьте, что пришло.** Папки сохраняются в именах вида
   «Папка / Запрос». Переменные Postman `{{variables}}` импортируются *как есть* —
   это собственный синтаксис Студии API, — а переменные коллекции
   вливаются в активное окружение, ничего уже заданного не затирая.
   Переменные пути `:id` становятся `{{id}}`.

3. **Загляните на вкладку Auth у запроса, где был bearer-токен.** Токен
   *там* — но пришёл он через поле Auth в связке ключей, а не строкой
   заголовка. Кладите `.nmoxapi.json` в репозиторий спокойно: секрета в
   нём нет. Всё, что импорт не смог представить (тела multipart, скрипты),
   названо в строке состояния и никогда не искажено молча.

4. **Импортируйте запись из браузера.** На вкладке Network инструментов
   разработчика выберите «Save all as HAR», затем **Импорт… ▸ Запись
   HAR…**. Импортируется только ваш трафик XHR/fetch (ресурсы страницы
   пересчитываются вслух), сеансовые cookie отбрасываются — записанная
   cookie есть учётные данные, — а записанный заголовок `Authorization`
   либо уходит в связку ключей (Bearer/Basic), либо отбрасывается и
   учитывается в подсчёте (всё непрозрачное).

5. **Отправьте один запрос.** Выберите импортированный запрос, при
   необходимости задайте `{{baseUrl}}` в окружении и нажмите
   **Отправить** — а заодно прочтите оценку заголовков безопасности на
   вкладке «Стандарты».

6. **Пройдите в обратную сторону.** **Импорт… ▸ Экспортировать коллекцию
   в .http…** записывает всю коллекцию на диалекте REST Client для любого
   редактора или раннера CI. Авторизации в файле намеренно нет; у каждого
   запроса с авторизацией есть комментарий, называющий, что добавить
   обратно.

## Что вы узнали

- Переезд — это одно меню: на вход curl / `.http` / OpenAPI / Postman /
  HAR, на выход `.http`.
- Закон о секретах соблюдается на каждой границе: пришло в связку ключей —
  там и остаётся.
- Отказы называются, а не замалчиваются: если что-то не импортировалось,
  строка состояния скажет, что и почему.
