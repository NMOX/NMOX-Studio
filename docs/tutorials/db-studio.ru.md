Студия баз данных — набор для работы с SQLite, PostgreSQL, MySQL/MariaDB,
MongoDB и CouchDB: встроенные драйверы, консоль, знающая движок, и
таблицы результатов, которые можно править на месте. В этом уроке мы
возьмём SQLite, потому что ему не нужен сервер.

![Подключение к SQLite, запрос, живые строки в таблице — и строка состояния, честно называющая причину, когда таблица доступна только для чтения](../images/db-studio.png)

## Как открыть

`⌥⌘7` или вкладка **Студия баз данных**.

## Шаги

1. **Создайте подключение к SQLite.** Нажмите **Добавить**, выберите
   **SQLite** и укажите путь к файлу (диалог в стиле «Сохранить» позволяет
   создать новый `.db`). Подключение появится в дереве.

2. **Выполните SQL.** Наберите в консоли и выполните:

   ```sql
   CREATE TABLE users (id INTEGER PRIMARY KEY, name TEXT, active BOOLEAN);
   INSERT INTO users (name, active) VALUES ('Ada', 1), ('Bob', 0);
   SELECT * FROM users;
   ```

   Каждый оператор получает свою таблицу результатов ниже, со временем
   выполнения.

3. **Измените строку в таблице.** Дважды щёлкните ячейку `name` у Bob,
   поменяйте значение и нажмите **Применить**. Студия баз данных
   разрешает правку в таблице, только когда может построить безопасный
   `UPDATE` для одной строки (одна таблица, есть первичный ключ): она
   показывает точный SQL до выполнения, а потом заново делает запрос,
   чтобы показать истинное состояние. Если строку нельзя безопасно
   изменить, студия скажет почему.

4. **Экспортируйте.** Правый щелчок по любой таблице → экспорт в CSV или
   JSON. При экспорте в CSV формулы, опасные для электронных таблиц,
   обезвреживаются автоматически.

5. **Посмотрите план запроса.** Выделите `SELECT` и нажмите **EXPLAIN** —
   получите план запроса на родном языке движка.

6. **Пусть KVASIR объяснит сбой.** Выполните `SELECT * FROM user;`
   (обратите внимание на опечатку). Под сообщением об ошибке появится
   кнопка **Объяснить…**. Нажмите её — диалог согласия назовёт ровно то,
   что будет отправлено: выполненный SQL (включая литеральные значения в
   нём), сообщение об ошибке и тип движка; никогда — подключение, пароль
   или строки. Согласитесь — и KVASIR объяснит ошибку и предложит
   исправление в окне беседы, где можно задавать уточняющие вопросы.

## Что вы узнали

- Пароли хранятся только в связке ключей ОС и никогда — в `.nmoxdb.json`.
- Консоль знает движок: SQL для SQL-движков и консоль документов JSON для
  MongoDB/CouchDB.
- История и сохранённые запросы хранятся по проекту; файлы `.env` сами
  предлагают подключения из `DATABASE_URL`/`DB_*`.
