*कमिट, समीक्षा, सुलझाना, प्रस्ताव — किसी दूसरे टूल पर गए बिना।*

पहला घंटा है कोई प्रोजेक्ट खोलना और उसे चलाना। दूसरा हफ़्ता है कोड के आसपास
का सब कुछ: दिन में बीस कमिट, हर एक से पहले पढ़ने को एक diff, pull के बाद एक
टकराव, push के बाद एक पुल रिक्वेस्ट, पीछा करने को एक स्टैक ट्रेस, ईमानदार
रखने को एक README। यह पूरा चक्कर उस git रिपॉज़िटरी में एक बैठक है जो आपके पास
पहले से है, और हर कदम ऐसा है जो आप कल फिर करेंगे।

## 1. NMOX Studio को git का एडिटर बनाइए

**करें:** टीम ▸ **NMOX Studio को Git के साथ इस्तेमाल करें…**

**देखें:** git की वे छह वैश्विक सेटिंग्स जो NMOX Studio को git का एडिटर,
difftool और mergetool बनाती हैं, हर एक उस मान के बगल में जो उसका **अभी** है,
ताकि बिना दिखे कुछ भी न बदले। **लागू करें** उन्हें सेट करता है (**बंद करें**
डिफ़ॉल्ट बटन है, क्योंकि यह आपका वैश्विक git कॉन्फ़िगरेशन लिखता है); **कमांड
कॉपी करें** इसके बजाय `git config` की पंक्तियाँ क्लिपबोर्ड पर रख देता है। जब
git पहले से NMOX Studio इस्तेमाल करता है, तो संवाद यही बताता है और लागू करें
नहीं देता।

वही पंक्तियाँ, अगर आप टर्मिनल पसंद करते हैं:

```bash
git config --global core.editor "nmox -w"
git config --global diff.tool nmox
git config --global difftool.nmox.cmd 'nmox -w -d "$LOCAL" "$REMOTE"'
git config --global merge.tool nmox
git config --global mergetool.nmox.cmd 'nmox -w "$MERGED"'
git config --global mergetool.nmox.trustExitCode false
```

## 2. कमिट कीजिए

**करें:** कोई फ़ाइल बदलिए, फिर किसी टर्मिनल में:

```bash
git commit -a
```

**देखें:** कमिट संदेश NMOX Studio में खुलता है, और स्थिति-पट्टी बताती है कि एक
टर्मिनल उसका इंतज़ार कर रहा है। git की `#` वाली पंक्तियाँ टिप्पणियाँ हैं; वर्तनी
सिर्फ़ उसी की जाँची जाती है जो आप लिखते हैं; 72 अक्षरों से लंबी सारांश-पंक्ति,
जहाँ git के अपने टूल उसे काटते हैं, 72वें के बाद चेतावनी पाती है। सहेजिए, टैब
बंद कीजिए, और कमिट हो जाता है — टर्मिनल तब तक रुका था जब तक आपने यह नहीं
किया। संदेश खुला रहते IDE छोड़ने पर भी वह git को लौट जाता है, जितना सहेजा गया
था उसके साथ।

`git rebase -i` अपनी सूची इसी तरह खोलता है: हर कमांड और हर कमिट हाइलाइट होता
है, और **कमेंट टॉगल करें** किसी पंक्ति को मिटाए बिना हटा देता है।

## 3. जानिए कि आप कहाँ खड़े हैं

**देखें:** स्थिति-पट्टी पर **⎇ चिह्न** — `⎇ main ±3 ↑2 ↓1` आपकी ब्रांच है, तीन
बदली हुई फ़ाइलें, push करने को दो कमिट और pull करने को एक (तीर सिर्फ़ तभी दिखते
हैं जब push या pull करने को कुछ हो)। इसका मेन्यू **ब्रांच बदलें…** और **कमिट
करें…** से शुरू होता है।

**करें:** किसी ट्रैक की गई फ़ाइल की किसी भी पंक्ति पर कर्सर रखिए।

**देखें:** चिह्न के बगल में, वह पंक्ति आख़िरी बार किसने बदली, कितने समय पहले
और क्यों: `Ada Lovelace, 3 दिन पहले · Fix the parser`। जो पंक्ति आपने अभी
कमिट नहीं की, वह यही कहती है, और बिना सहेजे बदलावों वाली फ़ाइल ग़लत लेखक का
नाम लेने के बजाय यही बताती है। पूरी फ़ाइल की टिप्पणियों के लिए नोट पर क्लिक
कीजिए; **दृश्य ▸ पंक्ति का लेखक** इसे बंद करता है।

## 4. किसी diff की समीक्षा कीजिए

**करें:**

```bash
git difftool
```

**देखें:** हर बदली हुई फ़ाइल NMOX Studio के diff दृश्य में अगल-बगल, ऊपर
**पिछला अंतर / अगला अंतर** और “अंतर 2 / 5” के साथ। जोड़ी गई या मिटाई गई फ़ाइल
अपनी ग़ायब तरफ़ को एक ख़ाली पैन (“कोई फ़ाइल नहीं”) के रूप में दिखाती है; बाइनरी
फ़ाइल बाइनरी के रूप में दिखती है, और पट्टी बताती है कि दो बाइनरी अलग हैं या
नहीं। टैब बंद कीजिए और git अगली फ़ाइल पर चला जाता है।

## 5. किसी टकराव को सुलझाइए

**करें:** कोई ऐसी ब्रांच मर्ज कीजिए जो टकराती हो, फिर:

```bash
git mergetool
```

**देखें:** टकराव वाली फ़ाइल एडिटर में, मौजूदा और आने वाली तरफ़ें रंगी हुई, और
हर `<<<<<<<` पंक्ति पर एक चेतावनी। उस पर कर्सर रखकर ⌘. दबाइए (बाक़ी जगह
Alt+Enter), या **स्रोत ▸ कोड ठीक करें…** इस्तेमाल कीजिए: **मौजूदा बदलाव
स्वीकार करें**, **आने वाला बदलाव स्वीकार करें** या **दोनों बदलाव स्वीकार करें**,
हर एक एक ही ऐसा संपादन जिसे पूर्ववत किया जा सकता है। जो ब्लॉक पेशकश के बाद से
बदल गया हो, उसे अंदाज़ा लगाने के बजाय अस्वीकार किया जाता है। सहेजिए, टैब बंद
कीजिए और git को जवाब दीजिए।

## 6. प्रस्ताव रखिए

**करें:** push कीजिए, फिर टीम ▸ **GitHub पर नया पुल रिक्वेस्ट** (चिह्न के
मेन्यू में भी)।

**देखें:** आपकी ब्रांच के लिए GitHub का अपना New Pull Request पेज, आपके अपने
ब्राउज़र में, जहाँ आप साइन इन हैं। एडिटर से, **संपादन ▸ GitHub पर खोलें** और
**GitHub लिंक कॉपी करें** वह पंक्ति या पंक्तियाँ देते हैं जिन पर आप हैं;
प्रोजेक्ट स्टूडियो के ट्री पर वे एक फ़ाइल या फ़ोल्डर देते हैं।

## 7. किसी विफलता का पीछा कीजिए

**करें:** अपने टेस्ट टर्मिनल (⌃\`) में तब तक चलाइए जब तक कोई विफल न हो।

**देखें:** आउटपुट में कोई स्थान — `src/app.ts:42:7`, एक स्टैक फ़्रेम
`(/abs/app.js:10:5)`, `--> src/main.rs:3:5`, `File "x.py", line 12` — ⌘-क्लिक
पर (Windows और Linux पर Ctrl-क्लिक) उसी पंक्ति और कॉलम पर खुलता है। कोई URL या
`localhost:3000` कभी लिंक नहीं होता, और जो पथ मौजूद नहीं है उसे अंदाज़ा लगाने के
बजाय नाम लेकर अस्वीकार किया जाता है।

## 8. README को ईमानदार रखिए

**करें:** उपकरण ▸ **Markdown लिंक जाँचें…**

**देखें:** प्रोजेक्ट के Markdown का हर सापेक्ष लिंक और हर चित्र उसी तरह जाँचा
जाता है जैसे GitHub उसे दिखाता है — फ़ाइल मौजूद होनी चाहिए, और `#heading` उस
फ़ाइल का कोई शीर्षक होना चाहिए। मरा हुआ लिंक एक त्रुटि है, ग़ायब शीर्षक एक
चेतावनी, दोनों लहरदार रेखाओं के रूप में और कार्य आइटम में, स्थिति-पट्टी पर एक
वाक्य के साथ। आपकी मशीन से कुछ बाहर नहीं जाता: स्कीम वाला लिंक नहीं जाँचा
जाता।

## 9. किसी एजेंट को सौंपिए

**करें:** उपकरण ▸ **Agent Port (MCP)…**, **यह पता और टोकन रखें** चुनिए, फिर
**Claude Code के लिए कॉपी करें**, और कॉपी की गई पंक्ति एक बार चलाइए।

**देखें:** एक एजेंट जो पढ़ सकता है कि IDE क्या जानता है — लक्षित प्रोजेक्ट, क्या
सर्व हो रहा है और क्या चल रहा है, आप क्या संपादित कर रहे हैं, पिछली विफलता — और
कल भी जुड़ जाता है, क्योंकि टोकन आपके सिस्टम के कीचेन में रखा जाता है और पोर्ट
दोबारा इस्तेमाल होता है। पोर्ट रचना से ही केवल-पठनीय रहता है। **यह पता और टोकन
रखें** का चयन हटाने पर कीचेन की प्रविष्टि मिट जाती है।

## आपने क्या किया

आपने एक कमिट संदेश लिखा, एक diff पढ़ा, एक टकराव सुलझाया, एक पुल रिक्वेस्ट
खोला, पता लगाया कि एक पंक्ति किसने लिखी, एक स्टैक ट्रेस का पीछा किया और एक
README जाँचा — सब उसी विंडो में जिसमें आप पहले से थे। इनमें से किसी ने git की
जगह नहीं ली: हर कदम git का अपना है, वहीं खुला जहाँ आप काम करते हैं।
