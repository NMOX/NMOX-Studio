# Урок: Image Kit (Web) — стисніть свої зображення

Зображення зазвичай найважче, що віддає сайт. Image Kit знаходить JPEG і
PNG вашого проєкту й стискає їх для вебу: менші сусідні `.min.jpg`
перекодуванням на чистій Java (нічого не треба встановлювати),
необов’язкове зменшення і сусідні `.webp` через ваш власний `cwebp`, якщо
його встановлено. Під час живої перевірки цього випуску шпалера на
17,8 МБ стала `.min.jpg` на 347 КБ і `.webp` на 342 КБ —
на 98% менше.

## Закони, яких він дотримується

- **Оригінали ніколи не чіпаються.** Результати лягають поряд
  (`photo.min.jpg`, `photo.webp`), а результат, що вже існує, пропускається
  з поясненням — ніколи не затирається.
- **«Оптимізація», що нічого не заощаджує, відкидається**: стиснення, яке
  звільняє менше 10%, видаляється й позначається як *вже щільне* —
  замість того щоб віддати більший «оптимізований» файл. (Зменшений
  результат лишається в будь-якому разі — менше пікселів і було метою.)
- **Перекодування PNG свідомо немає.** ImageIO не переможе справжнього
  оптимізатора PNG, тож для PNG чесний виграш — сусідній WebP.

## Кроки

1. **Націльтеся на проєкт** і оберіть **Файл ▸ Додати до проєкту ▸ Image Kit (Web)…**.
   Діалог скаже, скільки зображень знайдено і скільки вони важать разом
   (node_modules і результати збірки пропускаються, так само як і його
   власні результати `.min.` — стискати вже стиснене означало б накопичувати втрати).

2. **Оберіть стиснення.** Якість JPEG (85 — візуально без втрат / 80 —
   типово для вебу / 70 — агресивно), необов’язкова максимальна ширина
   (2560 — retina-банер / 1600 — контент / 800 — мініатюри) і — якщо `cwebp`
   є у вашому PATH — сусідні WebP. Якщо його немає, прапорець про це скаже
   й підкаже, де взяти (`brew install webp`); Діагностика середовища теж
   його перевіряє.

3. **Прочитайте звіт.** Для кожного файлу: що записано, розміри до → після
   або чесна причина, чому нічого не записано («вже існує», «вже щільне»).
   Загальна кількість заощаджених байтів — угорі, разом із готовим до
   копіювання фрагментом `<picture>`, який віддає WebP там, де його
   підтримують, і повертається до оригіналу деінде.

## Що ви щойно дізналися

- Оптимізація зображень для вебу без жодних обов’язкових інструментів — і з
  вашим власним `cwebp`, коли він є.
- Закони родини наборів — «ніколи не затирати» й «чесний звіт» — діють і
  для пікселів.
