# ट्यूटोरियल: अपना रैक डिवाइस लिखिए

*एक ही बैठक में। आप एक टेक्स्ट एडिटर से रैक में एक डिवाइस जोड़ेंगे, उसका
बटन दबाएँगे, उसे एक असली कमांड चलाते देखेंगे, और उसका आउटपुट MONITOR
से जोड़ेंगे — Java की एक भी पंक्ति लिखे बिना।*

2.0.0 में नया। रैक तिरपन डिवाइस के साथ आया था, और अब तक चौवनवाँ
जोड़ने का एक ही तरीका था: NetBeans प्लगइन लिखना। यह दूसरा तरीका है।

![टास्क रैक: बाईं ओर की डिवाइस शेल्फ़, जहाँ ~/.nmox/devices.d का डिवाइस अंतर्निहित डिवाइस के बगल में दिखता है](../images/tabs/the-task-rack.png)

## 1. फ़ोल्डर बनाइए

```bash
mkdir -p ~/.nmox/devices.d
```

इंस्टॉल का पूरा क़दम बस इतना है। रैक यह फ़ोल्डर ज़रूरत पड़ने पर पढ़ता है,
इसलिए कुछ भी दोबारा शुरू नहीं करना पड़ता।

## 2. डिवाइस लिखिए

यह `~/.nmox/devices.d/counter.json` में रखिए:

```json
{
  "id": "com.example.counter",
  "title": "COUNTER",
  "tagline": "counts the files in the project",
  "accent": "#7FB3D5",
  "category": "OBSERVE",
  "usage": "COUNT lists the project's files of the dialled KIND and shows how many.\nPatch OUT into MONITOR to read the list, or DONE onward to chain.",
  "knobs": [
    { "key": "kind", "label": "KIND", "options": ["js", "ts", "css", "md"] }
  ],
  "ports": [
    { "id": "count", "label": "COUNT", "direction": "IN", "signal": "TRIGGER" },
    { "id": "done", "label": "DONE", "direction": "OUT", "signal": "TRIGGER" },
    { "id": "out", "label": "OUT", "direction": "OUT", "signal": "DATA" }
  ],
  "buttons": [
    { "label": "COUNT", "role": "QUERY",
      "command": ["git", "ls-files", "*.{{kind}}"],
      "emit": "done", "trigger": "count" }
  ]
}
```

इसकी हर चीज़ कोई काम कर रही है: **घुंडी** कमांड में `{{kind}}` बन जाती है,
**QUERY** भूमिका बटन को नीला रंगती है (रंग का नियम: नीला पूछता है, हरा
करता है, लाल रोकता है), और तीनों पोर्ट उसे केबल से जोड़ने लायक बनाते हैं।

## 3. उसे लगाइए

**टास्क रैक** खोलिए (`⌘9`, या टास्क रैक टैब) और शेल्फ़ की **निगरानी**
दराज़ में देखिए। COUNTER वहाँ है, नीचे आपकी टैगलाइन के साथ। उसे किसी
रेल पर खींच लाइए।

उस पर राइट-क्लिक करके **COUNTER का उपयोग कैसे करें…** चुनिए — वह आपका `usage` पाठ है,
और इसीलिए फ़ॉर्मेट दो असली पंक्तियों पर ज़ोर देता है।

## 4. उसे दबाइए

> ध्यान दीजिए कि कोई `units` पंक्ति नहीं है: शेल्फ़ मुखपट को नापती है
> और वह सबसे छोटी ऊँचाई चुनती है जिसमें वह समा जाए (इसे घुंडी के लिए
> 2U चाहिए)। `units` तभी घोषित कीजिए जब आपको अतिरिक्त जगह चाहिए।

रैक को किसी git प्रोजेक्ट पर लक्षित कीजिए, **KIND** को `js` पर घुमाइए, और
**COUNT** दबाइए।

पहली बार दबाने पर **वर्कस्पेस ट्रस्ट** का संकेत आता है, क्योंकि डिवाइस फ़ाइल
असली कमांड चलाती है और मेज़बान हर प्रक्रिया को ठीक वैसे ही जाँचता है जैसे
किसी अंतर्निहित डिवाइस की। अनुमति दीजिए, और LCD पहले कमांड दिखाता है,
फिर आउटपुट की आख़िरी पंक्ति। DONE जैक हरा चमकता है।

इसके बजाय मना कर दीजिए और कुछ भी शुरू नहीं होता — यह इनकार ही सुविधा है।

## 5. उसे जोड़िए

COUNTER के **OUT** से MONITOR के **IN** तक एक केबल खींचिए। COUNT फिर से
दबाइए: हर पंक्ति मॉनिटर पर आती है, क्योंकि घोषित `OUT`/`DATA` पोर्ट को
चलने का आउटपुट बिना किसी अतिरिक्त कॉन्फ़िगरेशन के मिल जाता है।

अब TEMPO के tick से COUNTER के **COUNT** इनपुट तक खींचिए। जो डिवाइस
आपने टेक्स्ट एडिटर में लिखा था, वह अब घड़ी पर चल रहा है।

## 6. जान-बूझकर तोड़िए

फ़ाइल संपादित कीजिए और कमांड को पाइप वाली किसी चीज़ में बदल दीजिए:

```json
"command": ["sh", "-c", "git ls-files | wc -l"]
```

सेव कीजिए, और COUNTER शेल्फ़ से *ग़ायब* हो जाता है। यह फ़ॉर्मेट का शेल
पंक्ति से इनकार है: कमांड एक argv सूची है, ताकि पढ़ने वाला — छह महीने बाद
आप, या फ़ाइल की समीक्षा करता कोई साथी — ठीक-ठीक देख सके कि क्या चलेगा।
IDE लॉग बताता है कि कौन-सी फ़ाइल छोड़ी गई और क्यों:

```
device file counter.json skipped: button "COUNT" command token
"git ls-files | wc -l" contains "|" — commands are argv, never a shell line
```

सूची वाला रूप वापस रखिए और वह लौट आता है। यही बात पाथ से नामित टूल
(`./x.sh`), किसी अनजान `{{variable}}`, या एक पंक्ति वाले `usage` पर भी
लागू होती है: फ़ाइल आधी लोड होने के बजाय पूरी छोड़ दी जाती है, क्योंकि
जिस डिवाइस का लेबल झूठ बोले, वह डिवाइस न होने से भी बुरा है।

## आपने अभी क्या सीखा

- डिवाइस एक **फ़ाइल** है: `~/.nmox/devices.d/*.json`, ज़रूरत पर पढ़ी जाती
  है, न पुनःआरंभ, न बिल्ड।
- घुंडियाँ `{{variables}}` बनती हैं; भूमिकाएँ रंग चुनती हैं; पोर्ट उसे
  जोड़ने लायक और उसका आउटपुट पढ़ने लायक बनाते हैं।
- **नियम मेज़बान के पास रहते हैं** — हर प्रक्रिया पर वर्कस्पेस ट्रस्ट, रंग
  का नियम, पोर्ट की शब्दावली, शेल्फ़ का नियम — इसलिए डिवाइस फ़ाइल चाहकर
  भी बिना जाँच की कमांड या लाल GO नहीं लिख सकती।
- इनकार लॉग में ज़ोर से बोलते हैं और असर में पूरे होते हैं।
