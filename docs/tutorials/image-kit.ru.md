# Урок: Image Kit (Web) — ужмите свои изображения

Изображения обычно самое тяжёлое, что отдаёт сайт. Image Kit находит
JPEG и PNG вашего проекта и ужимает их для веба: рядом появляются меньшие
`.min.jpg` — перекодирование на чистой Java, ставить ничего не нужно, —
по желанию уменьшенные по размеру, а если у вас установлен `cwebp`, то и
соседние `.webp`. В живой проверке для этого выпуска обои на 17,8 МБ
превратились в `.min.jpg` на 347 КБ и `.webp` на 342 КБ — на 98 % меньше.

## Правила, которые он соблюдает

- **Оригиналы никогда не трогаются.** Результаты лежат рядом
  (`photo.min.jpg`, `photo.webp`), а уже существующий результат
  пропускается с пояснением — и никогда не затирается.
- **«Оптимизация», которая ничего не экономит, выбрасывается:** если сжатие
  отыгрывает меньше 10 %, файл удаляется, а в отчёте значится *уже
  плотно* — вместо того чтобы отдать «оптимизированный» файл большего
  размера. (Уменьшенный по размеру результат сохраняется в любом случае —
  смысл был именно в меньшем числе пикселей.)
- **Перекодирования PNG нет — сознательно.** ImageIO не обыграет
  настоящий оптимизатор PNG, поэтому для PNG честный выигрыш — соседний
  WebP.

## Шаги

1. **Наведитесь на проект** и выберите **Файл ▸ Добавить в проект ▸
   Image Kit (Web)…**. Диалог сообщит, сколько изображений найдено и
   сколько они весят вместе (node_modules и результаты сборки
   пропускаются, как и собственные результаты `.min.` — сжимать уже
   сжатое значит накапливать потери).

2. **Выберите степень сжатия.** Качество JPEG (85 — визуально без потерь /
   80 — обычное для веба / 70 — агрессивное), при желании максимальная
   ширина (2560 — большая картинка для retina / 1600 — контент / 800 —
   миниатюры) и — если `cwebp` есть в PATH — соседние WebP. Если его нет,
   флажок так и скажет и подскажет, где его взять (`brew install webp`);
   Диагностика окружения тоже его проверяет.

3. **Прочтите отчёт.** По каждому файлу: что записано, размер до → после
   или честная причина, почему ничего не записано («уже существует»,
   «уже плотно»). Вверху — общая сэкономленная величина и готовый к
   копированию фрагмент `<picture>`, который отдаёт WebP там, где он
   поддерживается, и откатывается на оригинал.

## Что вы узнали

- Оптимизация изображений для веба без обязательных инструментов — и с
  вашим собственным `cwebp`, когда он есть.
- Правила семейства наборов «никогда не затирать» и «честный отчёт»
  действуют и на пиксели.
