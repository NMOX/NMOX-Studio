*اعملوا commit، وراجعوا، وحلّوا، واقترحوا — من غير ما تروحوا لأداة تانية.*

الساعة الأولى هي إنكم تفتحوا مشروع وتشغّلوه. الأسبوع التاني هو كل اللي حوالين
الكود: عشرين commit في اليوم، وdiff تقروه قبل كل واحد، وتعارض بعد الـ pull،
وطلب سحب بعد الـ push، وstack trace تدوّروا وراه، وREADME لازم يفضل صادق.
الجولة دي قعدة واحدة في مستودع git عندكم أصلًا، وكل خطوة فيها حاجة هتعملوها
تاني بكرة.

## 1. خلّوا NMOX Studio محرر git

**اعملوا:** الفريق ‏◂‏ **استخدام NMOX Studio مع Git…**

**هتشوفوا:** إعدادات git العامة الستة اللي بتخلّي NMOX Studio المحرر والـ
difftool والـ mergetool بتوع git، كل واحد جنب القيمة اللي عنده **دلوقتي**،
عشان مفيش حاجة تتغيّر من غير ما تشوفوها. **تطبيق** بيظبطها (**قفل** هو الزرار
الافتراضي، لأن ده بيكتب إعدادات git العامة بتاعتكم)؛ و**نسخ الأوامر** بدل كده
بيحط سطور الـ `git config` في الحافظة. ولو git بيستخدم NMOX Studio أصلًا،
الديالوج بيقول كده ومش بيعرض تطبيق.

نفس السطور، لو بتفضّلوا الترمينال:

```bash
git config --global core.editor "nmox -w"
git config --global diff.tool nmox
git config --global difftool.nmox.cmd 'nmox -w -d "$LOCAL" "$REMOTE"'
git config --global merge.tool nmox
git config --global mergetool.nmox.cmd 'nmox -w "$MERGED"'
git config --global mergetool.nmox.trustExitCode false
```

## 2. اعملوا commit

**اعملوا:** غيّروا ملف، وبعدين في الترمينال:

```bash
git commit -a
```

**هتشوفوا:** رسالة الـ commit بتتفتح في NMOX Studio، وشريط الحالة بيقول إن
فيه ترمينال مستنيها. سطور الـ `#` بتاعة git تعليقات؛ الإملاء بيتفحص في اللي
إنتوا بتكتبوه بس؛ وسطر الملخص اللي أطول من 72 حرف، المكان اللي أدوات git نفسها
بتقصّه عنده، بياخد تحذير بعد الحرف الـ 72. احفظوا، واقفلوا التبويب، والـ commit
يتعمل — الترمينال كان مستني لحد ما تعملوا كده. ولو خرجتوا من الـ IDE والرسالة
لسه مفتوحة، بترجع لـ git برضه، باللي كان محفوظ.

وكمان ‎`git rebase -i` بيفتح القايمة بتاعته بنفس الطريقة: كل أمر وكل commit
متعلّم عليه، و**تبديل التعليق** بيشيل سطر من غير ما يمسحه.

## 3. اعرفوا إنتوا واقفين فين

**هتشوفوا:** **شارة ⎇** في شريط الحالة — ‎`⎇ main ±3 ↑2 ↓1` هو الفرع
بتاعكم، وتلات ملفات متغيّرة، واتنين commit محتاجين push وواحد محتاج pull
(الأسهم بتظهر بس لما يبقى فيه حاجة تتعمل لها push أو pull). القايمة بتاعتها
بتبدأ بـ **تبديل الفرع…**، و**عمل commit…**، و**عمل pull…** و**عمل push…**.

**اعملوا:** حطّوا المؤشر على أي سطر في ملف متتبَّع.

**هتشوفوا:** جنب الشارة، مين آخر واحد غيّر السطر ده، من إمتى، وليه:
`Ada Lovelace، من 3 أيام · Fix the parser`. السطر اللي لسه ماعملتولوش commit
بيقول كده، والملف اللي فيه تغييرات مش محفوظة بيقول ده بدل ما يذكر الكاتب
الغلط. اضغطوا على الملاحظة عشان تشوفوا تعليقات السطور للملف كله أو الـ
commit على GitHub، أو تنسخوا المعرّف بتاعه؛ والأمر **عرض ‏◂‏ كاتب السطر**
بيقفلها.

## 4. راجعوا diff

**اعملوا:**

```bash
git difftool
```

**هتشوفوا:** كل ملف متغيّر جنب بعض في عرض الاختلافات بتاع NMOX Studio، وفوقه
**الاختلاف اللي قبله / الاختلاف اللي بعده** و«اختلاف 2 من 5». الملف المضاف أو
الممسوح بيعرض الناحية الناقصة بتاعته كلوحة فاضية («مفيش ملف»)؛ والملف الباينري
بيظهر كباينري، والشريط بيقول لو ملفين باينري مختلفين. اقفلوا التبويب وgit
بيروح للملف اللي بعده.

## 5. حلّوا تعارض

**اعملوا:** اعملوا merge لفرع بيتعارض، وبعدين:

```bash
git mergetool
```

**هتشوفوا:** الملف اللي فيه التعارض في المحرر، والناحية الحالية والناحية
الواردة متلوّنين، وتحذير على كل سطر ‎`<<<<<<<`‎. حطّوا المؤشر عليه
واضغطوا ⌘. ‏(Alt+Enter في الأنظمة التانية)، أو استخدموا **المصدر ‏◂‏ إصلاح
الكود…**: **قبول التغيير الحالي**، أو **قبول التغيير الوارد**، أو **قبول
التغييرين**، وكل واحد منهم تعديل واحد ينفع يتلغي. البلوك اللي اتغيّر من ساعة
العرض بيترفض بدل ما يتخمّن. احفظوا، واقفلوا التبويب، وردّوا على git.

## 6. اقترحوه

**اعملوا:** اعملوا push، وبعدين الفريق ‏◂‏ **طلب سحب جديد على GitHub**
(موجود كمان في قايمة الشارة).

**هتشوفوا:** صفحة New Pull Request بتاعة GitHub نفسها للفرع بتاعكم، في
البراوزر بتاعكم، اللي إنتوا عاملين فيه تسجيل دخول. من المحرر، **تعديل
‏◂‏ فتح على GitHub** و**نسخ لينك GitHub** بيدّوا السطر أو السطور اللي
إنتوا واقفين عليها؛ وفي شجرة استوديو المشاريع بيدّوا ملف أو مجلد.

## 7. دوّروا ورا فشل

**اعملوا:** شغّلوا الاختبارات بتاعتكم في الترمينال (⌃\`) لحد ما واحد يفشل.

**هتشوفوا:** المكان اللي في المخرجات — `src/app.ts:42:7`، وفريم stack
‎`(/abs/app.js:10:5)`‎، و‎`--> src/main.rs:3:5`، و`File "x.py", line 12` —
بيتفتح على السطر والعمود دول بـ ⌘-كليك (Ctrl-كليك على Windows وLinux). الـ URL
أو `localhost:3000` عمره ما يبقى لينك، والمسار اللي مش موجود بيترفض باسمه بدل
ما يتخمّن.

## 8. خلّوا الـ README صادق

**اعملوا:** أدوات ‏◂‏ **فحص روابط Markdown…**

**هتشوفوا:** كل رابط نسبي وكل صورة في Markdown المشروع بيتفحصوا بالطريقة اللي
GitHub بيعرضهم بيها — الملف لازم يكون موجود، و‎`#heading` لازم يكون عنوان
في الملف ده. الرابط الميت غلط، والعنوان الناقص تحذير، والاتنين بيظهروا كخطوط
متعرّجة وفي بنود العمل، مع جملة واحدة في شريط الحالة. مفيش حاجة بتخرج من
جهازكم: الرابط اللي فيه scheme مش بيتفحص.

## 9. سلّموه لوكيل

**اعملوا:** أدوات ‏◂‏ **Agent Port ‏(MCP)…**‏، وعلّموا على
**الاحتفاظ بالعنوان والتوكن دول**، وبعدين **نسخ لـ Claude Code**، وشغّلوا السطر
المنسوخ مرة واحدة.

**هتشوفوا:** وكيل يقدر يقرا اللي الـ IDE يعرفه — المشروع المتوجّه عليه، وإيه
اللي بيتقدّم وإيه اللي شغال، وإنتوا بتعدّلوا إيه، وآخر فشل — ولسه هيتوصّل
بكرة، لأن التوكن محفوظ في سلسلة المفاتيح بتاعة نظامكم والبورت بيتستخدم تاني.
البورت بيفضل للقراءة بس من أساس تصميمه. وشيل العلامة من **الاحتفاظ بالعنوان
والتوكن دول** بيمسح المدخل من سلسلة المفاتيح.

## اللي عملتوه

كتبتوا رسالة commit، وقريتوا diff، وحلّيتوا تعارض، وفتحتوا طلب سحب، وعرفتوا مين
كتب سطر، ومشيتوا ورا stack trace، وفحصتوا README — كل ده في النافذة اللي كنتوا
فيها أصلًا. ولا حاجة من دول استبدلت git: كل خطوة هي خطوة git نفسه، مفتوحة في
المكان اللي بتشتغلوا فيه.
