# Посібник: напишіть власний прилад для стійки

*За один присід. Ви додасте прилад до стійки текстовим редактором,
натиснете його кнопку, побачите, як він виконує справжню команду, і
під’єднаєте його вивід до MONITOR — не написавши жодного рядка Java.*

Нове у 2.0.0. Стійка постачалася з п’ятдесятьма трьома приладами, і досі
був лише один спосіб додати п’ятдесят четвертий: написати плагін для
NetBeans. Це інший спосіб.

![Стійка задач: полиця приладів ліворуч — саме там з’являється прилад із ~/.nmox/devices.d, поряд із вбудованими](../images/tabs/the-task-rack.png)

## 1. Створіть теку

```bash
mkdir -p ~/.nmox/devices.d
```

Це й увесь крок встановлення. Стійка читає теку ліниво, тож нічого не
треба перезапускати.

## 2. Напишіть прилад

Покладіть це у `~/.nmox/devices.d/counter.json`:

```json
{
  "id": "com.example.counter",
  "title": "COUNTER",
  "tagline": "counts the files in the project",
  "accent": "#7FB3D5",
  "category": "OBSERVE",
  "usage": "COUNT lists the project's files of the dialled KIND and shows how many.\nPatch OUT into MONITOR to read the list, or DONE onward to chain.",
  "knobs": [
    { "key": "kind", "label": "KIND", "options": ["js", "ts", "css", "md"] }
  ],
  "ports": [
    { "id": "count", "label": "COUNT", "direction": "IN", "signal": "TRIGGER" },
    { "id": "done", "label": "DONE", "direction": "OUT", "signal": "TRIGGER" },
    { "id": "out", "label": "OUT", "direction": "OUT", "signal": "DATA" }
  ],
  "buttons": [
    { "label": "COUNT", "role": "QUERY",
      "command": ["git", "ls-files", "*.{{kind}}"],
      "emit": "done", "trigger": "count" }
  ]
}
```

Кожен рядок тут має свою роботу: **ручка** стає `{{kind}}` у команді, роль
**QUERY** фарбує кнопку в синій (закон кольору: синій питає, зелений
робить, червоний зупиняє), а два порти дають змогу під’єднувати прилад
кабелями.

## 3. Змонтуйте його

Відкрийте **Стійку задач** (`⌘9` або вкладка «Стійка задач») і загляньте
в шухляду **Спостереження** на полиці. COUNTER уже там, а під ним — ваш
підпис. Перетягніть його на рейку.

Наведіть курсор на його картку «Як користуватися» — це ваш текст `usage`,
і саме тому формат вимагає двох справжніх рядків.

## 4. Натисніть його

> Зверніть увагу: рядка `units` немає. Полиця вимірює лицьову панель і
> обирає найменшу висоту, що вміщує її (цьому приладу через ручку
> потрібно 2U). Оголошуйте `units` лише тоді, коли хочете більше місця.

Націльте стійку на проєкт git, поверніть **KIND** на `js` і натисніть
**COUNT**.

Перше натискання викликає запит **Довіра до робочої області**, бо файл
приладу виконує справжні команди, а господар охороняє кожен запуск так
само, як у вбудованого приладу. Надайте довіру — і LCD покаже команду, а
потім останній рядок виводу. Гніздо DONE блимає зеленим.

Якщо ж відмовити, нічого не запуститься — відмова і є функцією.

## 5. Під’єднайте його

Простягніть кабель від **OUT** приладу COUNTER до **TAP** приладу MONITOR.
Знову натисніть COUNT: кожен рядок потрапить на монітор, бо оголошений
порт `OUT`/`DATA` отримує вивід запуску без жодного додаткового
налаштування.

Тепер простягніть кабель від TICK приладу TEMPO до входу **COUNT** приладу
COUNTER. Прилад, який ви написали в текстовому редакторі, тепер працює
за годинником.

## 6. Зламайте його навмисно

Відредагуйте файл і змініть команду на щось із конвеєром:

```json
"command": ["sh", "-c", "git ls-files | wc -l"]
```

Збережіть — і COUNTER *зникає* з полиці. Це формат відмовляється від
рядка оболонки: команда — це масив аргументів, щоб читач — ви за пів
року чи колега, що переглядає файл, — бачив точно, що буде виконано.
Журнал IDE каже, який файл пропущено й чому:

```
device file counter.json skipped: button "COUNT" command token
"git ls-files | wc -l" contains "|" — commands are argv, never a shell line
```

Поверніть форму масиву — і прилад повернеться. Те саме стосується
інструмента, названого шляхом (`./x.sh`), невідомої `{{variable}}` або
однорядкового `usage`: файл пропускається цілком, а не завантажується
наполовину, бо прилад, чий напис бреше, гірший, ніж жодного приладу.

## Чого ви щойно навчилися

- Прилад — це **файл**: `~/.nmox/devices.d/*.json`, читається ліниво, без
  перезапуску, без збирання.
- Ручки стають `{{variables}}`; ролі обирають кольори; порти дають змогу
  під’єднувати прилад і читати його вивід.
- **Закони тримає господар** — довіра до робочої області на кожен запуск,
  закон кольору, словник портів, закон полиці, — тож файл приладу не може
  виразити неохоронювану команду чи червону кнопку GO, навіть якщо
  спробує.
- Відмови гучні в журналі й повні за наслідками.
