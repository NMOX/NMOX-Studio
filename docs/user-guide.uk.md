Як користуватися продуктом. Посібник іде можливостями в тому порядку, у якому ви їх зустрінете: встановлення, перший запуск, проєкти, стійка, студії, майстри та страхувальні сітки.

---

<a id="1-install"></a>
## 1. Встановлення

**macOS (рекомендовано):**
```bash
brew trust --cask nmox/nmox-studio/nmox-studio
brew install nmox/nmox-studio/nmox-studio
```

Рядок `brew trust` — це одноразове підтвердження Homebrew для будь-якого стороннього tap: під час оновлень вас більше не питатимуть. Застосунок підписано ad-hoc, але не нотаризовано, тож копію в карантині Gatekeeper відхилив би на першому запуску: cask сам знімає атрибут карантину кроком `postflight` і пише про це у вивід встановлення. Нічого мовчки.

**Усе інше:** завантажте файл з [останнього випуску](https://github.com/NMOX/NMOX-Studio/releases/latest) — `.dmg` для macOS, `-setup.exe` для Windows, `.deb` для Debian/Ubuntu, звичайний `.tar.gz` для Linux. Усі чотири несуть власне середовище виконання Java; наперед установлювати нічого не треба. `-portable.zip` — єдиний артефакт, що використовує вашу Java (потрібна Java 21+ у PATH або запуск із `--jdkhome <шлях-до-jdk>`).

> **macOS, перший запуск:** застосунок підписано ad-hoc, але не нотаризовано, тож Gatekeeper питає перед запуском. Першого разу **клацніть застосунок правою кнопкою → Відкрити** й підтвердьте, або виконайте
> `xattr -d com.apple.quarantine "/Applications/NMOX Studio.app"`. Будь-який зі способів розв’язує це назавжди.

### Оновлення

IDE оновлює себе сама: **Знаряддя ▸ Втулки ▸ Оновлення** пропонує модулі будь-якого новішого випуску. Установіть, перезапустіть на запит — готово, без повторного завантаження всього застосунку. Чесне застереження: вбудоване середовище Java та запускач змінюються лише з повним інсталятором, тож для великих стрибків платформи правильно встановити наново з файлу випуску.

<a id="2-first-launch"></a>
## 2. Перший запуск

З термінала `nmoxstudio --open <тека>` запускає застосунок із цією текою, відкритою як проєкт, і націленою на неї стійкою — ті самі двері, що їх відчиняє «Відкрити теку…» на сторінці вітання.

IDE відкривається з усіма вкладками набору поряд з областю редактора: **Ласкаво просимо → Стійка задач → Студія баз даних → Студія контрактів → Конструктор інфраструктури → Студія API → Панель Docker** — кожна головна поверхня за один клац із першої хвилини. У лівій панелі: **Студія проєкту** (дерево файлів і шаблони), база **Робоче місце** та **Оглядач NPM**. Створюється тека `~/NMOX` як типовий робочий простір; стійка вказує туди, доки ви не відкриєте проєкт.

<a id="3-projects"></a>
## 3. Проєкти

**Відкриття:** будь-яка тека з одним із 60 розпізнаваних маніфестів відкривається як справжній проєкт — `package.json`, `Cargo.toml`, `go.mod`, `pom.xml`, `composer.json`, `foundry.toml`, `bower.json`, `Gruntfile.js` та подібні — включно з маніфестами контрактних мереж: сховище Aiken (`aiken.toml`) або Clarinet (`Clarinet.toml`) відкривається з уже підключеними справжніми доріжками. Проста тека з HTML і тегами `<script>` **без** маніфесту теж відкривається — як проєкт STATIC: класичний веб тут повноправний, а не помилка.

**Створення:** *Новий проєкт…* пропонує справжні заготовки — Angular, Vue, Svelte, чистий JavaScript, Elixir/Phoenix, PHP Web (LEMP) і Класичний веб (jQuery). Кожна приходить із підключеними налаштуваннями лінтера, форматування та тестів і з ініціалізованим сховищем git: один коміт-заготовка, який — якщо майстер виконав встановлення за вас — містить і файл блокування, тож ваш перший `git status` чистий.

**Перемикання безпечне:** якщо пристрої працюють (сервер розробки, спостерігач), IDE питає перед перемиканням і акуратно їх зупиняє. Ніщо не працює далі за вашою спиною — ніколи. Навіть примусове завершення IDE не залишить осиротілого процесу.

**Експерименти** — найшвидший спосіб спробувати стек. **Файл ▸ Новий експеримент…** (⇧⌘E) обирає шаблон і створює одноразовий проєкт у `~/.nmox/experiments`: без git, без нещодавніх, уже довірений, із встановленими залежностями — щоб **перший запуск просто спрацював**. Він відкривається на власному обході `EXPERIMENT.md`, який каже, що натиснути, який файл змінити та де живе інтелект IDE для цього стека. Лишіть те, з чого щось виросло: **Файл ▸ Експерименти…** ▸ **Підвищити** виносить його назовні та ініціалізує git, **Дублювати** створює копію поряд для другого підходу, **Відкинути** прибирає решту. Полиця показує вік кожного та його виміряну ціну на диску. Волієте шлях із провідником? Діалог виводить наперед 93 навчальні простори.

![Полиця навчальних просторів — кількість, ціна на диску, вік і весь життєвий цикл](images/spaces-shelf.png)

![Свіжий експеримент Express: обхід відкрито, залежності встановлено, API вже відповідає](images/experiment-walkthrough.png)

**Запуск, збірка, тести — і зупинка:** кнопка ▶ на панелі (F6) запускає проєкт так, як його запускає його інструментарій: скрипт `start`, якщо він є в package.json, `cargo run`, `go run`, `dotnet run`, а для теки з HTML — невеликий статичний сервер на першому вільному порту починаючи з 8080. Збірка, Тести й Очищення поряд і в меню «Запуск». Сервер розробки, що оголосив свою адресу, засвічує значок ⇄ у рядку стану й відкриває сторінку у вбудованому браузері. Усе першого разу проходить через запит довіри робочому простору. Запуск, який не зміг початися, чесно про це каже й пропонує відкрити Доктор середовища. Щоб зупинити: ■ праворуч від «Зневадження» (⌥⌘.) зупиняє одразу всі виконувані команди й повідомляє, що саме зупинив; **Запуск ▸ Зупинити** зупиняє одну й потім пропонує **Повторити**. ■ бачить усе, що продукт запускає для вас, включно зі встановленнями; при наведенні підказка називає рівно те, що зупинить натискання, і відколи працює кожне.

**`.env` усюди:** якщо у проєкті є `.env`, пристрої, запущені зі стійки, отримують ці змінні. Відредагуйте його — і рядок стану зауважить, що перезапуски його підхоплять; робочі процеси чесно зберігають попереднє середовище.

<a id="4-the-task-rack"></a>
## 4. Стійка задач

![Стійка задач](images/tabs/the-task-rack.png)

Стійка — серце продукту. Кожен інструмент вашого робочого процесу — npm, збирач, запускач тестів, сервер розробки, лінтер, git, розгортання — це прилад у стійці: ручки обирають задачу, GO її виконує, світлодіоди показують стан, а РК-екран словами розповідає, що сталося.

![Стійка, націлена на класичний сайт на jQuery — пресет Classic Web Bench: MAESTRO, CRATE, DYNAMO (його ручка TASK розібрала справжній Gruntfile), IGNITION роздає статику, VITALS стежить за якістю](images/task-rack.png)

**Основи:**

- **Додавайте прилади**, перетягуючи їх із палітри (у ній є категорії та пошук). Кожен прилад має картку *Як користуватися*.
- **Запускайте**, натискаючи кнопку GO приладу. Спершу наведіть на неї вказівник: підказка покаже точний командний рядок, який буде виконано. Жодних чудес.
- **Зберіть конвеєр:** натисніть **Tab**, щоб розвернути стійку задньою стороною. Простягніть патч-кабель від гнізда **OK** одного приладу до гнізда **GO** наступного. Тепер `встановлення → збірка → тести` — одне натискання: ланцюг іде сам і спиняється на першій невдачі. Вивід біжить люмінофорним екраном приладу MONITOR.
- **Скасовуйте будь-які структурні зміни** через **⌘Z** — додавання, вилучення, перекомутацію. Вилучення працюючого приладу спершу спиняє його процес.
- **Пресети** дають цілу зібрану стійку одним клацанням — Ship Gate, Dev Intelligence, Monorepo Lanes, E2E Loop, LAMP Bench, Web3 Bench, Uptime Watch. Схеми зберігаються за проєктом автоматично.

![Tab розвертає стійку — патч-кабелі ведуть MAESTRO через CRATE, DYNAMO та IGNITION до VITALS](images/rack-rear.png)

**Координація, коли конвеєр розростається:**

- **QUORUM** зводить доріжки: він спрацьовує лише тоді, коли *всі* його під’єднані входи завершилися успішно — класичне «дочекайся лінтера І тестів І перевірки типів».
- **Затвори ENABLE** на довгих процесах: вхід ENABLE сервера розробки означає «не запускайся, доки це не спрацює».
- **REFLEX** стежить за файлами й розводить їх за шаблоном — `src/**/*.css` в один ланцюг, `**/*.ts` в інший, за доріжкою в монорепозиторії.
- **ROSETTA** обирає доріжку інструментів у змішаних сховищах (стійка визначає Node/Rust/Go/PHP/… за каталогом і націлює кожен прилад відповідно).

**Доріжки говорять мовою вашого інструментарію.** У положенні AUTO прилади лінтингу та форматування (PURITY, GLOSS) говорять інструментарієм самого проєкту, а не тягнуться всюди по засоби Node: робочий простір Deno використовує `deno lint` і `deno fmt`, проєкт Cargo — `cargo clippy` і `cargo fmt`, модуль Go — `go vet` (або `golangci-lint`, якщо проєкт несе свою конфігурацію) і `gofmt`. Файл `biome.json` переводить доріжки Node на Biome, а явні положення ручки завжди важливіші за AUTO.

**Ваші власні прилади.** Полиця розширюється текстовим редактором: будь-який `*.json` у `~/.nmox/devices.d/` стає справжнім приладом — ручки, кнопки, світлодіоди, порти та кабелі, зберігається у схемі й доступний з ⌘I. Опишіть команду масивом аргументів, назвіть ручку — і `{{ручка}}` підставиться при натисканні кнопки. Закони лишаються за господарем, а не за вашим файлом: **довіра робочому простору охороняє перший запуск так само, як у вбудованого приладу**.

**Затвори якості** перетворюють «начебто готово» на «готово»:

- **VITALS** проганяє Lighthouse вашим живим сервером і вимагає мінімуму швидкодії, доступності, добрих практик або пошукової придатності.
- **VERITAS** тримає мінімум покриття й повторює саме ті тести, що впали, поіменно.
- **GAUNTLET** навантажує кінцеву точку й вимагає мінімальної пропускної здатності. **PRISM** стежить за розміром збірки, **BEACON** — за сертифікатом і доступністю URL, а **PREFLIGHT** — це список перевірок перед відправленням: під’єднайте його OK до приладу розгортання, і розгортання фізично не зможе піти, доки все не стане зеленим.
- **GOVERNOR** стежить за регресіями газу в роботі з Solidity (`.gas-snapshot`).

**Усе інше:** **SOLDER** загортає будь-яку команду оболонки в повноцінний прилад — а вся стійка **експортується до GitHub Actions** (ваш локальний конвеєр і ваша інтеграція — та сама схема). **HELM** виконує команди на віддаленому сервері через ssh, **TAIL** стежить за будь-яким журналом, а **PHOSPHOR** — це термінал усередині стійки. Якщо команда друкує локальну адресу, значок ⇄ засвічується, як у будь-якого роздавального приладу, і гасне, коли запуск завершується.

**Стійка тримає себе в злагоді сама.** Відредагуйте `package.json` — і ручка скриптів NPM-9000 оновиться на місці. Відредагуйте `Gruntfile` — і DYNAMO перечитає свої задачі. Додайте залежність — і дисплей CRATE оновиться. Не треба ні перенаводити, ні тиснути кнопки оновлення.

### KVASIR — пояснює останню невдачу

![KVASIR пояснює справжній невдалий запуск: дозволений діагноз на лицьовій панелі та повні кроки виправлення у переглядачі](images/kvasir-explain.png)

**KVASIR** — це допомога ШІ по-стійковому: прилад, який пояснює помилку, що лежить зараз на шині MONITOR, а не бічна панель чату. Коли запуск падає, натисніть **EXPLAIN** — і KVASIR спитає ваш ШІ, що пішло не так і який конкретний наступний крок. Стислий вердикт з’являється на дисплеї; **VIEW** відкриває повну відповідь. **MODEL** обирає між **FAST** (швидко й дешево, типово) та **DEEP** (потужніше). EXPLAIN синій: він читає й питає, але ніколи не чіпає ваш проєкт.

**Оберіть свій ШІ, покладіть свій ключ.** KVASIR працює з **Claude (Anthropic)**, **ChatGPT (OpenAI)** чи **Gemini (Google)** — ваш ключ, ваш вибір. Натисніть **KEY…**, щоб обрати постачальника й вставити його ключ; вибір запам’ятовується, а ключ живе лише у в’язці ключів операційної системи. Звичні змінні середовища кожного постачальника теж читаються, і збережений ключ важливіший за ключ із середовища.

**Що KVASIR надсилає — і це все, що він надсилає.** При першому натисканні EXPLAIN діалог перелічує рівно те, що покине вашу машину, і те, що не покине; без цієї згоди не надсилається нічого, а згода дається окремо кожному постачальникові. Після вдалого EXPLAIN кнопка **VIEW** відкриває відповідь як бесіду — можна питати далі про ту саму невдачу.

**Спитайте KVASIR про свій код.** Той самий помічник дістає до редактора: виділіть код і оберіть **Спитати KVASIR про виділене…** або **Змінити з KVASIR…**, щоб сказати, що змінити, і побачити «до» та «після», перш ніж щось застосується. **⌥⌘G** доповнює біля курсора примарним текстом, який вставиться лише за Tab, а значок гілки git може скласти повідомлення коміту.

**Націльте агента на свою IDE.** Знаряддя ▸ Agent Port (MCP)… відкриває кінцеву точку MCP, яку може опитувати зовнішній помічник: вона **лише для читання за побудовою**, вимкнена, доки ви її не ввімкнете, слухає тільки локальний інтерфейс і вимагає токен, створений при запуску.

Стійка розширювана: сторонні втулки можуть додавати прилади (встановіть їхній NBM через Знаряддя ▸ Втулки). Щоб написати власний, див. [device-spi.md](device-spi.md).

<a id="5-the-editor"></a>
## 5. Редактор

![Код jQuery у палітрі NMOX Phosphor, структура в Оглядачі](images/editor.png)

Понад 70 мов підсвічуються як належить — сучасний набір, класичний (разом із CoffeeScript) і весь шар налаштувань, аж до `.env`, `.editorconfig`, конфігурацій nginx і Apache, файлів Dockerfile та файлів блокувань.

- **Доповнення** знає контекст, а також *класичні бібліотеки*: якщо проєкт несе jQuery, MooTools, Prototype, Backbone/Underscore чи Knockout (через залежності npm *або* звичайні теги `<script>`), їхні API з’являються при доповненні. Проєкти на jQuery 1.x і 2.x отримують чесну позначку про завершення підтримки, а не набридливе нагадування.
- **Структура в Оглядачі (⌘7)** показує будову файлу для 58 типів; клацання переносить до місця.
- **Мінікарта** — силует усього файлу поряд зі смугою прокручування кожного редактора; клацніть або потягніть, щоб прокрутити. Документ завжди вміщається у смугу цілком: рядки стискаються в міру зростання файлу. Вигляд ▸ Мінікарта вмикає й вимикає її одразу в усіх відкритих редакторах.
- **Липке прокручування** — оголошення, що охоплюють верх видимої області (клас, а тоді метод, у який ви спустилися), лишаються закріпленими над текстом, до трьох рядків самого коду; клацання переносить до рядка. Смуга зникає, коли верхній видимий рядок ніщо не охоплює.
- **Перейти до символу (⌥⇧⌘O)** переносить до будь-якої функції, класу, правила чи заголовка в усьому проєкті за набраним іменем — зі збігом за префіксом, за великими літерами всередині слова або за шаблоном. Покажчик обмежений і чесний: `node_modules` пропускається, а на дуже великому проєкті діалог каже, що проіндексував перші 2000 файлів, замість удавати, ніби прочитав усе.
- **Вікно тестів (⌥⌘2)** показує всі тести проєкту *ще до того, як щось запущено*, і запускає один тест, файл або все разом.

### Розгорнути скорочення (⌥⌘E)

Наберіть скорочення Emmet і натисніть **⌥⌘E**: `ul>li*3` перетворюється на готовий список. Це працює у HTML, у шаблонах Angular і — у формі CSS — усередині блоків `<style>` та атрибутів `style`, де вирізка обмежена областю, тож вона ніколи не проковтне навколишню розмітку. Скорочення, якого продукт не знає, відхиляється й лишає ваш текст недоторканим.

### Токени оформлення (власні властивості)

Набір `var(` пропонує токени, оголошені у справжніх таблицях стилів вашого проєкту, кожен зі своїм зразком кольору та місцем оголошення. **⌘-клацання** на використанні `var(--токен)` переносить до його оголошення. Кольори малюються тим кольором, яким вони є — hex, `rgb()`, `hsl()`, назви, а також `oklch()`, `lab()` і `color-mix()` — а **⌘-клацання** на кольоровому літералі відкриває палітру, що замінить його рівно в тому записі, в якому ви його написали.

### Атрибут class знає ваші таблиці стилів

Набір усередині `class="…"` пропонує класи, які ваш проєкт справді оголошує, із зазначенням таблиці, звідки вони; **⌘-клацання** на класі переносить до його правила, а **⌘-клацання** на селекторі `.клас` — до його першого вжитку в розмітці. **Перейменувати клас…** перейменовує в усьому проєкті — лише цілі токени, з числом по кожному файлу — і вголос відмовляє, якщо нове ім’я вже зайняте або лишилися незбережені зміни.

### Запустити скрипт просто від курсора

У розділі `scripts` файлу `package.json` команда **Запустити скрипт** виконує рядок, на якому стоїть курсор — через той самий запит довіри робочому простору й той самий ■, що й будь-який інший запуск.

### Ключі середовища — повноправні

Набір `process.env.` або `import.meta.env.` пропонує ключі, які справді оголошені у вашій родині файлів `.env`, а **⌘-клацання** переносить до рядка з оголошенням. Значення показуються врізаними: нагадування є, таємниці немає.

### Шаблони Angular — повноправні

Файли `.component.html` відкриваються з власною підсвіткою шаблону, з блоками `@if`/`@for` та структурними директивами в доповненні. Установіть Angular Language Service — і перевірка типів шаблону справді доходить: помиліться в імені властивості, і власний компілятор Angular запропонує правильне. **⌘B** у шаблоні переносить до оголошення, а контекстне меню перемикає між компонентом, його шаблоном, стилями й тестом.

### Компоненти Vue та Svelte — повноправні

Файли `.vue` і `.svelte` відкриваються зі своєю підсвіткою, своїм доповненням (разом із крапковими рунами Svelte 5) і Emmet усередині блоків шаблону. Діагностика Vue справді доходить до редактора — через власний мовний сервер Vue.

### Зневадження зі справжніми точками зупину

Клацніть на лівому полі, оберіть **Зневадити файл (точки зупину)** — і програма спиниться там, зі стеком, змінними й обчисленням виразів. JavaScript і TypeScript працюють одразу завдяки вбудованому адаптеру; Python використовує debugpy, а Go — delve, які ви ставите самі. **Зневадити в Chrome** робить те саме для сторінки: точки зупину у вашому коді спрацьовують усередині IDE, поки браузер працює на одноразовому профілі. Усе спершу проходить через запит довіри робочому простору.

### Показувати й ділитися

**Вигляд ▸ Режим презентації** разом збільшує кожен відкритий редактор, сторінку у вбудованому браузері, вікно виводу й термінал — і повертає все точно як було при виході. **Вигляд ▸ Показувати натискання** великим показує щойно натиснуте сполучення, але ніколи — те, що ви набираєте. **Зміни ▸ Копіювати як Markdown** копіює виділене огородженим блоком із правильною позначкою мови, а варіант **із посиланням** додає посилання GitHub на ті самі рядки. **Знаряддя ▸ Зберегти знімок…** малює усе вікно подвійного розміру; є варіанти для однієї вкладки редактора, для буфера обміну та для копіювання дерева проєкту в Markdown.

<a id="6-the-studios"></a>
## 6. Студії

### Доступ із клавіатури та через екранний читач

Кожен орган керування у стійці має доступне ім’я, і це перевіряється при кожному збиранні. Ручки — це повзунки, що відповідають на стрілки, Home та End; кнопки відповідають на пробіл і Enter, разом із приглушеними, які кажуть, чому відмовляють; світлодіоди та екрани повідомляють свій стан. Tab розвертає стійку — крім випадку, коли фокус на органі керування: тоді він поступається звичайному обходу.

### Git у рядку стану

Значок **⎇ гілка** показує, на якій ви гілці й скільки файлів змінено; він читається з диска, тож не коштує жодного процесу. Клацання відкриває повну історію, а меню несе **Різниці проєкту**, **Анотувати**, запити на злиття через ваш власний `gh` і **Скласти повідомлення коміту з KVASIR**.

### Дошка задач (⌥⌘1)

Канбан для кожного проєкту, збережений у `.nmoxtasks.json` — поряд із вашим кодом і під тим самим контролем версій. Перетягуйте картки або рухайте їх із клавіатури: **⌘↑/⌘↓** змінює порядок, і переміщена картка зберігає фокус. Обмеження на незавершену роботу — це порада, а не перепона: заголовок червоніє, але ніхто вас не спиняє. Кнопка **Огляд** міняє стовпці на зведення — що в роботі, зроблено сьогодні й за тиждень, потік за днями, старіючі картки — а годинник (**Відмітитися**) рахує справжній час за карткою, причому на всій дошці йде лише один годинник. **Нарада** перетворює все це на готовий до вставлення звіт.

### Студія блоків (⌥⌘5)

Складайте справжні вебкомпоненти з типізованих деталей, що зчіплюються, як у Scratch: неприпустимі вкладення відхиляються, код народжується самодостатнім користувацьким елементом, а клацання на деталі підсвічує її рядки. Сервер попереднього перегляду в пам’яті показує компонент по-справжньому, разом з іншими справними компонентами вашої бібліотеки. Коло замкнене точно: наново породити щойно прочитане дає байт у байт той самий файл.

### Студія API (⌥⌘8)

Колекції, запити, середовища зі `{{змінними}}` та тести, збережені в `.nmoxapi.json` — таємниці лише у в’язці ключів, ніколи в цьому файлі. Кожна відповідь дістає оцінку безпеки за своїми заголовками. Імпорт із curl, `.http`, OpenAPI, Postman, Insomnia та HAR; експорт у `.http` і копіювання як curl або як `fetch`, з уже підставленими змінними.

### Студія баз даних (⌥⌘7)

SQLite, PostgreSQL, MySQL, MariaDB, MongoDB і CouchDB, із вбудованими драйверами й паролями лише у в’язці ключів. Консоль знає рушій, кожен оператор має свою таблицю результатів, а рядки правляться просто в таблиці, якщо є первинний ключ — із попереднім переглядом точних UPDATE перед застосуванням і чесною причиною, коли щось лише для читання. Експорт у CSV чи JSON, із знешкодженими формулами.

### Студія контрактів (⌥⌘6)

Дерево артефактів Foundry і Hardhat, **Взаємодія** за ABI з розшифрованими поверненнями та відкотами, панель **Спостереження** за блоками й подіями, і **Нагляд** із таблицею газу, вироками щодо розміру EIP-170 та адресною книгою. **Жодних приватних ключів**: надсилання йде через розблоковані рахунки локальної мережі, а таємні URL живуть у в’язці ключів.

### Конструктор інфраструктури (⌥⌘9)

Полотно для DigitalOcean, Hetzner і Cloudflare: звіртеся з тим, що існує насправді, оновіть, щоб побачити розбіжності, і знищіть стек, маючи перед очима його вартість. Неприпустимі з’єднання відмовляють уголос і пояснюють чому, а поки триває хмарна операція, полотно замикається і смуга про це каже.

### IRC (⌥⌘3)

Повноцінний клієнт усередині IDE: TLS зі справжньою перевіркою імені, SASL, розширення IRCv3, доповнення табуляцією, підсвічування, посилання, що відкриваються у вбудованому браузері, запис на диск, власні фільтри та список каналів, який ви відсіюєте під час набирання.

### Вбудований вебсайт

**Довідка ▸ Сайт NMOX Studio (локально)** віддає сайт продукту з його ж стійки, на локальному інтерфейсі. Він говорить тими самими тринадцятьма мовами, що й IDE; перемикач — унизу сторінки.

### Браузер (⌥⌘4)

Справжній браузер усередині IDE, зі своїми знаряддями розробника — консоль, DOM, мережа, сховище та панелі для Vue, Svelte і Angular — бо в рушія немає власного інспектора, і цей наш. Він знає ваші вихідники: оберіть елемент, відкрийте рядок, що його породив, змініть стиль просто там — і оголошення ляже у вихідну таблицю стилів. Збереження файлу перезавантажує сторінку, а справжні розміри пристроїв слугують перевірці адаптивної верстки.

<a id="7-docker"></a>
## 7. Docker

Вкладка Docker — це пульт: стан рушія, контейнери, образи, томи та мережі, із запуском, зупинкою, журналами й очищенням. Пристрій HARBOR на стійці показує те саме одним поглядом. І як уже сказано: підніміть контейнер Postgres, MySQL чи Mongo — і Студія баз даних запропонує вам готове підключення.

Вкладка **Dockerize** створює `Dockerfile` промислової якості, `.dockerignore` і файл композиції, підігнані під набір інструментів вашого проєкту — Node, PHP-FPM з nginx та інші.

<a id="8-wizards-and-kits"></a>
## 8. Майстри та набори

Усі вони живуть у *Новий файл…* та в контекстному меню проєкту, і всі вони **ідемпотентні й ніколи не затирають чуже**: повторний запуск оновлює лише те, що належить самому наборові, і не чіпає ваших правок; те, що переписати не можна, лягає поруч файлом `.suggested`.

### Набір стандартів

`robots.txt`, `sitemap.xml`, вебманіфест, `security.txt` за RFC 9116 і `humans.txt`, створені з ваших відповідей.

### Набір PWA

Повний комплект піктограм, викуваний з одного зображення, разом із масковними варіантами; читабельний сервіс-воркер — оболонка застосунку або мережа спершу, на ваш вибір, — сторінка для роботи без мережі та обв’язка в `index.html`, що зв’язує все докупи.

### Набір доступності

Доступність як відправна точка, а не як перевірка заднім числом: `a11y.css` (видиме кільце фокуса, утиліта для тексту, який читають лише програми читання з екрана, стилі посилання пропуску та блок для тих, хто воліє менше руху), `A11Y-NOTES.md` із проходом клавіатурою та питаннями, на які не відповідає жодна автоматика, і ідемпотентна обв’язка `index.html` — мова, посилання пропуску, таблиця стилів. Про viewport, що забороняє збільшення, вас попередять, але не перепишуть його; те, чого набір полагодити не може, він називає, а не чіпає.

### Набір інтернаціоналізації

Перекладний із першого дня, брат набору доступності: `locales/en.json` і `locales/es.json` (по каталогу на мову, з однаковими ключами), `i18n.js` без залежностей, який застосовує каталог до розмітки `data-i18n`, тримає `<html lang>` чесним і показує загублений ключ ним самим, а не мовчазною порожнечею; плюс `I18N-NOTES.md` — жодних склеєних шматків, `Intl` для дат і чисел, прохід справа наліво та псевдолокалізація.

### Набір контрактів (Web3)

Оберіть ланцюг — Solidity з Foundry, Soroban, Solana, CosmWasm, ink!, Cairo, Move, Bitcoin з Miniscript, Clarity на Stacks, Cardano з Aiken або TON з Tact — і назву контракту, і набір збере перевірений наживо початок: маніфест, контракт, рідний тест і CONTRACT-NOTES.md, що називає пристрої стійки та одноразові кроки. Ключі ніколи не торкаються середовища.

### Класичний набір

Додайте до будь-якого коду jQuery, MooTools, Prototype, Backbone з Underscore чи Knockout — або просто в репозиторії (закріплені версії, sha256 записано), або залежностями npm; плюс заготовки webpack, grunt, gulp чи bower.

<a id="9-quick-search-status-line-and-staying-oriented"></a>
## 9. Швидкий пошук, рядок стану і як не загубити нитку

### Значок ⇄ обслуговує

У рядку стану з’являється значок **⇄ обслуговує**, щойно працюють сервери: запуск самого середовища, обслуговуючі пристрої та будь-яка команда, що надрукувала місцеву адресу. Натисніть і виберіть один — він відкриється у вбудованому браузері або в системному, якщо та вкладка його не бере.

### ⌘I, всезагальний шукач

Одне поле дістає до ваших проєктів (недавніх і відомих), до кожного пристрою стійки — просто до його органів керування, — до **працюючих серверів** (Ввід відкриває їх у браузері), до запитів Студії API, до підключень і таблиць Студії баз даних, до контрактів, до вузлів інфраструктури та до карток Дошки завдань, і знайдене називає стовпець, у якому картка стоїть.

### Рядок стану каже, що живе

Поруч зі значком серверів — націлений проєкт із його набором інструментів і гілка Git разом із числом змінених файлів. Усе це читається з диска або із записів, які продукт і так веде: подивитися не коштує жодного процесу.

### Робоче місце

Це домашня гавань: поточний проєкт, відкриті та недавні файли, недавні проєкти й запуск для кожної поверхні. Поки щось працює, сторінку очолює розділ **ВИКОНУЄТЬСЯ** — кожна команда, яку продукт запустив за вас, із її адресою, якщо вона її оголосила, і з тієї години, відколи вона йде, плюс кожен сервер, який обслуговує пристрій стійки. У кожному рядку справжні кнопки **Відкрити** та **Зупинити**, досяжні з клавіатури й програмою читання з екрана, тож один запуск можна зупинити, не поваливши решти. Усі заголовки на Робочому місці — справжні кнопки: Tab доходить, Ввід відкриває. ⌘I дістає до тих самих запусків: наберіть «зупинити», і Ввід зупинить саме цей. Те, що ви зупинили самі, читається як *зупинено* всюди, де повідомляють про наслідок, і ніколи як збій.

### Сполучення клавіш Emacs (а також Eclipse та IntelliJ)

Сервіс ▸ Параметри ▸ Розкладка клавіш змінює цілий профіль: переміщення та вирізання Emacs у кожному редакторі або набори Eclipse чи IDEA, якщо ваша м’язова пам’ять там. Кожне сполучення NMOX записане в усіх п’ятьох профілях, тож зміна профілю ніколи не відбирає у вас сполучень студій.

<a id="10-the-safety-nets-things-you-dont-have-to-do-anything-for"></a>
## 10. Страхувальні сітки (те, заради чого нічого робити не треба)

### Воскресіння сеансу

Стійка кожні кілька секунд знімає зліпок того, що працює. Примусове завершення, падіння, `kill -9` — під час наступного запуску спливне повідомлення запропонує підняти саме той сеанс, який ви втратили, одним натиском.

### Гарантія від сиріт

Вихід із середовища вбиває всі процеси, які воно запустило, — сервери розробки, інтерпретатори, ланцюжки, спостерігачів, — спершу TERM, потім KILL, якщо впираються, разом із нащадками.

### BLACKBOX і SONAR

Поставте **BLACKBOX** на стійку — і у вас є бортовий самописець: кожен запуск і кожен вихід, із тривалістю, тенденціями і тим, що змінилося від останнього зеленого складання. Те, що ви зупинили самі, читається як ЗУПИНЕНО — ні зелене, ні збій, і ніколи не те, що просять пояснити в KVASIR. **SONAR** показує, хто зайняв ваші порти, звіряючи це з Docker, і одним натиском виганяє того, хто всівся на 3000.

### Файли, які ніколи не затираються

Чотири робочі файли студій (`.nmoxapi.json`, `.nmoxdb.json`, `.nmoxweb3.json`, `.nmoxinfra.json`) перечитуються, коли ви правите їх поза середовищем, — але якщо у вас є незбережені зміни, вас запитають, а не перепишуть. Пошкоджений файл відкладається як `.bak`, і вам про це скажуть; мовчки його ніколи не замінять.

### TypeScript без складання

Проєкт, точка входу якого — `index.ts`, `main.ts` чи `src/index.ts`, запускається з IGNITION власним зрізанням типів у Node (`--experimental-strip-types`, починаючи з Node 22.6; за замовчуванням із 23.6 і 22.18 LTS). Відмову старішого Node перекладено у фразу, що називає цей поріг.

### Ваша мова

NMOX Studio говорить тринадцятьма мовами: English, Español, Français, Deutsch, Русский, Українська, Polski, Português (Brasil), Bahasa Indonesia, Filipino, Tiếng Việt, 简体中文 і हिन्दी. Оберіть свою в **Параметрах ▸ Загальні ▸ Мова** — кожну названо нею самою, щоб свою ви знайшли завжди. Вибір записується у ваші налаштування запуску (`etc/nmoxstudio.conf`, як аргумент `--locale`) і набуває чинності одразу. Змінюються меню, діалоги, підказки, рядки стану, екран вітання та параметри. Лишається словник передніх панелей стійки (GO, STOP, EXPLAIN — це написи на приладі, як на синтезаторі) та глибші діалоги самої платформи, для яких перекладу ще немає. Вибирати, можливо, і не доведеться: свіжа інсталяція вже говорить мовою вашої системи — і з країни, якої ми ніколи не називали: Тайвань, Сінгапур, Португалія та Квебек потрапляють на свою мову, а не на англійську, бо каталоги названо за мовою і ніколи за країною.

### Щоденна перевірка оновлень

Тиха, раз на добу: якщо вийшла новіша версія, сповіщення приведе вас до менеджера модулів на його вкладку оновлень, де центр оновлень встановить нові модулі на місце. Вимикається в Параметрах ▸ Загальні.

<a id="11-learning-spaces"></a>
## 11. Навчальні простори

### Перевірте свою роботу

У деяких просторів є контрольні точки: оберіть такий, і **Файл ▸ Перевірити мою роботу** перевірить вправи насправді — те, що стверджують файли, перевіряється чистою Java, разом із перевірками *відсутності*, якими тільки й можна перевірити «ви змінили заголовок»: первісний текст зразка має зникнути. Те, що стверджують команди, проходить через власний набір інструментів простору. Кожен ✗ відповідає підказкою самого простору, а при невдачі звіт пропонує **Пояснити в KVASIR…**: провалені точки і, якщо перевірявся файл, ваш власний файл — з обмеженням і під згодою, яка прямо називає, що йде назовні. Відповідь читається як відповідь наставника: що змінити й потім перевірити знову.

### Ваші власні уроки

Покладіть файл `*.json` у `~/.nmox/learn-catalog.d/` — і він з’явиться у виборі, за тією самою схемою, що й вбудовані; збіжний `slug` заміняє домашній. Ведете заняття? Пишіть, будуючи: зробіть вправу звичайним проєктом, і **Файл ▸ Вивантажити як навчальний простір…** збере цей файл за вас — зразки, ваш `TUTORIAL.md`, запускний сценарій і ваші контрольні точки, — перевіривши все розбирачем самого вибору перед записом, тож ваші учні дістануть саме те, що їхній вибір і завантажить.

### Каталог

*Новий навчальний простір…* пропонує 93 вбудовані уроки — мови, каркаси й бібліотеки. Кожен створює маленький зразковий проєкт, проведений урок і стійку, де вже висить **справжній інтерпретатор**: ви друкуєте у стійці, і живий інтерпретатор відповідає. Ручка ENGINE обирає серед 37 інтерпретаторів, а якщо якогось немає, кнопка INSTALL ставить його просто там, показуючи поступ на екрані. Простори живуть у `~/.nmox/learn`, осторонь від вашої справжньої роботи.

### Перші кроки, на екрані вітання

Четвертий стовпець перелічує шість перших рухів — відкрити проєкт, запустити щось у стійці, побачити, як підіймається сервер, спитати KVASIR про код, спробувати навчальний простір, скерувати агента на середовище — і позначає кожен за записами, які продукт і так веде. Кожен рядок — двері: натиск відчиняє саме те вікно чи дію. Позначка вже не знімається; стовпець зникає, коли зібрано всі шість, або коли ви натиснете **Сховати цей список**.

### Три відповіді меню Довідка

**Що нового…** показує нотатки до тієї версії, яку ви запустили, вкладені в саме складання; при першому запуску після оновлення вони відкриваються самі й несуть те, чого ваша інсталяція ще не бачила. **Повідомити про проблему…** збирає звіт із вашого оточення та останніх сорока рядків журналу, вже вичищених: домашня тека стає `~`, ім’я входу `<user>`, а все, схоже на таємницю, — `[redacted]`; ви його правите, і **Відкрити на GitHub** заповнює звернення, яке надсилаєте ви самі, або копіюєте. Продукт ніколи нічого не надсилає з власної волі. **Сполучення клавіш…** перелічує кожне сполучення NMOX із вашого профілю, прочитане з чинної розкладки, тож воно не може розійтися з тим, що роблять меню.

<a id="12-when-somethings-wrong"></a>
## 12. Коли щось не так

### Лікар оточення

У меню Сервіс він наживо опитує 66 зовнішніх інструментів — node, npm, docker, forge, composer, gopls… — і показує знайдену версію, а для відсутнього — команду встановлення.

### Стіни з дверима

Якщо немає мовного сервера чи інструмента, середовище каже, яку команду виконати, або пропонує виконати її саме; ніколи — просто відмова. В однієї стіни свої двері: TypeScript 7 не несе tsserver, тож якщо знайдений TypeScript — сьомий, редактор скаже про це один раз і запропонує п’яту лінію, яку сам і ставить із тієї самої причини. Якщо порт зайнято, помилка називає процес, що на ньому всівся, а SONAR його виганяє.

### GO, що нічого не робить

Погляньте на його екран: пристрої пояснюються словами, а підказка біля кнопки GO показує ту саму команду, яку вона виконала б, — можна спробувати її в терміналі.

### Застосунок відкривається в порожнечу (macOS)

Ні вікна, ні помилки, при першому запуску після встановлення: це карантин Gatekeeper — див. примітку в розділі 1. Правий клац і Відкрити, один раз, і це виправлено назавжди. Журнали лежать під `~/Library/Application Support/nmoxstudio/…/var/log/`, якщо знадобиться завести звернення.

<a id="appendix-the-files-nmox-studio-writes-and-what-to-commit"></a>
## Додаток: файли, які пише NMOX Studio (і що з них класти в репозиторій)

Усе, що середовище зберігає про проєкт, — це читабельний файл JSON у корені проєкту, зроблений для того, щоб ділитися ним із командою.

| Файл | Що всередині | Класти в репозиторій? |
|---|---|---|
| `.nmoxapi.json` | Колекції, запити, оточення та перевірки Студії API | **Так** — колега дістане весь ваш робочий простір |
| `.nmoxdb.json` | Підключення, збережені запити та історія | **Так** — паролів там *ніколи* немає (лише у сховищі ключів) |
| `.nmoxweb3.json` | Мережі та адресна книга Студії контрактів | **Так** — таємних адрес там *ніколи* немає (лише у сховищі) |
| `.nmoxinfra.json` | Полотно інфраструктури: вузли, зв’язки, властивості | **Так** — токенів там *ніколи* немає (лише у сховищі ключів) |
| `.nmoxtasks.json` | Дошка завдань: стовпці, картки, межі | **Так** — команда ділить одну дошку; не кладіть, якщо хочете особисту |
| `.gas-snapshot` | Опорні значення газу Foundry (за ними стежить GOVERNOR) | **Так** — так регресії газу ловляться на розборі коду |
| `.env` | Ваші змінні оточення | **Ні** — заради цього `.env` і існує |
| `*.bak` | Робочий файл, що не розібрався, збережений для вас | Ні — заберіть потрібне й видаліть |

Відредагуйте будь-який із чотирьох файлів `.nmox*.json` поза середовищем або заберіть правки колеги — і відповідна студія перечитає їх сама, хіба що у вас є незбережені зміни: тоді вона спершу спитає.

Поза проєктом: `~/NMOX` — робочий простір за замовчуванням, досліди живуть у `~/.nmox/experiments`, навчальні простори — у `~/.nmox/learn`, а стан самого середовища (розташування вікон, патчі стійки, параметри) — у користувацькому каталозі платформи.
