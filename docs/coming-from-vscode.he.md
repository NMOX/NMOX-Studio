הידיים שלכם כבר יודעות איפה הדברים נמצאים. העמוד הזה ממפה את ההרגלים האלה אל NMOX Studio: קודם הקיצורים, אחר כך איפה כל רעיון של VS Code נמצא כאן, ובסוף מה באמת שונה.

ארבעת הקיצורים הראשונים שמשתמש VS Code לוחץ עליהם עושים את מה שהוא מצפה: **⇧⌘P** פותח את לוח הפקודות, **⇧⌘E** את עץ הקבצים, **⇧⌘X** את התוספים, ו‑**⌃\`** את המסוף. הם רשומים בכל חמשת פרופילי מיפוי המקשים שהפלטפורמה מביאה, ושער בבנייה מפענח כל אחד מהם דרך מיפוי המקשים המורכב ב‑macOS, ב‑Windows וב‑Linux, כדי ששום דבר אחר לא יופעל במקומו.

## הקיצורים

עמודות macOS משתמשות בסמלים של שורת התפריטים (⌃ Control, ‏⌥ Option, ‏⇧ Shift, ‏⌘ Command); העמודות של Windows ו‑Linux הן אותו קיצור במקלדת של PC.

כל קיצור של NMOX בטבלה נקרא מתוך מיפוי המקשים שנשלח, לא מהזיכרון (‏⌘, שייך לתפריט האפליקציה של macOS). כמה דברים שהטבלה לא יכולה לומר בתא אחד:

- **F5 תפוס בזמן ניפוי.** כאן הוא אומר *Continue*, כמו בכל IDE ממשפחת NetBeans, ולכן הרצת ניפוי מתחילה מ‑**⇧⌘F5** ‏(Ctrl+Shift+F5) וממשיכה מ‑F5.
- **⌃R הוא שינוי שם כאן**, ולכן *החלפת פרויקט* יושבת על ⌥⌘P ולא על הקיצור של Open Recent ב‑VS Code. שינוי השם עובד כשהשפה שמאחורי הקובץ תומכת בו.
- **להעתקת נתיב יחסי אין קיצור.** ב‑PC, קיצור ⇧⌥⌘C של VS Code הוא Ctrl+Alt+Shift+C, וזה ה‑*Clear Split* של הפלטפורמה בכל פרופיל מקשים; הפריט נמצא בתפריט עריכה, ו‑⇧⌘P מוצא אותו לפי הכותרת ש‑VS Code עצמו נותן לו, *File: Copy Relative Path of Active File*.
- **Ctrl+, ב‑Windows וב‑Linux** חוזר אחורה בהיסטוריית העריכה, כמו שתמיד היה ב‑NetBeans; ההגדרות נמצאות תחת כלים ◂ אפשרויות (ב‑macOS, ‏**Settings…** בתפריט האפליקציה, ⌘,).

**עזרה ◂ קיצורי מקלדת…** מונה כל קיצור של NMOX בפרופיל מיפוי המקשים הפעיל שלכם, כולל ארבעת הקיצורים של VS Code, כפי שהם נקראים ממיפוי המקשים שרץ, כך שהרשימה לא יכולה לסטות ממה שהמקשים עושים.

### כל קיצור עריכה, נמדד

הקיצורים שהידיים שלכם מ‑VS Code מחפשות בזמן עריכה, כל אחד מהם נבדק במיפוי המקשים שנשלח בפרופיל ברירת המחדל ב‑macOS. איפה שהקיצור של VS Code היה פנוי כאן, הוא עושה עכשיו את מה ש‑VS Code עושה (השורות שכתוב בהן **אותו דבר:**); איפה שכבר הייתה לו משמעות שמשתמשי NetBeans סומכים עליה, הוא שומר עליה, והשורה אומרת איפה נמצאת הפעולה של VS Code.

הקיצורים שמסומנים **אותו דבר:** רשומים בכל פרופיל מיפוי מקשים שמשאיר אותם פנויים, ופרופיל שנותן לאחד מהם משמעות משלו שומר עליה: F12 בפרופילים Eclipse, ‏Emacs ו‑NetBeans 5.5, ‏F2 בכל פרופיל חוץ מברירת המחדל, ‏⇧F12 ב‑Emacs וב‑NetBeans 5.5, ‏⌃- ו‑⌃⇧- ב‑Emacs וב‑IntelliJ, ‏⇧⌥F ב‑IntelliJ. ב‑Windows וב‑Linux, ‏F12, ‏⇧F12 ו‑F2 עובדים באותה דרך; שאר הקיצורים של VS Code שונים שם, והטבלה שלמעלה נותנת את שניהם.

גם ב‑Windows וב‑Linux, הערת בלוק וגלישת שורות נמצאות על הקיצורים שלהן מ‑VS Code. גלישת שורות היא Alt+Z בכל פרופיל. הערת בלוק היא Shift+Alt+A בפרופיל ברירת המחדל ובפרופילים Emacs ו‑IntelliJ (הפרופילים Eclipse ו‑NetBeans 5.5 שומרים שם על ה‑Alt+Shift+A שלהם), וב‑Linux היא גם Ctrl+Shift+A, הקיצור של VS Code ב‑Linux, בכל חמשת הפרופילים. הרחבת הבחירה לשורה היא Ctrl+L ב‑Windows וב‑Linux בפרופיל IntelliJ בלבד; בפרופיל Emacs, ‏Ctrl+L שם הוא עדיין ה‑recenter של Emacs עצמו.

שפה שאין לה הערת בלוק, Python למשל, אומרת זאת בשורת המצב. בקובץ HTML, ‏Vue או Svelte, בלוק ‎`<script>` או ‎`<style>` מקבל הערה בשפה שלו. בלי בחירה, הקיצור מוסיף ומסיר את ההערה בשורה; הוא לא מחפש הערה שרק מקיפה את הסמן, ולכן כדי להסיר הערה של כמה שורות, בחרו אותה.

בחיפוש המהיר, הסמלים של הקובץ הם הקטגוריה **סמלים בקובץ הזה**. הקלדת ‎`@` לבדו מציגה אותם מתחילת הקובץ; `m name` (האות, רווח, ואז השם) מחפש בקטגוריה הזאת ולא באף אחת אחרת.

## מהמסוף

`code .`‎ הוא `nmox .`:

```bash
cd ~/code/my-app
nmox .          # open this folder (manifest or not) and aim the IDE at it
nmox src/app.ts # open one file
nmox src/app.ts:42  # open it at line 42 (code -g's form; -g itself is accepted)
nmox            # just start the IDE
```

הפקודה חוזרת מיד, ו‑`nmox` שני מעביר את התיקייה שלו ל‑IDE שכבר רץ. גם עמודה (`src/app.ts:42:7`) מתקבלת, והעורך נפתח בתחילת השורה; שם שלא קיים נדחה במסוף במקום להפעיל משהו. הדגל ‎`-r` של VS Code מתקבל, ו‑‎`-n` פותח בחלון היחיד; ‎`-a` ו‑‎`-v` נדחים בהודעה שמציינת את שמם.

הדגל ‎`-w` (`--wait`) פותח קובץ ומחכה עד שתסגרו את הלשונית שלו, והדגל ‎`-d` (`--diff`) משווה בין שני קבצים זה לצד זה, כך ש‑NMOX Studio יכול לשמש כעורך, ככלי ה‑difftool וככלי ה‑mergetool של git, כמו ש‑`code --wait` משמש:

```bash
git config --global core.editor "nmox -w"
git config --global diff.tool nmox
git config --global difftool.nmox.cmd 'nmox -w -d "$LOCAL" "$REMOTE"'
git config --global merge.tool nmox
git config --global mergetool.nmox.cmd 'nmox -w "$MERGED"'
git config --global mergetool.nmox.trustExitCode false
```

מעכשיו `git commit` פותח את ההודעה ב‑IDE; שמרו אותה וסגרו את הלשונית, ו‑git ממשיך. גם יציאה מה‑IDE כשקובץ עדיין פתוח מחזירה אותו, עם מה שנשמר. באותה דרך הפקודה `git mergetool` פותחת כל קובץ שיש בו התנגשות. במקום שבו VS Code מציב מעל התנגשות את *Accept Current Change | Accept Incoming Change | Accept Both Changes*, ‏NMOX Studio צובע את שני הצדדים ומציב אזהרה בשורה ‎`<<<<<<<`‎; הנורה בשוליים, או התיקון המהיר כשהסמן על השורה הזו (⌘. ב‑Mac, ‏Alt+Enter במקומות אחרים), מציעים את אותן שלוש אפשרויות, כל אחת עריכה אחת שאפשר לבטל. שמרו, סגרו את הלשונית, ו‑git עובר לקובץ הבא. הגוונים ושלוש האפשרויות קיימים בכל קובץ עם סימני התנגשות, עם `git mergetool` או בלעדיו. **צוות ◂ שימוש ב־NMOX Studio עם Git…** קובע בשבילכם את אותן שורות, אחרי שהוא מראה מה הערך של כל אחת מהן עכשיו. Homebrew, מתקין Windows (*הוספת "nmox" ל-PATH*) וחבילות Linux מכניסים אותה ל‑PATH שלכם; להתקנה מה‑DMG, [המדריך למשתמש](user-guide.he.md#2-first-launch) מראה את הקישור בשורה אחת.

| **`launch.json`** | הקובץ ‎`.vscode/launch.json` של המאגר שלכם נקרא: הקלידו שם של תצורה בחיפוש המהיר (⇧⌘P או ⌘I), ו‑Enter על *ניפוי: ⁦Launch Program⁩ — ⁦${workspaceFolder}/server.js⁩* מפעיל את מנגנון הניפוי עם נקודות העצירה על התוכנית הזאת — **ניפוי ◂ התחלת ניפוי…** מציג את אותן תצורות — כשהאמון בסביבת העבודה שואל קודם. תצורות Node ‏(`node`, ‏`pwa-node`) מנפות את ה‑`program` שלהן בתוך ה‑`cwd` שלהן, עם ה‑`args`, ה‑`env` וה‑`envFile` שלהן, תחת ה‑`runtimeExecutable` וה‑`runtimeArgs` שלהן — כך שתצורה של `npm run dev`, של `tsx` או של ‎`--experimental-strip-types` מתחילה כפי שנכתבה — ותצורת Node עם ‎`"request": "attach"` מתחברת לתהליך `node --inspect` במחשב הזה. תצורות Python ‏(`python`, ‏`debugpy`) מנפות את ה‑`program` שלהן עם `args`, ‏`env`, ‏`envFile` והמפרש שה‑`python` שלהן מציין; תצורות Chrome ‏(`chrome`, ‏`pwa-chrome`) פותחות את ה‑`url` שלהן (או את ה‑`file`) עם ה‑`webRoot` שלהן. ‎`"program": "${file}"` מנפה את הקובץ שהעורך שלכם מציג, ו‑`preLaunchTask` שמציין משימה מה‑`tasks.json` שלכם רץ קודם: מנגנון הניפוי מתחיל כשהמשימה הצליחה. בלי `launch.json`, **ניפוי הקובץ** (⇧⌘F5) ולחצן הניפוי בסרגל הכלים מבינים מה להפעיל מתוך הפרויקט עצמו — נקודת הכניסה של הסקריפט `start`, ‏`main`, ‏`index.js` — ומכשיר הראק **INSPECTOR** מפעיל מנפה כשלב בצינור. |
| **Integrated terminal** | החלון **מסוף** (⌃\`): הלחיצה הראשונה מפעילה shell בתיקיית הפרויקט, ולחיצות אחר כך מחזירות אותו. |
| **`settings.json`** | כלים ◂ אפשרויות (ב‑macOS, ‏NMOX Studio ‏◂‏ Settings…). גם הקובץ ‎`.vscode/settings.json` של מאגר נקרא: `editor.tabSize`, ‏`editor.insertSpaces` ו‑`editor.indentSize` קובעים את ההזחה של הקבצים שלו בזמן ההקלדה, `files.trimTrailingWhitespace` ו‑`files.insertFinalNewline` (כשהם `true`) חלים בשמירה, `files.eol` הוא סיום השורה שהקבצים נכתבים איתו, ‎`"editor.formatOnSave": false` מונע משמירה לעצב מחדש את הקובץ, ובלוק של שפה כמו ‎`"[typescript]"` גובר עליהם עבור השפה שלו. כשבמאגר יש גם ‎`.editorconfig`, ה‑‎`.editorconfig` גובר בכל מקום ששניהם אומרים משהו. |

<a id="what-is-honestly-different"></a>
## מה באמת שונה

- **⌘D מוסיף את המופע הבא במיפוי המקשים של ברירת המחדל, לא בכל פרופיל.** פרופיל Eclipse שומר על ⌘D בתור *Delete Line* של Eclipse, פרופיל NetBeans 5.5 בתור *Shift Line Left* ופרופיל Emacs בתור *kill word* (ועל Ctrl+D בתור *delete character* ב‑Windows וב‑Linux); בפרופיל IntelliJ יש ⌘D ב‑macOS, והוא שומר על Ctrl+D בתור *Duplicate Line* ב‑Windows וב‑Linux. גם הקיצור השני של הפעולה משתנה לפי הפרופיל: ⌘J ‏(Ctrl+J) בברירת המחדל, ⌃J ‏(Alt+J) ב‑Eclipse וב‑IntelliJ, ואף אחד ב‑Emacs וב‑NetBeans 5.5, ושם אפשר לתת לה אחד במיפוי מקשים.
- **⌃\` פותח את המסוף ומעביר אליו את המיקוד; הוא לא מסתיר אותו.** וכשהמיקוד במסוף, המקשים שייכים ל‑shell שלכם, ולכן הלחיצה השנייה מגיעה ל‑shell ולא מחזירה אתכם לעורך.
- **`launch.json` נקרא, ומה שמנגנון הניפוי לא יכול לכבד נדחה.** מנגנון הניפוי כאן מעביר תוכנית, את תיקיית העבודה שלה, את ה‑`args` שלה (רשימה של מחרוזות), את ה‑`env` וה‑`envFile` שלה, ואת סביבת הריצה שמפעילה אותה (`runtimeExecutable` ו‑`runtimeArgs` ל‑Node, ‏`python` ל‑Python); ב‑Node הוא גם מתחבר לתהליך שכבר רץ. תצורה שמגדירה `postDebugTask`, ‏`restart` או כל שדה אחר שלא לימדו אותו מופיעה ברשימה אבל לא מופעלת: Enter מציין את השדות בשורת המצב. הפעלת התוכנית בלעדיהם הייתה מנפה משהו אחר ממה שכתוב בקובץ. באותה דרך נדחים `args` או `runtimeArgs` שנכתבו כמחרוזת אחת (VS Code מעביר אותה ל‑shell) וערך `null` ב‑`env` (שמבטל משתנה), וכך גם רשומה ב‑`compounds`, סוג שאין לו כאן מתאם (`go`, ‏`msedge`, ‏`cppdbg` והשאר), התחברות לכל דבר שאינו Node, ערך שרק VS Code יכול לספק (`${input:…}`, ‏`${command:…}`), ותוכנית, תיקיית עבודה או `envFile` מחוץ לפרויקט. שדות שרק מעצבים את מה שמנגנון הניפוי מציג — `skipFiles`, ‏`outFiles`, ‏`sourceMaps`, ‏`console`, ‏`justMyCode`, ‏`presentation` — מתקבלים ולא מוחלים; הפלט של התוכנית הולך לחלון Output. חמישה דברים שכדאי לדעת לפני שלוחצים Enter:
  - **ה‑`preLaunchTask` רץ קודם, וחייב להצליח.** המשימה רצה כמו ש‑Enter עליה בחיפוש המהיר היה מריץ אותה — המשימות שהיא תלויה בהן (`dependsOn`), השאלות שלה, לשונית Output משלה — ומנגנון הניפוי מתחיל כשהיא הסתיימה עם קוד יציאה 0; במקום שבו VS Code שואל *Debug Anyway?* אחרי משימה שנכשלה, כאן שורת המצב אומרת שהתצורה לא הופעלה. `program` שהמשימה בונה (`dist/server.js`) מחופש אחרי המשימה, לא לפניה. תווית ש‑`tasks.json` לא מגדיר, תווית ששתי משימות חולקות, צורת האובייקט (‎`{"type": "npm", "script": "build"}`) ומשימת רקע (‎`"isBackground": true`, צופה שלא מסתיים אף פעם) נדחות בשמן לפני שמשהו רץ.
  - **קובץ `envFile` שלא קיים נדחה**, במקום שבו VS Code מפעיל את התוכנית בלעדיו. המשתנים שלו נוספים לסביבה, ורשומה ב‑`env` גוברת על הקובץ, כמו ב‑VS Code. הקובץ נקרא כשורות `NAME=value` פשוטות (שורות הערה, `export`, וזוג מירכאות אחד סביב ערך הם בסדר); שורה ש‑VS Code היה קורא אחרת — תו escape בתוך מירכאות כפולות, ‎`#` אחרי ערך, גרש הפוך (backtick), ובתצורת Python גם `export` או ‎`${NAME}` — נדחית בציון הקובץ ומספר השורה, ואף פעם לא הערך.
  - **המשתנים `${file}`, ‏`${relativeFile}`, ‏`${fileBasename}`, ‏`${fileBasenameNoExtension}`, ‏`${fileExtname}`, ‏`${fileDirname}` ושאר משתני הקובץ מתכוונים לקובץ של העורך הפעיל**: הלשונית שהמיקוד בה כשהיא עורך, ואחרת הלשונית שמוצגת באזור העורך — אותו קובץ שה‑`${file}` של משימה מתכוון אליו. כשאין קובץ פתוח, התצורה נדחית בציון המשתנה, ו‑`${file}` מחוץ לפרויקט נדחה כמו כל תוכנית אחרת שנמצאת שם.
  - **ה‑`runtimeExecutable` הוא שם או נתיב מוחלט.** שם (`npm`, ‏`tsx`, ‏`nodemon`) מחופש ב‑PATH שלכם ואחר כך ב‑`node_modules/.bin` של הפרויקט; ‎`${workspaceFolder}/node_modules/.bin/tsx` חייב להיות שם; נתיב יחסי נדחה, כי VS Code היה מחפש אותו כשם. כשסביבת הריצה היא הפקודה כולה (`npm run dev` בלי `program`), הסקריפט שהיא מפעילה מנופה כסשן משלו, שמופיע בחלון Sessions.
  - **התחברות היא למחשב הזה.** `port` (9229 אם לא נכתב אחרת) ו‑`address` שהוא `localhost`, ‏`127.0.0.1` או ‎`::1`; כל כתובת אחרת נדחית, כי זה לא פיתוח מרחוק. אם שום דבר לא מאזין, שורת המצב אומרת זאת, וסיום הסשן משאיר את התוכנית שלכם רצה.
- **`tasks.json` נקרא, ומה שלא יכול לרוץ כפי שנכתב נדחה.** משימה רצה כשהמשימות שהיא תלויה בהן (`dependsOn`) רצות קודם (יחד, או אחת אחרי השנייה עם ‎`"dependsOrder": "sequence"`), כש‑`${file}`, ‏`${relativeFile}`, ‏`${lineNumber}`, ‏`${selectedText}` ושאר המשפחה הזאת מתמלאים מהקובץ שפתוח בעורך, וכשהשאלות של ה‑`${input:…}` שלה (`promptString`, ‏`pickString`) נשאלות לפני שמשהו מתחיל. כל ההרצה מוכרעת מראש: אם משימה אחת בה לא יכולה לרוץ כפי שנכתבה, שום דבר לא רץ, ו‑Enter אומר בשורת המצב איזו משימה ולמה. זה כולל תווית ב‑`dependsOn` שהקובץ לא מגדיר, תלות שהיא משימת רקע (problem matchers לא נקראים, ולכן שום דבר לא אומר מתי היא מוכנה), ‎`${file}` כשאין קובץ פתוח, ושאלה שביטלתם. תלות שנכשלת עוצרת שם את ההרצה. עדיין נדחים בשמם: ערך שרק VS Code יכול לספק (`${config:…}`, ‏`${command:…}`, קלט עם ‎`"type": "command"`), תלות שנכתבה כאובייקט (‎`{"type": "npm", …}`) במקום כתווית, סוג משימה שהרחבה מספקת (`gulp`, ‏`typescript`), ותיקיית עבודה מחוץ לפרויקט.
- **קטעי הקוד הם של המאגר שלכם, ושלושה דברים שונים.** בחירה (‎`${1|a,b|}`) מתחילה באפשרות הראשונה שלה, בלי רשימה לבחור ממנה; מציין מקום שמקונן בתוך ברירת המחדל של מציין מקום אחר הופך לחלק מברירת המחדל הזאת; וקטע קוד שאי אפשר להריץ את ההמרה שלו בבטחה (ביטוי רגולרי ש‑Java לא יכול לקמפל, או כזה שעלול לרוץ בלי סוף) נשאר בחוץ ומצוין ביומן, במקום להתווסף חצי גמור. הקלדת קידומת לא פותחת את הרשימה מעצמה: ⌃Space פותח אותה. קטעי קוד בלי `prefix`, קטעי קוד ברמת המשתמש ו‑`isFileTemplate` לא נקראים.
- **משימה עם `"type": "shell"` רצה במעטפת ש‑VS Code היה משתמש בה.** ב‑macOS וב‑Linux זו ה‑`$SHELL` שלכם עם `-c` ‏(zsh, ‏bash או fish ב‑macOS מתחילים כמעטפת התחברות, `-l`, כמו בפרופילי ברירת המחדל של VS Code); ב‑Windows זו PowerShell, ‏`pwsh` כשהוא מותקן. ‏`options.shell` מכובד בדרך של VS Code: ציינו `executable`, והמשימה רצה בדיוק עם ה‑`args` שנתתם, ולכן bash צריך `"args": ["-c"]`. ב‑Windows רצות רק PowerShell (ארגומנטים שמסתיימים ב‑`-Command`) ו‑`cmd.exe` (ארגומנטים שמסתיימים ב‑‎`/c`); כל מעטפת אחרת שם נדחית בשמה, במקום לקבל שורת פקודה שצוטטה בניחוש.
- **אין פרופיל מיפוי מקשים בשם "VS Code".** הקיצורים שלמעלה נמצאים בפרופיל ברירת המחדל ובארבעת האחרים. חריג אחד מכוון: בפרופיל **Eclipse**, ‏⇧⌘E נשאר ה‑*Switch to Editor* של Eclipse עצמו, ובתוך העורך ⇧⌘P ו‑⇧⌘X שומרים על המשמעות שלהם ב‑Eclipse (סוגר תואם, אותיות רישיות) — מי שבחר ב‑Eclipse מצפה ל‑Eclipse.
- **ב‑Linux, ‏Ctrl+\` פותח את המסוף, לא מחליף חלונות.** המחליף נמצא על Ctrl+Tab. בשולחן עבודה שתופס את Ctrl+Tab לעצמו (KDE, למשל), **חלון ◂ מסמכים…** מציג במקום זאת את הקבצים הפתוחים.
- **קיצורי Ctrl+Alt יכולים להתנגש ב‑AltGr.** ב‑Windows, פריסות מקלדת שמקלידות תווים עם AltGr (פולנית, למשל) שולחות בשבילו Ctrl+Alt. אם Ctrl+Alt+P או Ctrl+Alt+K מקלידים לכם תו, העבירו את *החלפת פרויקט* או את קיצורי הניסויים תחת מיפוי מקשים.
- **הרחבות של VS Code לא מותקנות כאן.** האינטליגנציה לשפות מגיעה משרתי השפה ש‑NMOX מכיר (אבחון הסביבה מונה מה חסר ואיך להתקין אותו), מהדקדוקים של העורך עצמו, ומתוספים שנבנו לפלטפורמת NetBeans.
