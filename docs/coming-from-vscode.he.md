הידיים שלכם כבר יודעות איפה הדברים נמצאים. העמוד הזה ממפה את ההרגלים האלה אל NMOX Studio: קודם הקיצורים, אחר כך איפה כל רעיון של VS Code נמצא כאן, ובסוף מה באמת שונה.

ארבעת הקיצורים הראשונים שמשתמש VS Code לוחץ עליהם עושים את מה שהוא מצפה: **⇧⌘P** פותח את לוח הפקודות, **⇧⌘E** את עץ הקבצים, **⇧⌘X** את התוספים, ו‑**⌃\`** את המסוף. הם רשומים בכל חמשת פרופילי מיפוי המקשים שהפלטפורמה מביאה, ושער בבנייה מפענח כל אחד מהם דרך מיפוי המקשים המורכב ב‑macOS, ב‑Windows וב‑Linux, כדי ששום דבר אחר לא יופעל במקומו.

<a id="the-chords"></a>
## הקיצורים

עמודות macOS משתמשות בסמלים של שורת התפריטים (⌃ Control, ‏⌥ Option, ‏⇧ Shift, ‏⌘ Command); העמודות של Windows ו‑Linux הן אותו קיצור במקלדת של PC.

כל קיצור של NMOX בטבלה נקרא מתוך מיפוי המקשים שנשלח, לא מהזיכרון (‏⌘, שייך לתפריט האפליקציה של macOS). כמה דברים שהטבלה לא יכולה לומר בתא אחד:

- **F5 תפוס בזמן ניפוי.** כאן הוא אומר *Continue*, כמו בכל IDE ממשפחת NetBeans, ולכן הרצת ניפוי מתחילה מ‑**⇧⌘F5** ‏(Ctrl+Shift+F5) וממשיכה מ‑F5.
- **⌃R הוא שינוי שם כאן**, ולכן *החלפת פרויקט* יושבת על ⌥⌘P ולא על הקיצור של Open Recent ב‑VS Code. שינוי השם עובד כשהשפה שמאחורי הקובץ תומכת בו.
- **Ctrl+, ב‑Windows וב‑Linux** חוזר אחורה בהיסטוריית העריכה, כמו שתמיד היה ב‑NetBeans; ההגדרות נמצאות תחת כלים ◂ אפשרויות (ב‑macOS, ‏**Settings…** בתפריט האפליקציה, ⌘,).

**עזרה ◂ קיצורי מקלדת…** מונה כל קיצור של NMOX בפרופיל מיפוי המקשים הפעיל שלכם, כולל ארבעת הקיצורים של VS Code, כפי שהם נקראים ממיפוי המקשים שרץ, כך שהרשימה לא יכולה לסטות ממה שהמקשים עושים.

## מהמסוף

`code .`‎ הוא `nmox .`:

```bash
cd ~/code/my-app
nmox .          # open this folder (manifest or not) and aim the IDE at it
nmox src/app.ts # open one file
nmox src/app.ts:42  # open it at line 42 (code -g's form; -g itself is accepted)
nmox            # just start the IDE
```

הפקודה חוזרת מיד, ו‑`nmox` שני מעביר את התיקייה שלו ל‑IDE שכבר רץ. גם עמודה (`src/app.ts:42:7`) מתקבלת, והעורך נפתח בתחילת השורה; שם שלא קיים נדחה במסוף במקום להפעיל משהו. הדגל ‎`-r` של VS Code מתקבל, ו‑‎`-n` פותח בחלון היחיד; ‎`-a` ו‑‎`-v` נדחים בהודעה שמציינת את שמם.

הדגל ‎`-w` (`--wait`) פותח קובץ ומחכה עד שתסגרו את הלשונית שלו, והדגל ‎`-d` (`--diff`) משווה בין שני קבצים זה לצד זה, כך ש‑NMOX Studio יכול לשמש כעורך וככלי ה‑difftool של git, כמו ש‑`code --wait` משמש:

```bash
git config --global core.editor "nmox -w"
git config --global diff.tool nmox
git config --global difftool.nmox.cmd 'nmox -w -d "$LOCAL" "$REMOTE"'
git config --global merge.tool nmox
git config --global mergetool.nmox.cmd 'nmox -w "$MERGED"'
git config --global mergetool.nmox.trustExitCode false
```

מעכשיו `git commit` פותח את ההודעה ב‑IDE; שמרו אותה וסגרו את הלשונית, ו‑git ממשיך. גם יציאה מה‑IDE כשקובץ עדיין פתוח מחזירה אותו, עם מה שנשמר. **צוות ◂ שימוש ב־NMOX Studio עם Git…** קובע בשבילכם את אותן שורות, אחרי שהוא מראה מה הערך של כל אחת מהן עכשיו. Homebrew, מתקין Windows (*הוספת "nmox" ל-PATH*) וחבילות Linux מכניסים אותה ל‑PATH שלכם; להתקנה מה‑DMG, [המדריך למשתמש](user-guide.he.md#2-first-launch) מראה את הקישור בשורה אחת.

## איפה נמצא כל רעיון של VS Code

| ב‑VS Code | ב‑NMOX Studio |
|---|---|
| **Explorer** | **אולפן הפרויקטים** (⇧⌘E) — עץ הקבצים (בלחיצה ימנית על קובץ: העתקת נתיב, העתקת נתיב יחסי והצגה ב-Finder), התבניות ועורך ה‑`package.json` של הפרויקט. **שולחן העבודה** (⌥⌘0) הוא הבסיס: קבצים פתוחים, קבצים אחרונים, פרויקטים אחרונים וכל מה שרץ. |
| **Command Palette** | **חיפוש מהיר** (⇧⌘P או ⌘I) — פעולות, קבצים, פרויקטים אחרונים, מכשירים בראק, שרתים חיים, בקשות של אולפן ה‑API, סמלים. גם שמות הפקודות של VS Code עצמו עובדים: *Format Document*, ‏*Toggle Terminal*, ‏*Git: Commit* או *Open Settings* מציגים את הפעולה שעושה כאן את אותו הדבר, תחת **פקודות VS Code**, עם השם והקיצור שלה עצמה. |
| **Extensions** | **כלים ◂ תוספים** מתקין ומעדכן מודולים, כולל העדכונים של NMOX עצמו. הרבה ממה שהרחבה מוסיפה ב‑VS Code הוא כאן **מכשיר בראק** — ואפשר לכתוב אחד כקובץ JSON בתיקייה ‎`~/.nmox/devices.d` ‏([קובצי מכשירים](device-files.md)). |
| **`tasks.json`** | הקובץ ‎`.vscode/tasks.json` של המאגר שלכם נקרא: הקלידו שם של משימה בחיפוש המהיר (⇧⌘P או ⌘I), ו‑Enter על *הרצת משימה: ⁦build⁩ — ⁦make all⁩* מריץ אותה, כשהאמון בסביבת העבודה שואל קודם בפרויקט שעוד לא נתתם בו אמון, הפלט מופיע בחלון Output וה‑■ שבסרגל הכלים עוצר אותה. לצד זה, הסקריפטים של הפרויקט עצמו רצים כפי שנכתבו: הרצה / בנייה / בדיקה בסרגל הכלים (F6, ‏F11, ‏⌃F6), **הרצת סקריפט** על שורה בקטע ה‑scripts של `package.json`, **סייר NPM**, ו**ראק המשימות** (⌘9), שבו משימות הן מכשירים שמחווטים יחד. |
| **`launch.json`** | הקובץ ‎`.vscode/launch.json` של המאגר שלכם נקרא: הקלידו שם של תצורה בחיפוש המהיר (⇧⌘P או ⌘I), ו‑Enter על *ניפוי: ⁦Launch Program⁩ — ⁦${workspaceFolder}/server.js⁩* מפעיל את מנגנון הניפוי עם נקודות העצירה על התוכנית הזאת, כשהאמון בסביבת העבודה שואל קודם. תצורות Node ‏(`node`, ‏`pwa-node`) ו‑Python ‏(`python`, ‏`debugpy`) מנפות את ה‑`program` שלהן בתוך ה‑`cwd` שלהן, עם ה‑`args` וה‑`env` שלהן; תצורות Chrome ‏(`chrome`, ‏`pwa-chrome`) פותחות את ה‑`url` שלהן (או את ה‑`file`) עם ה‑`webRoot` שלהן. בלי `launch.json`, **ניפוי הקובץ** (⇧⌘F5) ולחצן הניפוי בסרגל הכלים מבינים מה להפעיל מתוך הפרויקט עצמו — נקודת הכניסה של הסקריפט `start`, ‏`main`, ‏`index.js` — ומכשיר הראק **INSPECTOR** מפעיל מנפה כשלב בצינור. |
| **Integrated terminal** | החלון **מסוף** (⌃\`): הלחיצה הראשונה מפעילה shell בתיקיית הפרויקט, ולחיצות אחר כך מחזירות אותו. |
| **`settings.json`** | כלים ◂ אפשרויות (ב‑macOS, ‏NMOX Studio ‏◂‏ Settings…). גם הקובץ ‎`.vscode/settings.json` של מאגר נקרא: `editor.tabSize`, ‏`editor.insertSpaces` ו‑`editor.indentSize` קובעים את ההזחה של הקבצים שלו בזמן ההקלדה, `files.trimTrailingWhitespace` ו‑`files.insertFinalNewline` (כשהם `true`) חלים בשמירה, ובלוק של שפה כמו ‎`"[typescript]"` גובר עליהם עבור השפה שלו. כשבמאגר יש גם ‎`.editorconfig`, ה‑‎`.editorconfig` גובר בכל מקום ששניהם אומרים משהו. |
| **Problems panel** | **פריטי פעולה** (⌘6), או לחיצה על הספירה **⁦✕ ⚠⁩** בשורת המצב: השגיאות והאזהרות של שרתי השפה, וממצאי ה‑lint והטיפוסים ממכשירי הראק PURITY ו‑TYPEGUARD. כמו ב‑VS Code, חלק מהשרתים מדווחים רק על הקבצים הפתוחים אצלכם; gopls מדווח על כל החבילה. |
| **Outline** | ה**נווט** (⌘7). |
| **Source Control** | סימן ה‑git בשורת המצב (ענף ושינויים, לחיצה אחת להיסטוריה) והתפריט **צוות**. |
| **Workspace Trust** | אותו רעיון, שנאכף לפני שמשהו שמאגר בחר רץ: פתיחת פרויקט משוכפל לא מריצה דבר עד שאתם נותנים בו אמון. |
| **Keyboard Shortcuts editor** | כלים ◂ אפשרויות ◂ מיפוי מקשים (ב‑macOS, ‏Settings… ◂ מיפוי מקשים) — עריכת כל קיצור, או החלפת הפרופיל כולו ל‑Eclipse, ‏Emacs או IntelliJ. |

בפעם הראשונה שאתם פותחים מאגר שיש בו ‎`.vscode/tasks.json`, ‏`launch.json` או `settings.json`, הודעה אומרת מה נמצא ואיפה הוא נמצא; לחצו עליה כדי לפתוח את החיפוש המהיר. היא אומרת זאת פעם אחת לכל פרויקט.

<a id="what-is-honestly-different"></a>
## מה באמת שונה

- **⌘D מוסיף את המופע הבא במיפוי המקשים של ברירת המחדל, לא בכל פרופיל.** פרופיל Eclipse שומר על ⌘D בתור *Delete Line* של Eclipse, פרופיל NetBeans 5.5 בתור *Shift Line Left* ופרופיל Emacs בתור *kill word* (ועל Ctrl+D בתור *delete character* ב‑Windows וב‑Linux); בפרופיל IntelliJ יש ⌘D ב‑macOS, והוא שומר על Ctrl+D בתור *Duplicate Line* ב‑Windows וב‑Linux. גם הקיצור השני של הפעולה משתנה לפי הפרופיל: ⌘J ‏(Ctrl+J) בברירת המחדל, ⌃J ‏(Alt+J) ב‑Eclipse וב‑IntelliJ, ואף אחד ב‑Emacs וב‑NetBeans 5.5, ושם אפשר לתת לה אחד במיפוי מקשים.
- **⌃\` פותח את המסוף ומעביר אליו את המיקוד; הוא לא מסתיר אותו.** וכשהמיקוד במסוף, המקשים שייכים ל‑shell שלכם, ולכן הלחיצה השנייה מגיעה ל‑shell ולא מחזירה אתכם לעורך.
- **`launch.json` נקרא, ומה שמנגנון הניפוי לא יכול לכבד נדחה.** מנגנון הניפוי כאן מעביר תוכנית, את תיקיית העבודה שלה, את ה‑`args` שלה (רשימה של מחרוזות) ואת ה‑`env` שלה (מחרוזות שנוספות לסביבה שעוברת בירושה), ולכן תצורה שמגדירה `envFile`, ‏`runtimeExecutable`, ‏`runtimeArgs`, ‏`preLaunchTask` או כל שדה אחר שלא לימדו אותו מופיעה ברשימה אבל לא מופעלת: Enter מציין את השדות בשורת המצב. הפעלת התוכנית בלעדיהם הייתה מנפה משהו אחר ממה שכתוב בקובץ. באותה דרך נדחים `args` שנכתבו כמחרוזת אחת (VS Code מעביר אותה ל‑shell) וערך `null` ב‑`env` (שמבטל משתנה), וכך גם ‎`"request": "attach"`, רשומה ב‑`compounds`, סוג שאין לו כאן מתאם (`go`, ‏`msedge`, ‏`cppdbg` והשאר), ערך שרק VS Code יכול לספק (`${file}`, ‏`${input:…}`), ונתיב מחוץ לפרויקט. שדות שרק מעצבים את מה שמנגנון הניפוי מציג — `skipFiles`, ‏`outFiles`, ‏`sourceMaps`, ‏`console`, ‏`justMyCode`, ‏`presentation` — מתקבלים ולא מוחלים; הפלט של התוכנית הולך לחלון Output.
- **`tasks.json` נקרא, ומה שלא יכול לרוץ כפי שנכתב נדחה.** משימה שמשתמשת בערך שרק VS Code יכול לספק (`${input:…}`, ‏`${file}`, ‏`${config:…}`, ‏`${command:…}`) או שיש לה `dependsOn` למשימה אחרת מופיעה ברשימה אבל לא רצה: Enter אומר בשורת המצב איזה משתנה או איזו משימה. הרצה שלה עם הערך ריק, או בלי המשימה שהיא תלויה בה, הייתה מריצה משהו אחר ממה שכתוב בקובץ. כך גם סוג משימה שתוסף מספק (`gulp`, ‏`typescript`), ותיקיית עבודה מחוץ לפרויקט.
- **משימה עם `"type": "shell"` רצה במעטפת ש‑VS Code היה משתמש בה.** ב‑macOS וב‑Linux זו ה‑`$SHELL` שלכם עם `-c` ‏(zsh, ‏bash או fish ב‑macOS מתחילים כמעטפת התחברות, `-l`, כמו בפרופילי ברירת המחדל של VS Code); ב‑Windows זו PowerShell, ‏`pwsh` כשהוא מותקן. ‏`options.shell` מכובד בדרך של VS Code: ציינו `executable`, והמשימה רצה בדיוק עם ה‑`args` שנתתם, ולכן bash צריך `"args": ["-c"]`. ב‑Windows רצות רק PowerShell (ארגומנטים שמסתיימים ב‑`-Command`) ו‑`cmd.exe` (ארגומנטים שמסתיימים ב‑‎`/c`); כל מעטפת אחרת שם נדחית בשמה, במקום לקבל שורת פקודה שצוטטה בניחוש.
- **אין פרופיל מיפוי מקשים בשם "VS Code".** הקיצורים שלמעלה נמצאים בפרופיל ברירת המחדל ובארבעת האחרים. חריג אחד מכוון: בפרופיל **Eclipse**, ‏⇧⌘E נשאר ה‑*Switch to Editor* של Eclipse עצמו, ובתוך העורך ⇧⌘P ו‑⇧⌘X שומרים על המשמעות שלהם ב‑Eclipse (סוגר תואם, אותיות רישיות) — מי שבחר ב‑Eclipse מצפה ל‑Eclipse.
- **ב‑Linux, ‏Ctrl+\` פותח את המסוף, לא מחליף חלונות.** המחליף נמצא על Ctrl+Tab. בשולחן עבודה שתופס את Ctrl+Tab לעצמו (KDE, למשל), **חלון ◂ מסמכים…** מציג במקום זאת את הקבצים הפתוחים.
- **קיצורי Ctrl+Alt יכולים להתנגש ב‑AltGr.** ב‑Windows, פריסות מקלדת שמקלידות תווים עם AltGr (פולנית, למשל) שולחות בשבילו Ctrl+Alt. אם Ctrl+Alt+P או Ctrl+Alt+K מקלידים לכם תו, העבירו את *החלפת פרויקט* או את קיצורי הניסויים תחת מיפוי מקשים.
- **הרחבות של VS Code לא מותקנות כאן.** האינטליגנציה לשפות מגיעה משרתי השפה ש‑NMOX מכיר (אבחון הסביבה מונה מה חסר ואיך להתקין אותו), מהדקדוקים של העורך עצמו, ומתוספים שנבנו לפלטפורמת NetBeans.
