# The main toolbar's buttons whose tooltip key lives in platform CODE.
#
# 3.2.0: a German build's main toolbar read "New File... (⌘N)", "Open
# Project... (⇧⌘O)" and "Pause I/O Checks" in English while
# ToolbarOverlayGateTest was green, because its population was five
# overlay packages chosen by the MENU rows of the same actions. A toolbar
# button does not paint the menu's key: Actions.ButtonBridge (openide-awt,
# read from its bytecode) sets the tooltip to the action's
# SHORT_DESCRIPTION, and only when that is null to its NAME with the
# ampersand cut, then formats FMT_ButtonHint with the shortcut.
#
# WHICH buttons exist is DERIVED by ToolbarOverlayGateTest from every
# Toolbars/<toolbar>/<item> registration of every toolbar a shipped
# configuration (Toolbars/Standard.xml, Toolbars/Debugging.xml) shows, and
# so is the key of every button the layer builds with a generic factory
# (Actions.alwaysEnabled/context/callback/checkbox read the layer's own
# ShortDescription, else displayName). The rows below are the rest: an
# action built in code, whose key only its bytecode says. Each row was read
# from the javap of the class that sets it:
#
#   NewFile, OpenProject: putValue(SHORT_DESCRIPTION, LBL_*Action_Tooltip)
#     in the constructor (OpenProject through its static _SHORT_DESCRIPTION);
#     the menu row reads LBL_*Action_Name, which is why v2.143.0's menu
#     overlay never reached the toolbar.
#   NewProject: the layer builds Actions.alwaysEnabled over the NewProject
#     delegate, and AlwaysEnabledAction.getValue asks the delegate first
#     once it exists; the delegate puts LBL_NewProjectAction_Tooltip. The
#     layer's displayName (derived) paints until then.
#   Build/Rebuild/Run/Debug Main Project: MainProjectAction formats the
#     choice pattern into NAME (setDisplayName); no SHORT_DESCRIPTION.
#   StopRunAction (ours): CTL_StopRun at construction, then StopRunText's
#     tooltip keys on every change of what is running.
#   Debug toolbar: DebuggerAction.getValue(NAME) answers
#     NbBundle.getMessage(DebuggerAction.class, <key put at creation>); no
#     SHORT_DESCRIPTION. The Debug toolbar shows while a session runs (the
#     debugger switches to the Debugging configuration), and these keys
#     paint nowhere else in this product: no menu carries the actions.
#   PauseAction (masterfs-ui): SHORT_DESCRIPTION = CTL_PauseAction; while
#     I/O is suspended the toggle button's TEXT is MSG_Resume.
#   SelfSamplerAction: the delegate puts ActionNameStart, and
#     ActionNameStop while it samples, into NAME and SHORT_DESCRIPTION.
#   GarbageCollectAction: its toolbar presenter is the HeapView memory
#     meter, whose tooltip is CTL_GC and whose right-click menu is
#     LBL_ShowText.
#   QuickSearchAction: its toolbar presenter is the search field; the field
#     is main-window chrome and MainWindowChromeSpeaksTest owns the rest of
#     its keys.
#   Undo/Redo: UndoRedoAction puts UndoSimple/RedoSimple into NAME, or
#     UndoWithParameter/RedoWithParameter when the edit has a presentation
#     name of its own.
#
# Format: toolbar/item|jar|package|key|English value the jar ships
